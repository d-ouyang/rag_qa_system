# 企业级 RAG 智能问答系统

面向企业内部文档的问答系统。传一份资料进去，提问时它先去知识库里找出相关段落，
再结合这些段落生成回答；回答下面挂一串引用，点开能看到那段话的完整原文和出处。

## 能干什么

- 上传的文档在后台自动切分、建立索引，不用手动干预
- 提问：一次拿完整答案，也可以流式逐字输出
- 多轮对话：在同一会话里接着问，前面的上下文会带进去
- 引用溯源：每条引用都能反查到切片全文，回答不是凭空编的
- 会话记录：问答往来落库，随时回看

## 由这几块拼起来

| 部分 | 作用 |
|------|------|
| 前端 | 登录、会话、流式回答、知识库管理 |
| 网关 | 登录校验、限流，把 `/api` 转到后端 |
| 后端 | 检索、重排、生成回答，以及会话与文档接口 |
| 解析进程 | 上传后的文档在后台切分并写入知识库 |
| MySQL | 会话、消息、文档记录 |
| Redis | 解析队列，以及相同问题的回答缓存 |
| Chroma | 向量检索 |

嵌入、重排、生成都走外部模型接口，应用侧不加载模型文件。

## 跑起来

需要 Python、Node.js、Docker，以及一份填好模型密钥的 `.env`（模板见 `.env.example`）。

```bash
make setup      # 建虚拟环境、装依赖（只需一次）
make infra      # 起 MySQL / Redis / Chroma
make dev        # 后端 + 网关 + 前端，Ctrl-C 一起停
make worker     # 解析进程，另开一个终端
```

`make help` 会列出全部命令，一次性做的事、中间件、容器部署、数据库迁移都在里面。

## 目录

```
rag-qa-system/
├── api/          问答、文档、切片反查、系统接口
├── core/         检索、生成、会话、缓存、解析
├── worker/       文档解析进程
├── gateway/      登录与反向代理
├── frontend/     Vue 3 页面
├── config/       配置
├── alembic/      数据库迁移
├── scripts/      重建知识库、会话冒烟等一次性脚本
├── docs/         版本日志、迭代记录、验收清单
└── tests/        回归测试与验收脚本
```

知识库文档放在 `docs/`，按目录灌进系统即可；当前这份是 `docs/guoquan-kb/`。
