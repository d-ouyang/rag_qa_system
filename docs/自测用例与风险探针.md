# 自测用例与风险探针（P4-6 / P4-7 / P4-9 / P4-10 验证）

> 用途：上线后人工验收。分两部分——
> **第一部分**是「应该是什么样」的验证用例（验证本轮修复生效）；
> **第二部分**是「我最担心但没测过」的风险探针（专找还没暴露的问题）。
> 取证入口：① 对话框回答下方的徽章与「检索详情」面板；② 管理端 `admin.nianan.site` → 问答溯源（`/traces`）看 `决策 / 依据校验 / 低置信`；③ 服务器 SQL 查 `qa_trace` 表。

## 取证字段速查（判据都在这里）

| 位置 | 字段 | 说明 |
|---|---|---|
| 检索详情 | 改写后查询 | 单句=改写结果；复合句=多个子查询用 ` / ` 连接 |
| 检索详情 | top1 分数（过滤前） | 最高重排分；`< 0.1` 阈值 → 零召回拒答 |
| 检索详情 | docs_returned | 真正进上下文的切片数（复合句应为多路合并后的条数） |
| 检索详情 | BM25 关键词召回 / RRF 融合 top1 | 混合召回是否工作（关时为「未开」而非 0） |
| 回答徽章 | 依据校验 ✓ / ⚠️ 依据未确认 / 低置信 | P4-6；未确认时把鼠标停在徽章上看未支撑论断 |
| 回答正文 | 「依据：文件名 第X条」行 + 更正块 | P4-6 提示词第 6 条 + 二期更正块 |
| 溯源页 | 决策（decision） | `cache_hit / chitchat / zero_recall / rag_qa` |

服务器取证（最近 20 轮的判定一览）：

```sql
SELECT created_at, question, decision, grounded, top1_before_filter, docs_returned
FROM qa_trace ORDER BY id DESC LIMIT 20;
-- 低置信带（派生字段不落库）：
SELECT question, top1_before_filter FROM qa_trace
WHERE top1_before_filter BETWEEN 0.25 AND 0.35 ORDER BY id DESC LIMIT 20;
```

## 第二部分：风险探针（我没测过、最可能翻车）

按「我最担心」排序。每个探针给出：**怎么问** / **为什么会翻车** / **翻车长什么样** / **发现了怎么报给我**。

### 风险 1 — 分解过度（误伤单问句）
- 怎么问：`公司的愿景是什么？我们的使命呢？`、`报销流程是什么，需要审批吗？`
- 为什么：疑问标记计数可能把「一个问句里的两个疑问词」当成两个子问题，白白多一次 LLM 调用与两路检索。
- 翻车长什么样：改写后查询出现 ` / `，但两个子查询其实是一回事；回答被强行分成两节。
- 报我：贴「改写后查询」原文。

### 风险 2 — 摘要污染上下文
- 怎么问：先在某轮里故意说一句**错的**（如「我们公司病假是全薪的，对吧？」并让助手顺着答），5 轮之后再问「病假怎么算工资？」
- 为什么：摘要是模型压缩的，可能把错误前提当事实固化，后续回答引用它。
- 翻车长什么样：回答把「全薪」当既定事实，而库里根本没有这条规定（且可能不判无依据，因为摘要给了"依据"）。
- 报我：摘要原文 + 该轮回答。

### 风险 3 — judge 误判（把有依据判成没依据）
- 怎么问：连续问 10 个**库里明确有**的条款题（迟到、加班、出差、年假、报销流程…）
- 为什么：judge 提示词偏保守（「拿不准按 unsupported」），可能误报——误报的代价是用户对正确答案也不信任。
- 翻车长什么样：明显正确的回答挂「⚠️ 依据未确认」。
- 判据：误报率。经验阈值：**> 20% 就该调 judge 提示词**。

### 风险 4 — 拒答措辞两套（P4-7 硬化 vs 旧短路文案）
- 怎么问：`我们公司有下午茶补贴吗？`（零召回）vs `请病假会不会扣工资？`（有切片但无答案）
- 为什么：零召回走 `_NO_CONTEXT_ANSWER` 短路（旧文案），无依据走 prompt 硬化文案——**两套措辞可能不一致**。
- 翻车长什么样：一个说「根据现有资料无法回答该问题…」，另一个说「根据现有制度未查到相关规定…」。
- 报我：两句的完整原文（这是真问题，值得统一）。

### 风险 5 — 更正块之后的续写
- 怎么问：1.3 那个病假题，看更正块之后有没有又冒出一段「不过…通常情况下…」
- 为什么：更正块是**追加**的，模型原文里那句「可以参考…推测」可能仍在更正块**之前**，视觉上仍然误导。
- 翻车长什么样：更正块上面还有一段推测性文字。
- 报我：截图（这是「追加 vs 替换」策略的已知代价，要评估是否值得改成替换）。

### 风险 6 — 更正后的答案进了缓存吗
- 怎么问：问 1.3（病假扣薪，产生更正块）→ 隔一会儿**一字不差**再问一遍
- 为什么：缓存写入有 gate（是否独立问句），更正后的答案是否被缓存、缓存命中轮是否还带校验标记，都没验证过。
- 翻车长什么样：第二次回答**没有**更正块（命中旧缓存）或决策=cache_hit 但徽章消失。
- 报我：两次的回答与决策。

### 风险 7 — 复合问题 + 缓存叠加
- 怎么问：`怎么请事假？事假扣不扣钱？` 问两遍
- 为什么：缓存键是**原问句**，分解发生在缓存之后——命中时不再分解，行为可能与首次不同。
- 翻车长什么样：第二次回答比第一次差（或更好）——不一致就是问题。

### 风险 8 — 长会话 + 复合问题叠加
- 怎么问：先聊 7 轮，第 8 轮问复合句 `考勤以什么为准？迟到扣多少钱？`
- 为什么：摘要（SystemMessage）+ 多路检索 + 依据校验三者同时工作，上下文最长、最容易出错。
- 翻车长什么样：回答少答一个子问题，或依据张冠李戴。

### 风险 9 — 低置信黄标误报
- 怎么问：问到某个 top1 落在 **0.25~0.35** 的正常问题（看检索详情确认分数）
- 为什么：黄标是提示性的，但如果常见正常问答也挂，用户会习惯性忽略。
- 翻车长什么样：明显正确答案挂「低置信」。
- 判据：挂黄标时答案是否真的可疑（这条要人判断）。

### 风险 10 — 意图路由边界（chitchat vs 知识）
- 怎么问：`你好`、`谢谢`、`今天天气不错`、以及 `用一句话介绍公司愿景`（指令式、无疑问标记）
- 为什么：chitchat 路由跳过检索；指令式句子既不触发分解也不像问句。
- 翻车长什么样：闲聊被当成知识问题去检索（浪费），或指令式问题答非所问。
