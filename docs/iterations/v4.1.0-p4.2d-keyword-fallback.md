# v4.1.0-p4.2d · 问句形态零召回根治 + 逐条召回来源标注（2026-11-17）

## 线上实测（验收 A1）

「年假有几天？」→ 零召回拒答，top1=0.0728（差 0.0272）。同库复测：
「年假规定」0.3866 / 「年假」0.6578 / 「员工手册 年假」0.6578，命中
`05_考勤管理制度.md`，8~15 条过线。**结论：库里有内容，是疑问句式把
bge-reranker 分数系统性拉低**（0.07 vs 0.39~0.66）——这类问题反复出现。

## 方案：改写重查，不是降阈值

p4.16b 曾上过"阈值×0.5 抢救"，被用户否决撤掉（喂噪声给 LLM 仍拒答，白付成本）。
本次根治的是 **query 质量**：零召回时用 `_keyword_fallback_query(question)`
确定性剥掉句尾疑问/请求词（「年假有几天？」→「年假」），拿名词核心用
**原阈值 0.1** 再检索一次；命中则继续走 LLM（拒答句过滤 + groundedness 照常兜底），
仍为空才拒答。

- **纯规则零 LLM 成本**，只在失败路径多花一次检索（~0.5s）。
- 剥词正则**句尾锚定**，句中疑问词不动（「怎么申请报销」剥"怎么"会变味 → 不兜底）。
- 剥完为空 / 与原问相同 / 长度<2 → 不兜底（原样重查是浪费）。
- 命中时 trace 记 `keyword_fallback: {from, to}`，检索详情面板 `rewritten_query`
  显示实际用的名词查询，可观测。
