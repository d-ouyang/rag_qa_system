### 2.3 防火墙

轻量控制台「防火墙」添加规则。⚠️ 下拉里**没有字面 "TCP 80/443"**，是预设模板

`8080` 那条**故意先留着**——等 443 全链路验收通过再收，避免中间断档。

### 2.4 🔴 边缘代理选型反转（本次最关键的转折）

按原计划 `/opt/edge` 起独立 nginx 容器，启动直接失败：

```
Error response from daemon: failed to set up container networking: ...
failed to bind host port 0.0.0.0:80/tcp: address already in use
```

诊断（`docker ps -a` + `ss -tlnp` + `systemctl`）结论：

| 检查 | 结果 |
|---|---|
| `docker ps -a` | 没有 Caddy 容器 → **不是容器占用** |
| `ss -tlnp` | `*:80 users:(("caddy",pid=947))` → **宿主进程占用**，且当时只监听 80（无 443） |
| `which caddy` / `systemctl` | `/usr/bin/caddy`，**v2.11.4**，`caddy.service` active running |
| `/etc/caddy/Caddyfile` | **裸默认配置**（`:80 { root * /usr/share/caddy; file_server }`，即 "Caddy works!" 页） |

即：这台机器上有个**没配过、没托管任何真实站点**的 Caddy 白占着 80。接管它零风险。

### 2.5 反代目标怎么定

`docker ps` 同时暴露了 QA 栈当前是**自测形态**：

```
rag-frontend   rag-qa-frontend:latest   0.0.0.0:8080->80/tcp
rag-gateway    rag-qa-gateway:latest    0.0.0.0:3000->3000/tcp
```

⚠️ **Caddy 是宿主进程，解析不到 docker 服务名**（`qa-frontend` 这类名字只有容器网络内有效），
所以反代目标只能用**宿主已发布的端口**：前端 `127.0.0.1:8080`、网关 `127.0.0.1:3000`。
前端 SPA 的 API base 是相对路径 `/api`（同源），故 `/api*` 单独路由到网关，其余走前端。

### 2.6 个人站上线 + pnpm 11 设置搬家坑

本地 `pnpm build` → `rsync -avz --delete dist/ → /var/www/personal`。
中途踩到：`pnpm install` 报 `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild@0.28.2`。
🔴 **第一版修法是错的**——把 `pnpm.onlyBuiltDependencies` 写进 `package.json`，
但本机 **pnpm 11.21.0 已不再读 package.json 的 `pnpm` 字段**（多出一条 "no longer read" WARN），
正确位置是 **`pnpm-workspace.yaml` 的 `allowBuilds`**（pnpm 11 改名并搬家，且它自己已在文件里写好占位 `esbuild: set this to true or false`）。

## 3. 否掉的方案与代价（本次最值钱的部分）

**否掉 ①：独立 nginx 容器 + certbot（DNS-01 通配符）**
代价：宿主机 80/443 已被 Caddy 占，nginx 容器根本起不来（除非先停 Caddy，那是无谓的破坏）。
改用 Caddy 反而全面占优：自动 ACME TLS（HTTP-01，80 已通）、**免腾讯云 DNS 密钥**、免手动续期、
**默认不缓冲**（NDJSON 流式直接透传，nginx 才需要 `proxy_buffering off`）、零新增容器。
→ 文档 §5.3/§5.4/§6 整体改写，certbot 方案标记废弃。

**否掉 ②：管理端挂 `qa.nianan.site/admin` 路径形态**
代价：admin-console 是**独立 Vite 应用**，路径形态要改 vite `base: '/admin/'` + 路由 base，
SPA 资源路径与 history 回退都是坑；独立子域 `admin.nianan.site` 则 **base 保持 `/` 零改动**，
而证书成本两种形态一样（Caddy 每域一张，全自动）。→ 见文档 §2。

**否掉 ③：在服务器上构建个人站（装 node/pnpm）**
代价：4C4G 内存紧张，且给生产机引入前端工具链不符合「服务器只跑服务」。
改为**本地构建 + rsync 产物**，服务器零工具链、零构建开销。

**否掉 ④（纠错）：`pnpm.onlyBuiltDependencies` 写 package.json**
代价：pnpm 11 不再读该字段，设置完全无效只多一条 WARN。
→ 改写到 `pnpm-workspace.yaml` 的 `allowBuilds: esbuild: true`，并从 package.json 删掉无效字段。

## 4. 方法论沉淀

1. **端口冲突先诊断再动手**：`docker ps -a` 与 `ss -tlnp` 双查，先分清占端口的是**容器**还是**宿主进程**——
   两者的解法完全不同（前者改映射，后者要么让路要么接管）。
2. **宿主进程当反代，目标只能用宿主已发布端口**（`127.0.0.1:xxxx`），**不能**用 docker 服务名。
3. **静态站点上传后无需 reload Caddy**（`file_server` 按请求读盘）；只有改了 Caddyfile 才需要 reload。
4. **本地验证必须 `curl --noproxy '*'`**：本机 ClashX 代理会给新子域伪造 502、并把中文注释当主机解析，
   第一次验收被它误导过一轮（响应头里带 `Proxy-Connection` 就是代理插手的证据）。
5. 🔴 **Caddyfile 的空格陷阱**：`try_files {path} /index.html` 必须**带空格**（两个参数）；
   写成 `{path}/index.html` 会退化成「只有一个候选路径」，SPA 深层路由照样 404，
   而 **`caddy validate` 查不出来**——只能肉眼盯。
6. **健康端点用 `/api/health`**，不是 `/api/v1/system/health`（后者实测返回 405）。
