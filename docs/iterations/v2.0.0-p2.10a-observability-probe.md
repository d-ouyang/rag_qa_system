## 3. 关键设计决策（否掉的方案与代价）

**① 重新盘点 PLAN §P2-10 的「三项健康检查」——两项早就有，不重复造。**
动手前先勘察：队列积压深度 + Worker 心跳在 **P0-3 就实现了**（`/system/queue`，
`core/queue.py` 的 `queue_depth()` / `worker_alive()`）；MySQL 连通检查函数
`check_connection()` 也在 `core/db.py:143`（当时给启动自检用），**只差一条路由**。
真正缺的是「显式 MySQL 探针路由」和「聚合视图」。教训落档：**PLAN 的任务清单
是按当年写的，动手前先勘察存量，否则会把已有能力再实现一遍**。

**② `/overview` 存在的理由——/queue 的 docstring 自己认账的债。**
`queue_status()` 的 docstring 原话：「拆成三个接口，告警规则就得跨接口拼，
而拼出来的规则没人维护」。overview 把判读收进服务端一处：监控只盯
`overall.status` 一个词，降级原因在 `overall.reasons` 里逐条可读。
否掉的方案「让监控脚本自己拼五路数据再判级」：判读逻辑散落 N 个脚本，
改一条阈值要同步 N 处——正是那句 docstring 抱怨的形状。

**③ `?worker=false` 跳过阻塞探测。**
`worker_alive()` 走 Celery `inspect().ping()`，必须等满超时窗口（本站 1 秒）才能
确定「没有更多 worker 会应答」。高频轮询（如 30s 一次的看板）不该每次都付这 1 秒，
所以暴露成 query 参数；**代价**：跳过时「积压 + worker 死」这条判据不参与判定，
`worker_checked=False` 在返回值里显式声明，监控端不会误把「没查」当「正常」。

**④ 判级的语义与三条 degraded 判据（写死在服务端，测试钉住）：**
- `down`：MySQL 不可达（真相源挂了，登录/问答/解析全部不可用，别的判据无从谈起）；
- `degraded`（任一）：① Redis broker 不可达（新任务投不进队列）；② 有积压且
  worker 探测无应答（任务将卡到孤儿超时）；③ Redis 内存水位 critical/fatal；
- `ok`：其余。**无积压 + worker 死 = ok**（没任务时 worker 闲着不是故障）——
  这条反直觉判据在测试场景 5 单独钉住。

**⑤ 不加进网关免 token 白名单。**
`/system/db`、`/system/overview` 含文档计数、队列深度、连接池水位等运行面信息，
不进 `PUBLIC_PATHS`（现只有 `/system/health` 与 `/qa/health` 两个轻量探活）。
监控脚本在服务器本机直打后端容器，不穿网关——安全面零扩张。

## 4. 配置与接口变化

```
GET /api/v1/system/db
  → { db: { backend, ok, detail, latency_ms, pool: { status } }, checked_at }

GET /api/v1/system/overview[?worker=false]     # 默认阻塞约 1s（worker ping）
  → { overall: { status: ok|degraded|down, reasons: [...] },
      db, queue, worker, documents, memory, worker_checked, elapsed_ms, generated_at }
```

无新 env、无 schema 变更。网关侧无改动（不进白名单 = 需登录态，与 `/system/queue` 同）。

## 5. 验证证据

- `tests/test_module17_observability.py` **31/0，连跑两遍**（铁律）。
  判定规则七场景全部 mock 注入确定性依赖：db挂→down / broker挂→degraded /
  积压+worker死→degraded / 积压+worker死+跳过探测→ok / 无积压+worker死→ok /
  redis内存critical→degraded / 全正常→ok。
- **真实环境交叉验证**：本地 dev（worker 未启动 + 队列有 11 条历史积压）下
  `overall=degraded`，`reasons=['有 11 条解析积压且无 worker 应答（任务将卡到孤儿超时）']`
  —— 以前要跨接口拼的判读，现在服务端一句话给结论，且与 `/queue` 原始数据对得上。
- `/db` 实测：`latency_ms=53.7`（首次借连接，池命中后会降）、
  `pool.status='Pool size: 5  Connections in pool: 1 ...'`。
