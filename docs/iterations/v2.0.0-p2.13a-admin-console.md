## 2. 形态：多了前端，不多后端进程

| 项 | 决定 |
|---|---|
| 前端 | 独立应用 `admin-console/`，端口 `127.0.0.1:5174` + `strictPort`，`make admin` |
| 后端 | **不新建进程**。复用现有 FastAPI 的 `/api/v1/admin/*`（4C4G 预算，PLAN §11.1） |
| 视觉 | 深色仪表盘（见 §3.3），强调色沿用主应用的蓝 `#4f6ef7` |
| 依赖 | Vue 3 / TS / Vite / Pinia / vue-router —— 与主应用同一套技术栈，只多一个 vue-router |

> 「再加一个 Node 服务只需 ~50MB」听起来很便宜，但它换来的是：多一份 CORS 与端口、多一条要监控的健康检查、
> 多一个要在服务器上配 nginx 的进程。而这事的用量是一天几次。

## 3. 关键设计决策

### 3.1 ⚠️ 顺手修掉的**第四处**迁移往返数据损失（数据已经丢过一次了）

跑 `--apply` 之后的种子员工本应是 admin / hr / user + 1 名离职。
实际查库却是：

```
mysql> SELECT username, role, status FROM user;
wu.jing   | user | active      ← 管理员变成了普通员工
zheng.shuang | user | active   ← 离职的人变回在职
```

**根因**：`acceptance_p2_11a.py` 的往返会 `downgrade 0003 → 0002`，
`user` 表里由 0003 新增的**列连同数据一起被 DROP**，upgrade 回来时
`ADD COLUMN` 只能按 `server_default` 填。**列回来了，数据没回来。**

11d 那轮已经修过三处类似的损失（department / position / password_history 整表 DROP、
`employee_no` 被冲成 `LEGACY-<id>`），但**漏了 user 表自己的列** ——
因为脚本当时的断言只盯着「列在不在 / 行数变没变」，一条都没看值。

**修法**：往返前把别人（非脚本自己）的员工行按 id 快照 19 个业务列，往返后逐列还原，
并新增一条**逐列比对**的断言。

**代价/教训**（写进踩坑清单第 53 条）：
> 「列回来了」不等于「数据回来了」。凡是 downgrade 会 DROP 列的地方，
> 验收脚本必须**逐列比快照**，而不是只比 `COUNT(*)` 和 `information_schema`。

**已知遗留**：本次发现时数据已经被冲过一次，`role` / `status` / `must_change_password`
这些值无法凭增量找回，所以是**重建种子**修的（`seed_users.py --apply --reset`）。
数据延长线到此为止，不会有第二次。

### 3.2 身份：`Actor` 而不是「裸用户名」

路由层曾经有两种写法可选：

| 写法 | 后果 |
|---|---|
| 每个接口自己读 `Header(None, alias="X-User-Id")` | 同一段解析逻辑散落 N 处；漏一个就是一处没有权限校验的接口，而且**不报错** |
| 统一依赖 `current_actor` → `Actor`（采用） | 只有一个解析出口；权限判定（`can_reset_password` / `is_self`）写一次，全站共用 |

`Actor` 与 `UserRecord` 是两回事：`UserRecord` 是库里那一行的快照，
`Actor` 是**这一次请求的视图**，额外带 `identity_source`（header / dev_fallback / breakglass）
与权限位。看板里的「我到底是谁」在这种系统上属于必需品，而不是装饰。

### 3.3 为什么管理端是深色（这个决定要能回答「为什么和主应用不一样」）

主应用是浅色聊天界面 —— 它的背景是内容，要退到后面。
管理端天天盯的是**密集表格与状态列**：badge、状态色、表格线在深色上
不会被卡片阴影干扰，扫读更快。

否掉的另一条路是「深色侧边栏 + 浅色内容区」—— 那是把两套色板拼在一起，
结果是两边都要照顾对比度。强调色沿用主应用的蓝，保证它仍然是同一个产品。

### 3.4 dev / gateway 两种模式：差别只在「没有头的时候怎么办」

| 模式 | 缺头 | 库里查不到 | 用途 |
|---|---|---|---|
| `gateway`（生产） | **401** | **401** | fail-closed，见设计规格 §5.1.3 的 A 方案 |
| `dev`（默认，本机） | 回落 `IDENTITY_DEV_USERNAME` | 只有那个名字能当 break-glass 超管 | `make api` 起来就能用 |

为什么要 dev 模式：① 阶段登录真相源还在 `.env`（11c 才迁 MySQL），
网关签发的 JWT 里 sub 是登录名，而那个登录名在 user 表里**未必有一行**。
没有回落的话，登录成功 → 一进管理端就被 401 踢回登录页，
而它的成因离症状很远，排查会跑偏。

**为什么 break-glass 只认一个名字**：写成「谁查不到都当超管」的话，
任何一个拼错的 `X-User-Id` 都会得到一个 admin ——
那是把一次手误升级成一次静默越权。

### 3.5 浏览器里还验不了「非管理员登录被拒」（务必写下来，别让后面的人再查一遍）

① 阶段能登录网关的只有 `.env`（或 dev 兜底的 admin/admin123），
而这个人在 MySQL 里**没有一行**。所以此刻真实浏览器里的效果是这样的：

```
用 admin/admin123 登录 → /me 返回 identity_source=breakglass, role=admin
```

也就是说：**权限分层现在只能用 HTTP 头的形态验证**（见 §5.2），
还没法「打开浏览器、以陈杰的身份登录、看到 403」——
因为陈杰在网关眼里还不存在。这是 11c 的活，不是本轮的缺陷；
迭代文档里写清楚，是为了让下一轮的人不会被它当成 bug 排查一遍。

### 5.1 真链路（浏览器 → 5174 → 网关 3000 → 后端 8000）

```
make api + make gateway + make admin
curl -XPOST :3000/api/auth/login  admin/admin123   → 拿到 JWT

curl :5174/                                        → 200（Vite dev server 起得来）
curl :5174/api/v1/admin/me  （不带 token）          → 401（代理转发正常）
```

### 5.2 权限分层（CI 形态的真实断言）

`tests/test_module12_admin.py` **31 / 0**（连跑两遍）：

```
wu.jing(admin)      → 200  permissions.reset_password = true
zhou.yan(hr)        → 200  permissions.reset_password = false   ← D10
chen.jie(user)      → 403  「需要管理员或人事权限才能使用管理端」
zheng.shuang(离职)  → 403  「账号已停用或已离职」
nobody              → 401
数字 id (440)       → 200   ← 11c 之后网关会发整数 uid
```

**反向验证**：把 `require_staff` 依赖换成「谁都放行」之后，
`chen.jie` 的那条 403 变成 200 —— 证明 403 确实是这道守卫拦的，不是别的原因。

**gateway 模式 fail-closed**：缺头 401、查不到 401、正常链路不受影响。

## 6. 已知边界与遗留项

1. **浏览器里的「非管理员登录被拒」验不了**（§3.5）。11c 之前网关不认这些账号。
2. **dev 模式有一个 admin 后门**：任何请求缺头都会拿到 `IDENTITY_DEV_USERNAME`，
   而这个名字在库里没有时就被当成超管 —— 所以部署环境必须是 `IDENTITY_MODE=gateway`。
3. **后端仍不校验「头是不是网关注入的」** ——「无条件剥离」是 12b ① 的事，本轮一行网关代码没动。
   在此之前，**8000** 端口一旦对外暴露就是身份伪造。
4. **三个内容页是占位**（概览 / 员工 / 组织 / 密码），13b 与 13c 补齐。
5. **还没有 `audit_log`**（13d）。每个写操作会经 `admin_service` 走统一入口，13d 只需在那里插一段。
6. `.gitignore` 加了 `admin-console/dist`；管理端的 nginx server block 与 P1-7 / P2-9 一起做。
7. **`make test` 全量仍未跑**（module9 会清 `document`、module8 清会话），本轮继续挑模块跑。
