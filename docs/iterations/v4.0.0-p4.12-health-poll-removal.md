# v4.0.0-p4.12 · 侧栏服务状态灯去掉 30s 轮询（事件驱动探活）

## 1. 背景与动机

用户在 office 项目连续两次生产资源事故（fd 耗尽 / OOM）后提出：**前端不要再定时轮询 health 类接口**。排查发现 rag 5173 前端 `AppSidebar.vue` 有一个 30 秒轮询（`setInterval(pingHealth, 30_000)`）驱动侧栏"服务状态灯"。

- 本接口（`/api/v1/system/health`）本身是**纯静态轻接口**（不碰 MySQL/Redis/Chroma，system.py 内注释也明确它是"轻量探活"），泄漏风险为零；
- 但定时器的真实问题是：**后台标签页里也在空转打接口**（用户挂着页面不看，一天 2880 次），且与 office 事故后的"接口调用最小化"口径不一致。

## 2. 改动

`frontend/src/components/AppSidebar.vue`：

- **删除** `setInterval` 定时器（`healthTimer` 变量一并移除）；
- 状态灯保留，探活时机改为**事件驱动**：
  - 组件挂载时探活一次（原有）；
  - `visibilitychange` → **切回标签页**时补一次（用户真正回来看的时候才需要新鲜状态）。
- 卸载时移除监听器（原来移除的是 interval）。

## 3. 同轮排查（按用户要求 rag/office 全量过一遍）

| 项目 | 定时器 | 处置 |
| --- | --- | --- |
| rag 5173 `AppSidebar.vue` | 30s health 轮询 | **本版移除**，改事件驱动 |
| rag 5173 `stores/documents.ts` | 递归 setTimeout 轮文档状态 | **保留**：只在有文档正在解析时运行（业务进度查询，用户上传后需要它），且解析完自动停止 |
| rag admin-console | 无 setInterval | 无需处理 |
| office 前端 | 无 setInterval | 无需处理（OverviewTab 的 getHealth 是进页一次性调用） |
| office backend docker healthcheck | 60s /health（p2.7 已从 15s 放宽） | 保留：存活标记，chroma 单例化后无泄漏 |

- 纯前端改动，无接口/数据影响；`/system/health` 服务端一行未动。
