## 1. 这一版做了什么（一句话）

让知识库的**写入口对没有写权限的人不存在**：主应用的上传区、拖拽落点、删除按钮、重试按钮，

## 3. 关键设计决策（含**否掉的方案**）

### 3.1 前端的权限判据从哪来 —— 否掉「前端自己抄一份五档表」

**决定**：新增后端端点 `GET /documents/capabilities`，前端只读三个布尔。

**否掉的方案**：前端写一张 `const MIN_KB_ROLE = { none: 0, ops: 1, qa: 2, dev: 2, superadmin: 3 }` 自己比大小。

**为什么否**：这就是 13d（「两份清单各自漂」）与 14f（`set_role` 与 `set_kb_role` 严格度不一致）在同一个月里踩的两次。
漂了之后**不报错**：表现是「运营明明有权限却看不到上传按钮」，而没有人会想到去比后端那张表。
`kb_acl.capabilities()` 的 docstring 早就写好了这件事（「14d 的前端按钮显隐从这一个函数派生」）——
 那一行注释是 14a 写的时候留的，14d 只是来兑现它。

**代价**：多一次请求（进知识库页时一次，不进轮询）。为此专门加了两条判据：
`capabilities` 的三个键必须**齐全**（少一个键时前端 `?? false` 会把有权限的人当无权限），
以及「两个档位返回的能力必须不同」（防「恒返回同一个值」）。

### 3.2 隐藏还是置灰 —— 否掉「置灰 + tooltip」

**决定**：上传区与两个按钮都**不渲染**（只读时换成一张说明卡）。

**为什么不是置灰**：置灰按钮仍然占位、仍然长得像能点。
而「重试」会重新触发解析、「删除」会把全公司共用的文档从索引里抹掉 ——
这两项出现在一个只读用户的界面上，置灰与隐藏传达的是同一个信息（「你不能」），
但置灰多了一份「看起来能用其实不能用」的误导。

**为什么上传区要换成说明卡而不是留空**：一个点不动的虚线框会让人以为页面坏了。
说明卡把三件事说完了：你是只读的、你能做什么、找谁开通。

**代价**：只读用户**看不到**「知识库还能上传」这件事。
这是刻意的 —— 那是管理端的事，不是主应用该展示的。

### 3.3 🔴 拖拽那个洞（本项最容易漏的一条）

`KnowledgeView.vue` 的根节点上有 `@drop="onDrop"`，**不是**挂在上传区上。
所以「上传区不渲染」完全不妨碍「把文件拖到页面任意空白处照样上传」。

第一版只做了 `v-if` 收敛，浏览器验收时正好被对照组撞见：
只读用户拖文件 → 界面没反应，但**上传请求真的发出去了**（后端 403 兜住了，所以没出事）。

修法：`onDrop` 开头自己判 `canUpload`，且判断必须在读 `dataTransfer` **之前**
（否则已经准备提交了，只是不发）。

**这条为什么值得单列**：它是「界面收敛」这个任务里唯一一个**改了界面反而更容易漏**的地方 ——
因为验收时看界面是对的，只有监听网络请求才抓得到。

### 3.4 权限拉取时机 —— 否掉「进轮询」

**决定**：只在 `refresh()` 里拉（进页面 + 手动刷新）。

**为什么**：`kb_role` 在 token 有效期内不会变 ——
后端 `set_kb_role()` 会 bump `token_version` 让对方旧 token 立刻失效，
所以「token 里的档位」与「库里的档位」不可能长期不一致（这正是 14b 刻意不注入 `kb_role` 头的理由）。
每 2 秒重跑一趟纯属浪费。

**代价**：管理员改权限后，对方**当前页面**要刷新一下才看到新按钮。
可接受 —— 他的 token 此刻已经失效了，任何写操作都会 401 并被踢去重新登录，
重新登录后自然拿到新档位。

### 3.5 端点为什么用 `current_actor` 而不是 `require_kb_*`

恰恰是**没有**写权限的人才需要读它（才知道自己该看不能改）。
挂 `require_kb_upload` 的话，只读用户拿到的是403，
而他真正需要的恰恰是「一份告诉我我不能的答案」。

⚠️ 这个端点**不是权限闸门**，只是把既有判定如实告诉前端。
即使它被绕过（返回全 true），四条写路由的 `Depends(require_kb_*)` 依然会拒。
它错了的后果只是「界面多显示几个点了会失败的按钮」，不会造成越权。
这一点在端点的 `description` 里写死了 —— 因为「一个返回权限信息的端点」很容易被误当成「权限系统的一部分」。

### 3.6 修 14e 结构断言的一个真实缺陷：依赖提取器会扫注释

**症状**：加了 `/capabilities` 之后，`test_module12_write_acl` 的
「读路由不该挂 `require_kb_*`」转红，报 `实际依赖：'require_kb_ current_actor'`。

**真相**：提取器的正则是 `Depends\(\s*(\w+)`，它不区分代码与注释。
而我那个新端点的 `description` 里有一句「真正的拒绝发生在 `Depends(require_kb_*)` 上」——
注释里的那个 `Depends(require_kb_` 被当成真依赖提取了。

**修法**（修根因，不加白名单）：提取前先 `_strip_py_comments()`，走 `tokenize` 而不是朴素的「按 `#` 切半行」
—— 因为字符串里可能有 `#`（URL 片段、颜色值 `#00E0A4`），朴素做法会把后面真正的代码一起吃掉，
而「提取不到依赖」在这类结构断言里等于**漏检**（比误报更坏）。

**并补了四条提取器自检**（钉在每次回归里）。理由：剥注释最坏的失效是**剥过头**
—— 一旦它把代码也当注释，「每条写路由都挂了守卫」会全部转红，而红的原因是提取器坏了。
反向验证（让它恒返回空串）实测转红 11 条。

### 3.7 🔴 测试不该依赖「跑之前跑过什么」

**症状**：14d 测试在 `make test` 里跑是 34/0，单独跑也是 34/0，
但跟着 `test_module12_*` 跑一遍之后再跑就红1 条（`chen.jie` 401）。

**真相**：`tests/acceptance_p2_12b.py` 的 `restore_pwd()` 在收尾时把账号换成
**随机临时密码 + `must_change_password=1`** —— 那是它唯一诚实的还原方式
（种子的原始密码谁也不知道）。于是任何依赖 `dev_test_accounts.py` 那两个固定密码的测试，
在 `make accept-12b` 跑过之后就永久失效。

一个测试的成败取决于**跑它之前跑过什么**，那它测的就不是自己的被测物。

**修法**：14d 自己设密码（只写这两个账号的 `password_hash`），收尾换回随机临时密码。
代价是本模块要写库 —— 但不碰任何业务数据。

### 3.8 测试触发了真实的限流 —— 退避，而不是关掉它

**症状**：修完 3.7 之后，连跑第二遍又红了：`429 TOO_MANY_REQUESTS`。

**真相**：网关对 `POST /api/auth/login` 的限流是 **8 次 / 60 秒 / IP**
（写死在 `auth.controller.ts` 的 `@Throttle`）。14d 一次要登 2 个账号，
加上浏览器验收脚本也登 2 个，再加 `make test` 里其它要真登录的模块 —— 连跑几遍必然撞上。

**修法**：撞到 429 就等一个限流窗口（62s）重试，最多 2 次。

**为什么不关掉限流**：这与「用错密码会锁账号 15 分钟」是同一类问题 ——
**测试触发了真实的防护机制**。正确做法是让测试适应机制。
为了「让尺子准」而把尺子砸掉，得到的不是准，是「量不出东西」。

⚠️ 顺带修了一处更坏的东西：原本「登录失败就跳过第 2 组」，
而「跳过」与「通过」在退出码上无法区分 —— 那是最坏的一种失败方式。现在登录失败直接红。

### 3.9 验收脚本自己往知识库里塞了垃圾

**症状**：浏览器验收第一版跑完，文档数从 35 变成 36，多了一份 `probe.txt`。

**真相**：拖拽探针在「有写权限」那一侧是**故意**真发请求的
（作为对照组，证明这条探针本身是通的、不是恒真）。于是它真的上传了。

**修法**：`page.route(... route.abort())` 拦掉上传请求。
判据依然成立 —— 我们要验的是「**前端有没有发起请求**」，请求在 route 层就被掐断根本到不了后端。

顺带修了两处同源的坏判据：
- 「全程无 JS 错误」这条恒红，因为 `route.abort()` 会让浏览器记一条 `net::ERR_FAILED`。
  而那条控制台消息里**没有 URL**，所以按字符串分流会把真实的资源失败也一起放过 ——
  改用 `requestfailed` 事件（那里有 URL）分流，并且**只放行 upload 一类**。
- 「被拦的 upload 数 = 拖拽探针数」：不加这条的话，「拦了 0 次但请求也不发」与「拦了 1 次」
  在 `uploadHits` 上是同一个值，判据没有分辨力。
  只读侧也补了对称的一条「0 个被拦」（分得清「被守卫挡住」与「压根没走到那一步」）。

### 3.10 断言扫全文会咬住无关字面量

**症状**：「视图里不该出现 `'none'`」这条红了。命中的是模板里上传图标的 `fill="none"`（SVG 属性）。

**修法**：加 `_script_of()` 只取 `<script setup>` 段 —— 判据只可能写在 script 里。

这与踩坑清单第 50 条同源：**判据不精确时，它红的原因不是被测物有问题**，
而是自己撞上了别的东西 —— 而这种红会让人去改对的东西。

### Makefile

## 6. 已知边界

1. **只读用户看不到「知识库还能上传」这件事**。这是刻意的（§3.2），
   但如果将来产品上要「申请权限」的入口，位置应该在管理端或专门的审批流，不是主应用的知识库页。
2. **管理员改权限后，对方当前页面要刷新才看到新按钮**。可接受 ——
   他的 token 此刻已失效，任何写操作都会 401 并被踢去重新登录（§3.4）。
3. **`reindex` 没有 UI 入口**（只有 `scripts/reindex.py`），所以本版本的三个布尔里
   `reindex` 前端暂不使用。它照样下发，是为了将来加入口时**不用再改端点**。
4. **`/capabilities` 不在 `make kb-guard-count` 的护栏里**。它不是写路由，护栏不适用；
   但它确实是一个「返回权限信息」的端点，将来若有人给它加上 `Depends` 以外的判定，
   现有的结构断言（「端点内零 if」「判据来自 `kb_acl`」）会转红。
5. **14d 的测试会写两个账号的 `password_hash`**，收尾换回随机临时密码。
   如果在它运行途中 `Ctrl-C`，那两个账号会留在「测试密码」上 ——
   下次跑会自己纠正（它开头就设），但那段时间里知道密码的人能登进去。
6. 限流退避最多等 2 × 62s。连撞三次 429 时会红并提示「隔一分钟再跑」——
   刻意不无限等，否则 CI 里会出现「卡住」这种比红更难查的状态。

### §7.1 2026-10-07 · 14f 前端的表格视觉溢出（顺手修）

长标签「超级管理员（可上传 / 删除 / 重灌索引）」（21 个汉字）放进行内下拉，
把整张表撑到横向溢出，连带把左边几列压成竖排单字（「总部职能中心」→「总/部/职/能/中/心」）。

修法：后端加 `KB_ROLE_SHORT_LABELS`（**由长标签 `split("（")[0]` 派生**，刻意不另写一份 ——
另写一份就会漂，而漂了的表现是「下拉里叫 A、徽章上叫 B」，没有报错），
`/options` 一并下发 `short_label`；前端下拉用短名 + `.select.inline` 限宽省略。

反向验证：把短标签改成硬编码的另一份表（`superadmin` 写成「超管」）→ 1 条转红。

### §7.2 2026-10-07 · 管理端下拉失败不弹回（顺手修的旧 bug）

`changeRole` / `changeStatus` 失败时没 `await load()` ——
下拉停在「看起来改成功了」的值上，而库里还是旧值（`:value` 是单向绑定）。

这个 bug 与 14d 无关，是 14f 验收时看出来的。记在这里是因为它属于同一类：
**界面状态与真相源脱节且不报错**。
