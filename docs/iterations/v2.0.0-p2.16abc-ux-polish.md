## 3. 关键设计决策（含**否掉的方案**）

### 3.1 全局默认额度 0 → 100,000：用户决策推翻 15a 的一条设计

15a 的 `.env` 注释里写着「故意留 0，不是拍一个数字」。2026-10-08 用户拍板
「给个固定用量」—— 他要的是每个人一上来就有一个**可见的额度**，而不是「不限」。
选择 100,000 的依据是**实测**：本月人均用量 5,368 tokens（唯一有用量的人），
100K ≈ 18 倍余量，正常使用碰不到 80% 提醒线。
注释里的旧论据没有删掉重写，而是写明「被哪天的决策推翻、依据是什么」——
三个月后的人要知道这不是拍脑袋，也不是原设计，是一次变更。

### 3.2 🔴 下拉的两个 UI 问题，根因是原生 `<select>` —— 换组件才是根治

- **箭头贴右**：原生箭头是浏览器画的，`padding-right` 只影响文字、动不了它；
- **面板遮挡触发框**：原生下拉面板是浏览器原生 UI，位置、样式前端都控制不了。

**❌ 否掉的方案**：`appearance: none` + 背景图自绘箭头 —— 能解决箭头，
但面板遮挡依然无解（还是原生 UI）。两个问题一个根因，一次换干净。

`AppSelect` 的实现要点（每条都有实测理由）：
- 面板 **Teleport 到 body + fixed 定位**：管理端表格容器有横向滚动
  （`overflow-x: auto`），面板放在组件树里会被裁掉；
- 面板 `top = 按钮 bottom + 4px`：永远向下展开，**几何上不可能遮挡触发框**
  （验收 C3 用 boundingBox 断言了这一点，不是「看起来对」）；
- 滚动/resize 时关闭（重算比跟随简单；打开状态下用户几乎不会滚动）；
- `modelValue` 支持 `string/number/null`，change 回传**原始类型**——
  部门/职位 id 是 number，被转成 string 会让 `changeStatus(row, v as UserStatus)`
  这类调用拿错类型。

### 3.3 OrgView 的父部门选项必须基于 `parentOptions`（防环拦截不能丢）

替换时第一版把选项表基于 `departments` 全量 —— 那会丢掉
「部门不能把自己/子孙设为上级」的前端防环拦截（后端还会再兜一次，
但前端先拦是 13b 的设计）。修正为基于已过滤的 `parentOptions`，
并在注释里写明为什么不能图省事。

### 3.4 全局默认变更的连带：两条测试断言从「写死 0」改为「与 settings 一致」

`/quota/me` 空横幅、看板 `usage_percent is null` 两条断言都以「全局默认=0」为前提。
默认改 100000 后它们红是**应该的**（前提变了）——
修正方向是让断言读 `settings` 而不是写死数字，
这同时让它们对将来的额度调整免疫。

## 5. 已知边界

1. **历史总用量的口径是「现存明细的累计」**：会话删除（硬删）会让它变小。
   面板副标题写明「删除会话会同时移除其用量记录」—— 文案不说满。
2. AppSelect 展开状态下用户滚动页面 → 面板关闭而不是跟随
   （重算比跟随简单；打开状态下滚动极罕见）。
3. 个人信息面板**只读**（无编辑入口）：改资料是人事职责（管理端），
   问答端给编辑入口会把人事数据的真相源从 MySQL 挪到「用户随手改」。
