| **性质** | 计划内（PLAN-v4.0.0 P4-9；q042 复合问题实测驱动） |
|----------|--------------------------------|
| **tag** | `v4.0.0-p4.9` |
| **默认行为** | 单问句行为不变；含 ≥2 个问号的复合问句自动分解为 1~3 个子查询分别检索 |

## 背景

复合问句「怎么请事假？事假扣不扣钱？」作为单查询检索，重排分被稀释：单独问 top1=0.4787、5 个切片通过；复合问 top1=0.3488、**仅 1 个通过**（还是无关的考勤打卡切片），事假流程切片缺席 → 答案缺流程。改写模块只做指代消解，不做拆分。

## 实现（四件套）

1. **改写提示词**：复合问题按行输出子问题（最多 3 行，剥编号前缀），单问题原样返回。
2. **`rewrite_to_sub_queries()`** 新入口：解析逐行输出为子查询列表；P4-7b/c 的指代重试语义原样迁移（单元素原样返回且含指代 → 强化指令重试一次）；`rewrite_query` 降级为字符串包装（评测脚本 `--enhance` 兼容）。
3. **`_multi_retrieve()`**：每个子查询各走一遍**完整检索**（混合召回 + 重排 + 阈值），候选池按 chunk_id 去重合并（多路命中保留最高分）、按 rerank 分降序；轨迹合成——top1 取各路最大值（低置信带判定沿用）、bm25_hits 逐路累加、合并池全量进 candidates。
4. **零成本复合预检 + 生成侧**：问号 ≥2 的问句首轮也触发改写分解（复合问题不依赖「有历史」）；`_QA_SYSTEM_PROMPT` 第 7 条要求分子问题组织回答、子问题无依据须明说。

## 端到端实测（真实链路）

「我想咨询下事假怎么申请，另外事假期间工资是怎么算的？」→ 分解 2 路 → 合并候选（829:1 员工手册摘要 + 813:0 请假申请单）→ 回答按「### 事假申请流程 / ### 事假期间工资计算」分子问题作答、两个子问题都诚实「未查到」→ judge 判 False → 更正块追加。

**已知局限（P4-9 二期候选）**：子查询措辞敏感——改写出的「事假怎么申请」该路 top1 仅 0.121（单独问「怎么请事假」为 0.4787），低分切片虽进上下文但模型利用度低；多路合并后是否对合并池做一次统一 rerank、改写提示词的措辞贴近度，留待评测调优。

## 踩坑（本期新增）

## P4-9b（2026-10-17 深夜，tag `v4.0.0-p4.9b`）：复合预检不再只数问号

用户提问指出：无问号的复合句（「事假怎么申请，另外事假工资怎么算」）怎么办？首版触发门只数问号（≥2），这类句子根本不触发分解。

**重要澄清**：问号个数**不是**分解依据，只是「要不要花一次 LLM 做改写」的零成本触发门；真正的拆分由改写模型按行输出（最多 3 行）。

**改为 `_looks_compound()`**（三条命中其一）：问号 ≥2 ／ 疑问标记 ≥2（怎么·如何·多少·几·是否·能不能·会不会·哪些·什么·吗·呢）／ 并列连词（以及·另外·还有·同时·并且·；·且）+ ≥1 疑问标记。单问号+单疑问标记（「怎么申请事假？」）刻意不触发以避免误伤；9 例边界用例固化（module26 66/0）。

**剩余缺口**：纯指令式复合句（无任何疑问标记，如「请说明事假流程和扣薪标准」）仍不触发——只能靠「始终改写」（QUERY_REWRITE 打开，每轮 +1 次 LLM 调用）或小模型判定，列二期候选。
