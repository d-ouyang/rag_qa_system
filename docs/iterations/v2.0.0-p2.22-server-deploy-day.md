> 性质：**计划外运维修复迭代**（类比 p2.14f0）。当天完成腾讯云轻量服务器（4C4G 上海，Ubuntu 24.04）

## 1. 一句话总结

首部署当天踩了 13 个问题，其中**真 bug 三个**（nginx 请求流式竞态丢 body、
`crypto.randomUUID` 非安全上下文崩溃、Dockerfile 依赖安装的网络脆弱性），
**环境陷阱五个**（AppleDouble 影子文件、软链接死链、compose `$` 插值、PyPI 镜像截断、
Docker Hub 不可达），**设计预期行为三个**（网关 fail-closed 两连、kb_role 独立授权维度、
检索阈值短路拒答）。全部闭环，系统在 `http://42.192.111.82:8080` 可用。

## 2. 问题时间线与根因

### 2.1 部署准备段

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 1 | 绑定 SSH 密钥后 `Connection closed by ... port 22` | Lighthouse 绑定密钥后**必须重启实例**才注入 authorized_keys | 控制台重启即通；登录用户名 `ubuntu` 非 `root` |
| 2 | 服务器无 Docker | 全新系统 | `apt install docker.io docker-compose-v2`（⚠️ 不用 snap 版，有网络/挂载坑）；`usermod -aG docker` 免 sudo |
| 3 | 担心内存不足 | — | 实测镜像出厂自带 `/swap.img` 1.9G 且已写入 fstab，无需手动加 |
| 4 | `alembic upgrade` 报 `source code string cannot contain null bytes` | macOS 打 tar 时给每个文件附带的 **AppleDouble 影子文件**（`._0001_xxx.py`）以 `.py` 结尾，被 alembic 当迁移加载 | `find /opt/qa -name '._*' -delete` + 重建镜像；打包命令固化 `COPYFILE_DISABLE=1` + `--exclude='._*'` |
| 5 | backend 容器挂载失败 `mkdir /opt/qa/models: file exists` | 本地 `models/` 是指向 `~/Downloads` 的**软链接**，tar 把死链接带上服务器 | 删链接建空目录；线上 embedding/rerank 走硅基流动，本地模型目录只需占位 |

### 2.2 构建段（三次失败换来的最终方案）

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 6 | 拉镜像 `registry-1.docker.io i/o timeout` | 国内服务器直连 Docker Hub 不通 | `/etc/docker/daemon.json` 配 `mirror.ccs.tencentyun.com`（内网）+ `docker.m.daocloud.io`（备份） |
| 7 | pip 装 lock 第一败：`files.pythonhosted.org Read timed out` | 直连 PyPI 超时 | 换清华镜像 |
| 8 | pip 装 lock 第二败：清华镜像回源仍 `Read timed out` | 镜像对冷门文件回源代理，仍撞上游 | 换腾讯云内网镜像 + `--timeout 600 --retries 10` |
| 9 | pip 装 lock 第三败：`JSONDecodeError: Unterminated string` | **串行拉 200+ 个包的元数据，暴露时间长，随机截断必中招** | 🔴 **结构性修复（Dockerfile）**：① torch 单独成层（装完即缓存，重试成本从 45min 降到分钟级）；② lock 改用 **uv 并行安装**（内置重试，快一个量级）；③ index 用腾讯云内网 + 清华兜底。实测 torch 层 66s 缓存命中、uv 安装一次通过 |

### 2.3 运行段（网关 fail-closed 逐道过卡）

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 10 | 网关启动即崩 `生产环境必须配置 GATEWAY_JWT_SECRET` | 11c fail-closed：生产缺 JWT 密钥拒绝启动；本地裸跑读 `gateway/.env` 有值，服务器根 `.env` 没有 | `openssl rand -hex 32` 追加 |
| 11 | 接着崩 `生产环境必须配置 GATEWAY_USERS` | 同为 fail-closed；break-glass 超管 | 本地 `hash-password.js` 生成 bcrypt，⚠️ `.env` 里 `$` 必须写成 `$$`（compose 插值会吃 `$2a$10$`） |
| 12 | backend 挂载 `mkdir /opt/qa/models: file exists` | 见 #5 | 同 #5 |
| 13 | `.env.example` 里没有 `GATEWAY_ALLOWED_ORIGINS` | compose 用 `${VAR:-default}` 引用，默认值是 localhost，服务器上必须显式加 | `echo` 追加一行 |

### 2.4 联调段（权限与两个真 bug）

| # | 现象 | 根因 | 处置 |
|---|------|------|------|
| 14 | wu.jing 登录后知识库只读 | **P2-14 设计行为**：`role`（管理端权限）与 `kb_role`（知识库写权限）是独立维度，种子默认 `kb_role=none` | SQL `UPDATE user SET kb_role='superadmin'`（实时生效）；⚠️ 改完必须**重新登录**——网关粗筛（14b）用的是 JWT 里的 kbRole 快照，旧 token 有滞后 |
| 15 | 浏览器上传随机 422 `body.files Field required`（约一半失败） | 🔴 **本次最大坑**。排查路线见 §3；抓包定案：nginx 收到完整 body，转发给网关时**只发头、丢体**。真凶 = `proxy_request_buffering off`（请求侧流式）与网关 Node 流处理之间的**随机竞态**，与文件名/大小/请求头全部无关 | 删除 `frontend/nginx.conf` 的 `proxy_request_buffering off`（问答流式只依赖**响应侧** `proxy_buffering off`，请求侧缓冲开启零损失）；修复后批量 12/12 全过 |
| 16 | 点「新建会话」`TypeError: crypto.randomUUID is not a function` | `crypto.randomUUID` 只在**安全上下文**（HTTPS/localhost）存在；`http://IP:8080` 是非安全上下文（本地开发是 localhost，从未暴露） | `sessions.ts` 新增 `uuid4Hex()` 降级：`crypto.getRandomValues` 手工拼 RFC 4122 v4 位段，格式与后端 `uuid4().hex` 一致 |
| 17 | 删除文档后知识库残留 6 个片段（sources 指向已删文档） | **删除与解析并发竞态**：文档在 `pending/parsing` 时被删，worker 解析完成后把切片写入，文档行已不在 | 新增 `scripts/clean_orphan_chunks.py`（干跑默认，`--apply` 真删；判据 = chunk 的 doc_id 不在 document 表）。**归档为已知边角竞态**，代码级修复（删除时撤销解析任务）待立项 |
| 18 | Q2「我想知道年假有多少天?」被拒答，Q3「那公司的假期制度有吗?」成功 | **检索阈值短路（设计行为）**：拒答文案是固定模板 `_NO_CONTEXT_ANSWER`（rag_chain.py:236），证明未走到生成 LLM；182 tokens 是前段意图/改写调用的消耗。Q2 改写后查询未拿到过阈值候选（retriever.py:196 `score_threshold`）；Q3 因会话上下文改写更准而命中 | 诊断成立；**观测盲点**（被全过滤时日志看不到原始 top1 分数）立项为 **P2-23**（见 §5） |

## 3. 否掉的方案与代价（本次最值钱的部分）

| 否掉的方案 | 为什么否 |
|-----------|---------|
| 重装系统选「Docker CE 应用镜像」 | `apt install docker.io docker-compose-v2` 在 Ubuntu 24.04 上一次成功，重装是不必要的破坏性操作 |
| `snap install docker` | snap 版 Docker 有网络/挂载路径的坑，社区共识回避 |
| 清华镜像作为 PyPI 终解 | 对冷门包回源代理到 pythonhosted，仍随机超时；换腾讯云内网镜像后仍有截断 → **换装包器（uv）才治本** |
| 继续用 pip + 加大 timeout/retries | 串行拉 200+ 包元数据暴露时间长，随机截断只是概率问题；uv 并行 + 重试才结构性地消除 |
| Clash DIRECT 规则 / 换 Safari / 改 ASCII 文件名 / 排查请求头 | 全部是**假相关**方向：抓包证明 body 在浏览器→nginx 一跳完整到达、nginx→网关一跳丢失，与客户端、文件名、请求头无关（见 §4 教训） |
| 用 Copy as cURL 重放上传请求 | Chrome 对 multipart 的 Copy as cURL **丢弃文件内容**（只留空 part），重放结果是「内容为空」业务错，不代表浏览器真实行为 |
| 修网关代码适配流式 body | 本地同版本 nginx 全字节透明复现失败 + 一次性容器 A/B 对照（缓冲开/关）分离出行为差异 → 修配置一行即可，不动代码 |
| 盲调 `score_threshold` 救回 Q2 类问法 | 没有可观测数据（原始 top1 分数 vs 阈值）之前调参是瞎猜 → 先立 P2-23 再调 |

## 4. 方法论沉淀

1. **🔴 假相关陷阱（踩坑 50「概率断言」的亲历变体）**：A1（中文名）失败、A2（ASCII 名）成功，各只有**一次样本**就下了「中文文件名」结论；Safari 的结果看似佐证，实际也是单样本。直到批量 12 连发出现「同一个文件忽成忽败」才暴露**随机性**。**规矩：遇到随机失败，先跑 N 次重复试验确认失败率与分布，再找变量。**
2. **抓包定案法**：`tcpdump -i any` 三跳全捕 + `strings | grep -c` 数边界串出现次数（完整体每跳 3 次：头 1 + 体开 1 + 体尾 1），一次抓包同时推断三跳的 body 有无与框架类型。
3. **Copy as cURL 对文件上传是有损的**（Chrome 丢文件内容），不能用于重放验证，只能看头。
4. **跨机传输陷阱清单**：AppleDouble 影子文件、软链接死链、`node_modules/.venv/.git` 冗余 —— 打包命令固化为 `COPYFILE_DISABLE=1 tar --exclude='._*' ...`。
5. **compose 的 `.env` 值里 `$` 必须写 `$$`**：bcrypt 哈希 `$2a$10$` 会被插值吃成空串，网关照样能启动（parse 不校验哈希形状），break-glass 静默失效。
6. **fail-closed 的生产启动链是逐道过卡**：`GATEWAY_JWT_SECRET` → `GATEWAY_USERS` → …… 每道都是设计行为，部署文档应前置清单。
7. **安全上下文 API 清单**：`crypto.randomUUID` 属于「HTTPS/localhost 才有」的 API 家族；IP+HTTP 访问是部署验收常态，前端必须对这类 API 带降级。
