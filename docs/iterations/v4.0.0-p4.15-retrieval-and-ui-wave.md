# v4.0.0-p4.15 · 检索与生成加固 + 引用展示重做（同源聚合 / 预览 / 分页 / 跑马灯）

> 本批是 p4.14 之后连续多轮「边用边修」的产出：一半是检索与生成的正确性，一半是引用区与侧栏的可用性。
> 全部只在 `develop`，**未合 main、未上生产**（生产仍是 `v4.0.0-p4.13b`）。

## 1. 交付

### 1.1 检索与生成

1. **双路检索 + 零召回回退**（`core/rag_chain.py`）：在既有「猜测试检索」上补
   `_merge_rerank / _merge_retrieval / _reconcile_dual / _rewrite_strict`——
   改写后问句与原始问句各检索一路，按 `_doc_score` 合并去重；某一路零召回时用另一路兜底，
   两路都空才判定零召回。轨迹新增 `dual_used / fallback_used`，前端检索详情可看到走了哪一路。
2. **依据校验（judge）硬化**（`core/groundedness.py`）：
   - 判定规则补「数字、档位、期限、比例、金额必须与原文逐字/逐档一致」；
   - 被阈值过滤的候选原文以【补充候选资料】分区进 prompt（解决「细节在另一条被过滤切片里」的误判），
     候选上限 5 → 10；
   - 新增「说明资料边界」豁免：答案里「资料只按类别汇总 / 没有按人拆分」这类表述属于如实告知，
     不计入 unsupported——否则 p4.15 新加的部分匹配规则会被 judge 反向判成「依据未确认」。
3. **问答提示词**（`_QA_SYSTEM_PROMPT`，规则 1–10）：
   - 去掉「依据：…」引用行（引用由界面统一展示，正文里再写一遍是噪音）；
   - 数字不许改写成区间档位（「每增 1 年增 1 天」不能写成「5-10 年 10 天」）；
   - 按级别/情形/对象分别规定时按类别完整列出，不许因为不是单一数值就说「未查到」；
   - **新增规则 3「部分匹配」**：资料有同类但粒度不同的数据时，先用资料原粒度列出已有数据，
     再另起一句说明缺哪一维，只有完全无关才用固定拒答话术。
4. **QA 直击门控前移**（`core/qa_direct.py`）：精确层移到 `is_standalone_question` 之前，
   「婚假多少天」「调休怎么算？」这类短问/指代词也能命中问答集（此前被 6 字门控挡在语义层外）。
5. **标识符不参与改写**：`_IDENTIFIER_RE / _looks_identifier / skip_rewrite`——
   问句里带编号/条款号时跳过改写；`_sanitize_rewrite` 补冒号句式、列举标记、标识符丢失三类兜底。
6. **会话标题首问自动生成**（`core/memory_manager.py`）：首轮问答后把问句前 60 字写进
   `session_meta.title`，侧栏不再出现「会话 ab12cd34」。摘要改异步（`_summarize_async` 守护线程），
   `done` 帧不等摘要。
7. **逐步耗时落库**：`timings{prepare_ms, generate_ms, grounded_ms, other_ms, total_ms, llm_timeout_ms}`
   进 `turn_meta`，历史接口按轮回填；`llm_timeout_ms` 让「60s 超时后自动重试」这类假慢可见。
8. **SourceItem 契约补字段**（`api/routes/qa.py`）：`doc_id / section / qa_id / match_via / match_score`；
   旧数据缺 `index/chunk_id` 时给默认值，历史消息不再 500。
9. **文档加载**（`core/document_loader.py`）：
   - 新增 `.xlsx`：openpyxl → markdown 管道表，单元格 `|` 转全角，前缀「工作表：{title}」；
   - 数据行 > 10 的表格按**行原子**切分（每片重复表头 + 分隔线），≤ 10 行按表分组
     —— 此前 `UnstructuredExcelLoader` 空格拼文本会把一行拆到两片里，检索命中却答不出；
   - PDF 抽文本 < 20 字时告警「疑似扫描件/纯图层」，不再静默产出空片。

### 1.2 前端

1. **引用卡片重做**（`MessageBubble.vue`）：点任意引用展开详情（切片全文 / QA 标准答案 + 来源条款），
   一次只展开一条，取数结果按 `chunk_id` 缓存（含失败态，避免反复打接口）。
2. **引用资料按源文件聚合**：分组键 `doc_id` 优先、退化文件名；组内切片按重排分降序；
   **组的位置 = 组内最高分切片在后端序列里的位置**（1、3、5 同源 → 整组落在 1，2、4 依次在后）。
   组头一份文件名 + 唯一一个「查看原文档」，组内每行 `资料N` + 切片标识 + 重排分。
   折叠按钮显示「引用资料 N 条（M 个文件）」。**后端 `sources` 顺序与落库一概不动**，不落 `display_sources`。
3. **文档预览**（`DocumentPreview.vue`）：PDF（`<object type="application/pdf">` + iframe 兜底）、
   docx（mammoth）、xlsx（SheetJS，多工作表页签 + 1000 行/50 列上限提示）、图片、md。
   解析全部放 Web Worker（`lib/md|docx|xlsx`）。下载接口返回 `application/octet-stream`，
   预览前按扩展名重包 Blob 的 MIME，否则 iframe 会把 PDF 当文件下载。
4. **Tokens / 耗时两个徽章共用一个明细浮层**：浮层挂在 `.meta-hover` 容器里（不再嵌在 Tokens 徽章内），
   纯耗时消息也能弹；浮层 `position: fixed` + JS 写视口坐标，贴底时朝上展开。
5. **侧栏会话分页**：每页 10 条，「查看更多（剩余 N 条）」/「收起」，分组标题显示总数。
6. **侧栏标题溢出渐隐 + hover 跑马灯**（`SessionTitle.vue`）：实测溢出（`scrollWidth > clientWidth`）才滚；
   右端 26px 渐变遮罩（滚动中同样保留，否则硬切）；8s linear infinite 无缝循环；窗口 resize 重新测量。
7. **登录页密码显示开关**；dev 账号 `admin` 全量替换为 `wu.jing`。

## 2. 关键决策与被否掉的方案

- **CHUNK_MODE 保持 `fixed`**，title 模式（`MarkdownHeaderTextSplitter`）实现保留但不启用：
  切分参数一改就是整库重建 + golden 全量重标，本批没有这个预算。已写进切分策略文档，等整库重建窗口一起做。
- **同源聚合放前端而不是后端合并**：`sources` 是「本轮答案实际引用了哪些切片」的事实记录，
  改它会影响溯源与评测（chunk 级 recall）；展示层重排可以随时回退，且历史消息刷新后表现一致。
- **不落 `display_sources`**：两份真相必然漂移，展示分组是纯函数，宁可每次重算。
- **部分匹配规则没有推翻「不许编造」**：规则 3 只允许「照抄原粒度 + 声明缺哪一维」，
  并配了 judge 侧豁免，避免防幻觉变成「宁可什么都不答」。
- **被否**：把拒答话术从提示词里删掉换成「请说明你找到了什么」——实测模型会退化成自由发挥，
  固定话术对负样本（EXT-19）仍是必要的硬约束。

## 附：title 切分模式复核（2026-11-04 晚，结论：**继续否决**）

**背景**：既然 p4.15 上线必须整库重建，用户提出「趁这次把 `CHUNK_MODE=title` 一起打开，
避免以后再来一次重建」。方向对——重建是稀缺窗口；但 p3.7a 当年实测 title 更差（recall@5
0.94 → 0.61）才默认 fixed，所以先在本地区间复测，达标才动线上。

### 复测方法（这次比 p3.7a 严谨一档）

1. `snapshot_kb_p37a.py` 导出当前 fixed 库 436 条切片正文；
2. golden 全部重标（`remap_golden_p37a.py`，52 个标注 id → 81 个，**0 条失配**）；
3. 同一条命令跑三档：`fixed-pre`（基线）/ `title`（原样）/ `title-fix`（修缺陷后）；
4. 新增 `scripts/compare_chunk_modes.py`：按**内容**把新切片折回旧 id，两个口径对比
   —— chunk 级（同一套标注）+ 文档级（该文档进没进 top-k）。
   文档级是为了排除「切法不同导致标注重叠」的干扰：文档都不在 top-5，就一定答不出。

### 数据（42 题，31 道库内；同一套旧标注折算）

| 口径 / 指标 | fixed（基线） | title（原样） | title（修缺陷后） |
|---|---|---|---|
| chunk 级 recall@5 | **0.9086** | 0.5742 | 0.8172 |
| chunk 级 hit@5 | **0.9677** | 0.8387 | 0.9032 |
| chunk 级 mrr@10 | 0.8559 | 0.7455 | 0.8710 |
| 文档级 hit@5 | **1.0000** | 0.9677 | 0.9355 |
| 库内误拒 | 0/31 | 1/31 | 2/31 |

原文切换后 `title-fix` 与 fixed 的**文档级**差异只剩两条，但两条都是灾难态：
q028「公司在供应链上做过哪些收购和投资？」与 q042「怎么请事假？事假扣不扣钱？」
在 title 下 **top-5 完全为空**（零召回 → 直接拒答），fixed 下都能答。

### 根因（已修一半，另一半是切分粒度的固有代价）

- **缺陷 1（已修）**：短节合并时 `header_path` 取两节的**公共祖先**。制度类 md 里
  150 字以下小标题极多（第五章 加班管理 145 字、第六章 115 字），一合并就退到文档级
  「考勤管理制度」——合并块的 enrichment 前缀里既没有第四章也没有第五章。改为沿用**首块**路径。
- **缺陷 2（已修）**：二次切时表格段前会 flush，把「## 第四章 请假管理 / 第九条 请假类型…：」
  甩成独立一片（35 字），表格单独一片且丢了引导句。改为**过短片并给下一片**。
  修完 md 切片 197 → 113，最短片从 6 字升到可用长度。
- **固有代价（修不掉）**：title 把一片 500 字的「标题 + 条款 + 整张表」拆成 200～350 字的三四片。
  top_k=5 的预算下，同一个问题的证据被切散，rerank 更容易把「有标题没数据」的片排上来；
  请假表那种「引导句 + 大表」即使合回一片，也因为缺前后条款的语境而分数下滑。

### 裁决

**`CHUNK_MODE` 维持 `fixed`，线上按 fixed 重建。** 两条缺陷的修复保留在代码里
（title 目前唯一的线上使用者是 MinerU 产出的 PDF markdown，修完 pdf 82 → 80 片，
19 条扩展题基线仍 19/19）。若将来要再试 title，前置条件是：把「短节贪心打包到接近
chunk_size」做成可选档（`title-pack`），而不是继续用「只合并 <150 字」的规则。

### 事故：md 解析联网下载 NLTK，重建卡死 1 小时（→ p4.15c）

- **症状**：`reindex.py --apply` 跑了一小时零写入，Chroma 仍是 69 片；进程 CPU 0.07%、
  主线程阻塞在 `read(19)`。
- **定位**：`strace` 看到阻塞 fd 指向 socket，`/proc/PID/fd` 里有
  `/root/nltk_data/tokenizers/punkt_tab.zip.tmp` —— 半截下载文件。即
  `UnstructuredMarkdownLoader` 在缺 NLTK `punkt_tab` 时**联网抓 raw.githubusercontent.com**，
  服务器到该域名不通且没有超时。
- **为什么本地没发现**：本地有代理安全拦截，NLTK 请求**立刻报错**并回退纯文本，
  反而显得一切正常；只有服务器这种「连得上但不回」的网络才会挂死。
- **临时解锁**：容器 `/etc/hosts` 把该域名指到 127.0.0.1，让下载快速失败 → 走回退路径，
  重建随即完成。**这是临时的**（容器重建即失效）。
- **根治（p4.15c）**：`.md` 改为直接按文本读，不再经过 unstructured。切分本来就由本模块自己做，
  title 模式用的是原始 `#` 标记，unstructured 的 element 结构从未被消费。
- **等价性验证**：本地整库重建前后 **434 片 → 434 片，同 id 同内容 434/434、零新增零消失**，
  所以线上已重建的 90 片无需再重灌。module2 118✓ / p37a 28✓。
