## 范围收缩（2026-11-16 用户拍板）

原计划的「本地 bge-m3 降级链」**否决不做**，全走 API：
1. **生产未部署任何本地模型**（Ollama 未装，服务器可用内存 1.5G，跑不动）；
2. **嵌入空间不兼容**：生产 Chroma 434 片全部是 bge-large-zh-v1.5 编码——降级用
   bge-m3（或其他任何异模型/异 API）编码 query 会导致召回整体失效。**嵌入模型
   的降级铁律：只能是「同一个模型的另一个来源」**；
3. 服务器 4C4G 跑本地 embedding 成本/收益不划算。

**bge-m3 全量迁移**列为独立决策项（前提：④1 golden set 门禁建好 + 服务器升配）。

## 交付：API 调用韧性

| 调用点 | 现状 → 改动 |
|---|---|
| rerank（SiliconFlowReranker，裸 httpx） | **无重试 → 重试 2 次**（5xx/连接层错误，退避 1s/2s；4xx 不重试）。重试耗尽 → 内层重抛 → 外层既有「降级为原顺序」兜底（排序退化不打断问答） |
| embedding（langchain OpenAIEmbeddings） | SDK 隐式 2 次重试 → **显式 max_retries=3**（防止 SDK 默认变化静默退化） |
| LLM（llm_client） | 已有重试 ✔ 不动 |

## 测试（tests/test_rerank_retry.py +3）

502 重试后成功（calls=2、退避 1s）/ 4xx 不重试（calls=1，被兜底降级）/ 耗尽降级
（calls=3、退避 1s/2s、返回 None）。注意 rerank 的实际语义：内层重抛会被外层
`except Exception → return None`（降级为原顺序）接住——测试断言对齐该语义。
