# v2.0.0-p1.6b 会话一直留在列表里 + 相同问题缓存

- **版本**：`2.0.0-p1.6b`
- **日期**：2026-09-24
- **对应计划书任务**：不占新的计划格。改的是已交付行为：会话闲置不再从列表消失；模型窗口与历史记录拆开；相同问题走 Redis 精确缓存（计划书 P3-11 的一小块，近义缓存不做）。
- **上游基线**：`2.0.0-p1.6`
- **进度**：仍是 7/10。下一步仍是 P1-7 TLS。

## 1. 会话记录

闲置满 6 小时后，列表接口不再返回这条会话。再问一句时，读取被当成空会话，写入会按序号盖掉旧消息。

现在：

- 列表返回全部会话。`last_active_at` 仍在打开或新提问时更新，只表示「多久没再动」，不用来隐藏。
- `purge_expired()` 不再打归档标记，也不删行。用户点删除才删除。
- 库里的问答一轮不删。`MEMORY_MAX_TURNS=5` 只决定送进模型和问题重写的最近 5 轮。第 6 轮以前的原文还在，刷新也能看见，只是不再送进模型。
- 代词仍靠现有的问题重写，输入是这 5 轮，不再另做一次「先总结再重写」（那会多一次大模型调用）。

否掉的做法：按命中次数决定缓存去留。旧热门题会一直占着名额，新问题进不去。采用最近使用：命中或新写入排到最前，超过 100 条删最久没被用到的。命中次数只记在值里。

## 2. 相同问题缓存

键是「规范化后的原问题」。规范化只做空白、全角符号、末尾问号。知识库版本存在值里；解析成功、删除文档、重灌时版本加一并清空池子。

- 存在 Redis db0，和解析队列（db1）分开。丢了只是下次重新走模型。会话正文仍在 MySQL。
- 上限 100。命中后不走检索、不走大模型，这一轮仍写入当前会话，并标 `cache_hit`。
- 「落户如何办理？」这种完整问句，出现在已有会话里也会写入。
- 「它呢」「继续」以及短于 6 个字的问句不写入。
- 「员工如何办理居住证？」和「办理居住证的流程是什么？」不会互相当成同一题。近义缓存用户要求先停，不实现。

图上 Token 明细里的「缓存命中」是硅基流动的提示词前缀缓存，不是这份问答缓存。问答缓存命中时，不会再出现两千级 token 和数秒耗时。
