---

## 1. 背景（结论先行）

P4-5 一期把每轮轨迹落进 `chat_message.turn_meta.qa_trace`（JSON 列），解决了「刷新后回看」。但 JSON 列**没法建索引**——「近 30 天多少轮零召回？拒答的都差多少分？哪种意图最多？」这类**跨会话**问题只能全表扫 JSON，查不动。

二期补三件事（PLAN 原文）：
1. `qa_trace` 分析表 + `GET /admin/qa-traces`（decision / min_top1_gap / date 过滤）；
2. 管理端「问答溯源」页：每轮实走路径高亮 + 状态机参照图；
3. 抽 `QaFlowMachine` 把隐式分支收口成**可测决策点**。

## 2. 方案（实现了什么）

**① `core/qa_flow.py`（状态机，纯函数）**
- `QaFlowState` 12 态（4 终端：`cache_hit` / `chitchat` / `zero_recall` / `rag_qa`）；
- `resolve_decision()`：三个非缓存终端的**唯一判定处**——`query()` / `stream()` 里原来的两份三元式删掉，改调它（收口前两处必须逐字一致才不漂，收口后 module27 穷举守）；
- `flow_path()`：给定终端返回按序经过的状态列表，**溯源页的路径高亮由后端算好下发**，前端不重推分支。刻意不把 HyDE/BM25 做成状态——它们是 retrieve 节点内部的召回手段，不是分支。

**② `qa_trace` 表（迁移 0012）+ `core/qa_trace_repo.py`**
- 定位：`turn_meta.qa_trace` 的**查询优化镜像**。列 = 过滤/聚合维度 + 详情标量；`candidates` 存 JSON 只给详情渲染；不建 message/session 外键（会话与账号可被清理，轨迹留存；快照存储也不回传 message id）；
- 写入点**唯一**：`rag_chain` 三处写记忆后各镜像一次（`_record_qa_trace`，**fail-open**——镜子碎了该有的症状是「溯源页缺数据」，绝不是「用户问不了」；仓库层本身抛异常，由调用方定姿态，与 audit_repo.record 同分工）；
- `min_top1_gap` 过滤 = `threshold - top1_before_filter >= X`（JSON 列上写不出来的那行 SQL）；`describe()` 附带 `flow_path` 与 `top1_gap` 派生字段；
- 意图中文名加在 `intent_router.INTENT_LABELS`（**唯一清单**，接口随列表下发，前端不写第三份——kb_acl ACTION_LABELS 的教训）。

**③ `GET /api/v1/admin/qa-traces`（admin.py）**
- 两层守卫：`require_staff`（role 维度，进得了管理端）+ `require_kb(view_qa_traces)`（kb_role 维度，**仅 ops / superadmin**——qa/dev 是问答的消费者与生产者，看别人的会话轨迹不在其职责里）；
- `view_qa_traces` 刻意**不进** kb_acl 的 `ACTIONS` 集合（那是文档动作集，混进去会漏到文档能力面）；`capabilities()` 手挑四键，天然不受影响。

**④ 管理端「问答溯源」页（`TracesView.vue`，路由 `/traces`）**
- 筛选：终端状态 / 意图 / 会话 id / 关键词 / 日期范围 / 拒答差距下限（下拉候选全部来自服务端）；
- 列表：时间 / 状态徽章（四色）/ 意图 / 问题（带 HyDE、BM25 徽标）/ top1/阈值（拒答轮显示差多少分）/ 耗时 / 会话；
- 详情抽屉：**状态机 SVG**（12 节点固定坐标，`flow_path` 命中的节点与相邻边点亮）+ 关键指标 + 问句链（原始 → 独立 → 改写 → HyDE）+ 候选清单表。

## 4. 否掉的方案与代价

- **否掉「溯源页直接查 chat_message JSON」**：`JSON_EXTRACT` 全表扫 + 无法用索引，数据量上来后必慢；镜像表加一次写入换所有筛选查询走索引。代价：每轮多一次单行 INSERT（fail-open，1~3KB）。
- **否掉「qa_trace 表做面板数据源」**：一期已确立「面板读 turn_meta」且经 API 回吐，改成查表要多一次按 message 关联的查询，而快照存储不回传 message id——自包含镜像反而更稳。两份数据的一致性由「同一 dict 同时写入两处」保证（同一个 `_build_qa_trace` 产物）。
- **否掉「前端自己推分支画高亮」**：前端推一遍 = 分支逻辑第二份实现，漂移不报错；后端 `flow_path` 下发、前端只点亮。
- **否掉「复用 require_superadmin」**：PLAN 写明 superadmin/**ops**，溯源查看是只读分析不是系统变更，ops 档该有；用 kb_acl 新动作（单点判定）而不是路由里写 if（违反「路由层出现业务规则就是放错地方」）。

## 5. 已知边界与遗留项

- **`mysql.DOUBLE` 读回是 `Decimal`**（SQLAlchemy `asdecimal=True` 默认）：`describe()` 已在派生计算前强制转 float；API 层 FastAPI 的 jsonable_encoder 会把 Decimal 编成数字，前端无感。若后续有别的调用方直接消费 `list_traces()` 的原始行，注意这一层。
- **`top1_gap` 为负的行**（rag_qa 但 top1 低于阈值——重排后保留判据与阈值存在时序差的极端场景）照实存照实算，页面不隐藏；分析时用 `min_top1_gap >= 0` 过滤即可排除。
- **镜像表只增不删**：会话清理不级联（设计如此，轨迹留存）；若日后要按保留期清理，加 beat 任务即可，表已按 `created_at` 建索引。
- **触发条件**：需要「拒答率按意图/日期下钻」「拒答差距分布」「按会话回放整段链路」时用本页；一期面板仍服务单轮回看。

- **§3（P4-5b 期间修订）**：一期给 `_run_test()` 定的 flake 判据「只摘 exit 134」在全量回归中被当场打脸——同一 flake 换了个死相 **SIGSEGV（exit 139）**，module4 假红漏网。判据修订为「**退出码 ≥128（被信号杀死）且汇总行失败 0 项**」，四种情形重新验证通过；教训（判据按「类」定不按「例」定）补进坑 98。module18「LABELS==ACTIONS」与 module24「head==0011」两条旧断言随新动作/新迁移更新期望（断言漂移，非逻辑回归）。
