# v2.0.0-p2.12c 会话隔离（P2-12c）

> 日期：2026-10-08 · tag：`v2.0.0-p2.12c` · 前置：`v2.0.0-p2.12b`（身份与信任边界）
>
> **一句话**：让「登 A 看 A 的问答、登 B 看 B 的问答」这件事**真的成立**。
> 12b 封的是「冒充」（不能改个请求头自称别人），12c 封的才是「看到别人的」。

## 1. 范围

**做**：

- `session.user_id` 归属判据**下沉到存储层**：`load`/`save`/`delete`/`exists`/`list_ids`
  五个方法全部带 `owner_id`，且 `load`/`save`/`delete` **必填**（漏传立刻 `TypeError`）；
- 新增第 6 个契约方法 `is_foreign_to()`：让接口层能区分「不存在」（404）与「别人的」（403）；
- 三个存储实现（Memory / MySQL / Redis）**语义逐条一致**，共享契约里17 条归属断言钉死；
- 7 个会话相关路由全部挂 `Depends(current_actor)`，把 `actor.id` 当 `owner_id` 往下传；
- `/ask` 与 `/ask/stream` 在**调链路之前**做越权预检（不白花检索与 token）；
- 无主会话（`user_id IS NULL`）**认领**给第一个打开它的人；
- 新增 `tests/test_module15_session_isolation.py`（48 断言）+
  `tests/test_module15_session_isolation_reverse.py`（23 项反向验证）+
  `tests/acceptance_p2_12c.py`（真链路 32 断言）+
  `tests/acceptance_p2_12c_ui.mjs`（**浏览器验收 28 断言**）。

**不做**（本格只封「会话」，不封「知识库」）：

- **12d 文档与检索隔离**（`project` 归属 + Chroma `where` 下推）—— 下一格。
  所以此刻**所有人仍共用同一个知识库**：A 上传的文档，B 搜得到、也能删。
- 12a 角色权限矩阵、12e 越权回归总表。
- 12c 顺手把「文档能不能被越权删掉」一起做掉——那是12d 的地盘，混进来会让这一格没法单独验收。

## 3. 关键设计决策

### 3.1 `owner_id=None` 的语义：只认无主，不是「不过滤」

`owner_id` 是必填的，但类型是 `int | None`。`None` 是什么意思，有三种候选：

| 候选 | 后果 |
|------|------|
| **不过滤**（返回全部） | break-glass 身份（`actor.id is None`）能看所有人的会话，整个隔离模型有一个「靠大家记得别用」来守的例外 |
| **只认无主**（`user_id IS NULL`）← 选了这条 | 语义可解释、无后门；无主会话是「还没被人认领的」，break-glass 身份正好管这类 |
| 报错 | break-glass 身份连问一句都问不了，dev 形态直接不可用 |

**代价**：break-glass 管理员（`.env` 里的 `admin`）登进去会看到一个空列表。
这是**故意的**——它不区分用户，而隔离要求它必须区分。要看别人的会话去管理端看元数据，不要在问答里看。

### 3.2 归属判据放存储层，不放接口层

如果把 `WHERE user_id = ?` 写在 `qa.py` 的每个路由里，那么**每新增一个后端**（比如将来的
`admin.py` 要列某人的会话）就要在接口层重新写一遍归属判定，漏写一处就是一次泄漏。

放进 `SessionStore` 之后：接口层只需要把 `actor.id` 传下去，写新接口的人**想漏都漏不掉**
——`owner_id` 是必填位置参数，漏传是 `TypeError`，不是「静默返回全部」。

**代价**：`core/memory_manager.py` 与 `core/rag_chain.py` 几乎每个会话级方法都要加参数，
改动面很大（连带5 个测试文件共 113 处补参数）。这是「接口不变时业务侧零改动」的一次反例——
**零改动的前提是接口不变；接口一改，抽象层就要在调用侧补齐这个新维度。**

### 3.3 无主会话要能被认领，所以查询必须带上 `OR user_id IS NULL`

MySQL 谓词最终形态：

```python
def _owner_match(owner_id: int | None):
    if owner_id is None:
        return SESS.c.user_id.is_(None)
    return sa_or(SESS.c.user_id == owner_id, SESS.c.user_id.is_(None))
```

`OR user_id IS NULL` 这一支是**功能性的**，不是宽松处理：12c 之前建的所有会话
`user_id` 都是 NULL。如果无主会话对所有人不可见，用户第一次打开自己 12c 之前的会话时
`load` 会返回 `None`，逻辑层会「从零重建」并**覆盖掉原内容**——那不是隔离，那是删数据。

**`save()` 的三态**（在 `session_lock` 的 `FOR UPDATE` 事务内判，先判归属再写）：

| 库里状态 | 动作 |
|---------|------|
| 没有这条 | 新建，`user_id = owner_id` |
| 有且 `user_id IS NULL` | **认领**，写进 `owner_id` |
| 有且属于别人 | **抛 `SessionOwnershipError`，一个字都不写** |

不存在「写到一半才拒绝」的中间态 —— 因为归属判断和写入在同一个事务里。

### 3.4 为什么用异常而不是返回 `False`

越权时 `load` 可以返回 `None`、`save` 可以返回 `False`。但：

- 返回 `None` 与「会话不存在」**无法区分**，接口层只能二选一：要么404（把「别人的」说成「不存在」），
  要么 200+空列表（把「越权」说成「没数据」）——两个都在骗客户端；
- 返回 `False` 极易被 `if not ok: return` 吞掉，吞掉之后就是一次静默的越权；
- 异常让越权**必须**被显式处理：漏了就是 500，测试立刻红。

### 3.5 `is_foreign_to()`：第6 个契约方法，且Redis 版刻意多一条

`load`/`exists`/`list_ids` 都把「不存在」和「不属于我」压成同一个 `False`/`None` ——
**对逻辑层而言两者没区别**。但用户拍板越权要报 **403 而非 404**，于是需要额外问一次存储层：
「这条到底存不存在、是不是别人的」。这就是 `is_foreign_to()`。

它是**接口层需求驱动**出来的，三份实现都得有。文档里写明：Redis 版因为已退役、
只被 module6/7 的契约测试覆盖，容易被当成「少实现一个方法没关系」——
所以在 `core/session_store.py` 的模块文档里专门记了这一条。

### 3.6 归属不进快照

`MemorySessionStore` 的归属存**并行字典** `self._owners`，不塞进 `SessionSnapshot`。
理由：快照是**业务交换格式**，每个调用方（包括测试里的伪造快照）都有机会改写它；
归属只应由存储层在 `save` 时决定。塞进快照等于允许调用方给自己发通行证。

### 3.7 `stats()["session_count"]` 保持「全部会话数」

它是运维口径（后端要知道总共有多少会话），与「谁看得见什么」无关。
混成「当前用户的会话数」会让运维看板随登录用户变化。
要看某用户的会话数用 `list_ids(owner_id=...)`。

| 层 | 手段 | 结果 |

| 全量回归 | `make test` | 1208~1209/0（差异见 §7） |

浏览器验收的形态就是用户要亲手复现的那件事：

1. `chen.jie` 登录 → 提问 → 库里那条会话 `user_id` 确实是 chen.jie；
2. **同一个浏览器、不刷新页面**登出（走 `.logout-btn` 按钮，不是清 storage）→ 换 `zhao.min` 登录；
3. Bob 的列表接口返回**空数组**，界面上搜不到「Alice的问题」这个片段；
4. Bob 自己提问 → 库里 `user_id` 是 zhao.min，与 Alice 的是两条不同会话；
5. Bob 登出，Alice 再登回来 → 列表里仍有自己那条，且**没有 Bob 那条**。

第2 步刻意不刷新页面：只有这样才能验「Pinia 里的内存数据有没有被清掉」。
两个浏览器 context 等于两个浏览器，A 的内存与 B 完全无关，验不到任何东西。

## 5. 否掉的方案 + 代价

### 5.1 否掉：在 `qa.py` 每个路由里写 `WHERE user_id = ?`

代价：漏一处就是泄漏，且随接口增长线性增加。见 §3.2。

### 5.2 否掉：给 `owner_id` 一个「不过滤」的特殊值（如 `0` / `-1` / `"all"`）

代价：多一个取值就多一处要论证的东西。实测里最要命的是 —— 一旦存在「能看全部」的取值，
任何一次「这里是不是该用 all」的判断失误都不留痕迹，而 `None` 的语义只有一个（只认无主），
不需要判断。见 §3.1。

### 5.3 否掉：越权统一报 404（不区分「不存在」与「别人的」）

代价：用户会以为「我的会话弄丢了」，去建新会话，反而制造更多孤儿数据。
而且 404 不区分会让「拿别人的 session_id 遍历」这件事**无法被审计发现**——
403 会在网关日志里留下痕迹。见 §3.4。

### 5.4 否掉：把归属塞进 `SessionSnapshot`

代价：调用方可以自己发通行证。见 §3.6。

### 5.5 否掉：用「列表差集」推断这次提问落在哪条会话上（浏览器验收第一版）

代价：**假红，而且会传染**。实测：界面上已有当前会话时，前端**会续用那条而不是新建**，
于是「新增 0 条」，脚本判成「提问失败」，后面所有依赖 sid 的断言一起红。
最后改用响应首帧`{"type":"session","session_id":...}`（`api/routes/qa.py:317`）——
后端自己说的，不猜。

### 5.6 否掉：按按钮可见文字找「登出」按钮（浏览器验收第一版）

代价：**找不到，而红的原因看起来像「登出功能坏了」**。
实际那个按钮是纯图标 + `aria-label="退出登录"`，文字是空的。
教训：找控件要按稳定类名（`.logout-btn`）或测试属性，不要按可见文字猜。

### 5.7 否掉：把 `cleanupSessions()` 之类收尾代码顺序裸写在 `finally` 里

代价：**崩在第一步，后两步根本不会执行**。第一版就踩了：崩在 `cleanupSessions`，
于是 `restorePwd` 没跑到，`chen.jie` / `zhao.min` 的密码在库里留成了探针值。
现在收尾三步各自独立 `try`，且**收尾失败不盖掉主流程已打出的断言结果**，
但会显式报出并让退出码非 0。

### 5.8 否掉：新增 Alembic 迁移给 `session.user_id` 加索引

代价：不需要。`session.user_id` 列与 `idx_session_user_active` 索引在 **P0-1b 就已建好**，
只是一直为 NULL。当时按「会话属于某个用户」的模型建了表，结果认证晚了两格才上线。
起始时 `session` / `chat_message` 均 0 行，**无存量数据迁移负担**。

## 6. 一次「未复现的漂移」，以及它真正的成因

全量回归两遍，第一遍 module15 是 48，第二遍数出 47。因为统计只数 `[PASS]`，
所以推测「有一条 `[FAIL]` 被吞了」。

**排查过程**：单独跑 module15 共 6 次 → 全部 48/0；复现批次条件（module8 + 14 + 15）2次 → 全部 48/0；
查库确认 `session` / `chat_message` 残留 0 行。**都复现不出来，于是没下结论，只记为待办。**

**交付前的最后一轮把它解开了，成因是统计口径本身坏了**：

```
grep -cE "^\s*\[PASS\]" log   →  0        # BSD grep 下 \s 不匹配
grep -cE "^[[:space:]]*\[PASS\]" log  →  1362  # 正确写法
```

**这与坑 46 同形**（BSD/macOS `grep` 不支持 `\|` 交替，一律要用 `grep -nE "A|B"`）——
`\s` 也是 BSD grep 不认的转义。而 1362 + `test_qa_cache.py` 的 14（它用 `ok` 格式打印，
不计入 `[PASS]`，**必须单列**）= 1376，与「12b 的 1265 + module15 的 48 + module6 的 +42 +
module8 的 +21」= 1376 两条独立路径完全对上。

**所以「47」从来不是测试漂移，是我的尺子坏了。** 这条比「有个漂移」更值得记：

> **验收脚本自己会骗人，一次通过不算通过，连跑两遍才算**（既有铁律）——
> 本轮要补的是它的下半句：**统计口径本身也是被验收对象的一部分**。
> 数字对不上时，先怀疑尺子，再怀疑被测物。尤其当「差1 条」这种小差出现时：
> 小差最常见的成因是**数数的方式**（`\s` / 漏一个格式 / 漏一个模块），
> 而不是被测物的行为 —— 真漂移通常不会只差 1。

**仍未写进任何断言的遗留**：为什么第一次会用错口径？
因为统计是「手敲一条命令」，不是「脚本里的一行代码」。
**能改进的方向**（本轮未做，记为待办）：把总数统计写进 `make test` 末尾，
让 `make test` 自己报「N 通过 / 0 失败」而不是靠事后 grep 日志。
