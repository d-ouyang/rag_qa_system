## 3. 决策与代价

- **否掉**：「`GATEWAY_ALLOWED_ORIGINS` 也写成 JSON 数组」。网关 `configuration.ts:52` 用
  `.split(',')` 解析（逗号分隔），写成数组会被当**一整个字符串**——跨域全失效且**不报错**。
- **白名单提前放未建域名 `blog.nianan.site`**：零副作用（该来源不存在则永不匹配），
  换来以后上线博客时不用排查跨域；但真要对外访问仍需在 DNSPod 补 A 记录 → `42.192.111.82`。
- **个人站 `nianan.site`/`www` 进白名单**：用户计划后续在个人站挂后端服务，提前加入避免将来排查。
  初版建议是不加（当前纯静态不调 API），用户以扩展计划为由拍板加入。

## 4. 方法论沉淀

1. 🔴 **两份 CORS 白名单格式不同，写混 = 跨域全失效但不报错**：
   后端 `ALLOWED_ORIGINS` 是 JSON 数组（pydantic-settings 解析 list）；
   网关 `GATEWAY_ALLOWED_ORIGINS` 是逗号分隔（`.split(',')`）。两种格式都已写进模板注释。
2. **改 `.env` 后必须 `up -d --no-deps <service>` 重建**；`restart` 不会重新读 env_file。
3. **sed 改 `.env` 用 `|` 做分隔符**（URL 里的 `/` 免转义）；`^KEY=` 锚点不会误伤 `PREFIX_KEY=`；
   `^#\?KEY=` 可连带处理注释行。
4. **验证生效要看容器内实际值**（`settings.ALLOWED_ORIGINS` / `process.env`），不能只看 `.env` 文件。
