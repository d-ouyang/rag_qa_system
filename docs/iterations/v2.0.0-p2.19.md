## 3. 关键决策与根因

### 3.1 🔴 色差的根因是 CSS 导入顺序，不是变量没写

P2-17 已经在 `html.dark` 里对齐过 `--el-*`，但 `main.ts` 里 `main.css` 在
EP dark css-vars **之前** import —— 同特异性（同为 `html.dark` 选择器）下
后 import 的胜出，EP 的默认暗色把我们的对齐**整个覆盖回去**。
表现为 el-select 触发框是一块与页面明显不同的浅色（截图 3）。
修法：EP 变量先 import、`main.css` 后 import。验收用 computed style
断言触发框背景是深色（RGB < 80），不是「看起来差不多了」。

### 3.2 🔴 EP 对 `null` 一律显示 placeholder —— 「全部/—」改用 `''` 哨兵

`el-option :value="null"` + `v-model=null` 时界面显示 "Select"（placeholder）而不是
option 的 label —— null 在 EP 里有特殊语义（无值）。
所以所有「全部 / — / 不分配」选项的 value 改为 `''` 哨兵，
**提交时**把 `''` 转回 `null` 落库（哨兵只在界面层存在）。
这解释了截图 1/3 里的 "Select"。

### 3.3 行内表单用官方结构

按用户给的参考（`el-form :inline="true"` + `el-form-item`）改造，
宽度走官方 CSS 变量（`--el-select-width` / `--el-input-width`）而非硬编码 width。

### 3.4 改密规则提示数字**后端下发**

新增 `GET /me/password-policy`（current_actor 即可——普通员工改密也需要看规则；
`/admin/options` 的同名信息要 staff 令牌，不复用）。前端 11b 改策略时提示跟着变。
