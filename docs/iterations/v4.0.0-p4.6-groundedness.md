## 与 PLAN 的偏差

- **溯源标注简化**：PLAN 原设想「依据行可点击跳转溯源页」——一期只做「模型在答案末尾输出依据行」（prompt 第 6 条），不做点击跳转（答案文本行跳转需要前端解析模型自由文本，收益/脆性比差；候选原文查看已在 P4-7 就绪，核对路径已闭环）。
- **「不通过 → 改写答案」推迟二期**：答案已流式流出，撤回改写会造成「回答中途变脸」的诡异体验；一期只挂「依据未确认」徽标并列出未支撑论断，二期评估改写时机（生成前预检 or 非流式模式改写）。
- **低置信徽标不落库**：`low_confidence` 从 `qa_trace.top1_before_filter` 在 `describe()` 派生（top1 本来就在列上，冗余存两处必然漂移）。

## 踩坑（本轮新增）

1. **修逻辑不修入口 = 没修**（P4-7c 同款教训的实锤延续）：p4.7b 把改写重试加在模块级 `rewrite_query`，但生产 `_rewrite_question` 内联了自己的调用——今早 c860195b 会话（08:45，修复之后）事假/陪产假/婚假仍全部失败。本期已统一三处入口走单一函数。**以后任何「改了某个函数」的修复，必须先回答「生产链路走的是它吗」**。
2. **response_model 字段剥离**（P4-7b 教训复用）：历史接口新增回填字段（grounded/low_confidence）必须同步声明进 `MessageItem`，否则静默剥离。
3. **环境依赖断言**：module27 的 min_top1_gap 断言独立跑在 dev 库上时混进了真实用户的拒答轮——repo 级断言必须带会话/锚点限定。
4. 假 LLM 过 `(prompt | llm)` 管道必须用 `RunnableLambda` 包装（裸对象 TypeError）。
