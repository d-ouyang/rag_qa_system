# v2.0.0-p1.6c 流式回答可停止，上滑不再被拽回底部

- **版本**：`2.0.0-p1.6c`
- **日期**：2026-09-26
- **对应计划书任务**：不占新的计划格。改的是已有的问答流式链路。
- **上游基线**：`2.0.0-p1.6b`
- **进度**：仍是 7/10。下一步仍是 P1-7 TLS。

传输保持 `application/x-ndjson` + `fetch` + `ReadableStream`。问答必须 POST 请求体并带登录令牌，不改成浏览器原生的 EventSource。

## 1. 停止生成

`postNdjson` 本来就能接收 `AbortSignal`，页面上没有按钮把信号传进去。

- 每一轮提问新建一个 `AbortController`，传给流式请求。
- 生成过程中发送按钮变成「停止」。点下去中断这一轮。
- 已经写出来的文字留下，并补上「已停止生成」。这不当成请求失败。
- 后端在客户端断开时关掉内层生成器，模型流不再继续往下要 token。半截答案不写入会话记忆，避免残缺回答进入下一轮。刷新后这一轮不会留在历史里。

否掉的做法：改成 SSE。鉴权头和 POST 请求体都对不上原生 EventSource，强行换成 SSE 还是要回到现在这套读取方式。

## 2. 滚动跟随

新字到达时不再无条件滚到底部。人停在底部附近（约 80 像素内）才跟着走。上滑去看引用或更早的消息时，后面的字不会把画面拽回去。滚回底部附近后，跟随恢复。

没有做成「停 3 秒再自动滚回去」：人停下来读引用时，过几秒仍会被拉走。

## 3. 合并刷新与两处收尾

- 每个 token 先攒着，在下一帧动画里一次写入，减少长回答时的反复排版。
- 流结束时再解码一次，把解码器里残留的多字节吐出来。
- 后端本来就会先发 `session` 帧。前端现在会收下；若服务端会话编号和本地不一致，本地条目改成服务端的编号。

## 4. 这一版明确不做

答案仍按纯文本展示，不渲染 Markdown。富文本要处理半截语法和内容清洗，等确认需要再做。

## 5. 验证

- 前端 `vue-tsc -b` 通过。
- 关掉回答生成器时，上游流会收到关闭并停止继续产出。
- 页面上的停止按钮和上滑阅读没有在浏览器里点过。
