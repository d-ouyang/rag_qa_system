# v4.1.0-p4.2g · 空状态改为快捷问题（2026-11-23）

## 背景

新用户打开会话页，看到的是一句技术栈说明：「基于向量检索 + CrossEncoder 重排 + 多轮对话记忆。
试着问我知识库里的内容，或先到『文件传输 · 知识库』上传文档。」

这句话回答的是「这个东西怎么做的」，而用户此刻想知道的是「我能问什么」。前者对系统实现者有意义，
对第一次上手的人是噪音——尤其「CrossEncoder」这类词，除了让人怀疑自己不懂，起不到任何引导作用。
空状态恰恰是**唯一一次**能低成本教会用户「问什么粒度、能得到什么」的时机，用来贴技术栈是浪费。

## 改动

1. **删除**该提示文案与对应 `.welcome p` 样式。
2. 新增 `QUICK_ASKS`（`ChatView.vue`，6 条）：两列三行卡片，点一下即提问；卡片下方以
   「来自《文档名》」标注这条问题对应知识库里的哪份资料，让用户一眼看出「这些问题是有据可查的」。
3. 交互与边界：
   - 点击直接走 `sessions.ask(text)`，与输入框回车同一条链路（不新增提问路径，避免两套逻辑分叉）；
   - 流式生成期间卡片 `disabled`（`sessions.ask` 内部本身也有 `streaming` 防重入，双保险）；
   - 宽度 ≤720px 自动单列；卡片 hover 主色描边 + 轻微上浮，暗示可点；
   - `.welcome` 宽度 420 → 680px，为两列卡片留出空间，窄屏仍居中自适应。
4. 每条问题的首行长度控制在单行内（约 ≤21 字），避免卡片出现「孤字换行」的破版。

## 为什么是这 6 条

问题直接取自 `data/eval/kb_extras_questions.jsonl`（扩展资料 19 题评测集）——这批问句的价值在于
**已经验证过能在知识库里召回并答对**，不会出现「点了卡片却被拒答」的尴尬（空状态的示例一旦查不到，
用户对系统的信任在第一次点击就没了）。

覆盖面按两个维度铺开：

| 维度 | 覆盖 |
|------|------|
| 载体 | PDF 制度（客户投诉、门店选址）/ DOCX 细则（供应商、信息安全）/ XLSX 台账（巡检评分表、培训计划） |
| 问法 | 条款分档（投诉分级 + 时限）、指标权重、清单内容、分类分级、数值区间、表格汇总统计 |

## 验证

- 前端 `npm run build`（`vue-tsc -b && vite build`）通过。
- **本地真链路**（vite dev 5173 → 网关 3000 → FastAPI 8000 → 本地 MySQL/Chroma 容器）用无头浏览器
  实跑，未用静态复刻页代替：
  - 空状态渲染 6 张卡片，`document.body.innerText` 断言原提示中的「CrossEncoder 重排」已不存在；
  - 点击首卡「客户投诉分几级？各级处理时限是多久？」→ 会话标题自动改为该问题、用户气泡出现、
    顶部显示「已检索知识库 · 政策咨询」、答案给出四级投诉及 2 小时/24 小时、1 小时/3 个工作日、
    30 分钟/7 个工作日的时限，引用资料 5 条（1 个文件）——证明快捷问题不是摆设。
- `make golden-gate` 对照基线（recall@5 0.9389 / hit@5 1.0 / mrr@10 0.8889 / abstain 1.0）通过。
  本次为纯展示层改动，零检索/切分/Prompt/模型改动，指标按定义不可能变化；跑一次是为了留痕。

- 回滚：还原该文件并重新部署即可，无数据副作用。
