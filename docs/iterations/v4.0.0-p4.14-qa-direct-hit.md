# v4.0.0-p4.14 — QA 问答集直击（优化 2 一期）

日期：2026-10-29　|　分支：develop　|　tag：v4.0.0-p4.14（待打）

## 背景

PLAN-v4.0.0「优化日程」优化 2：制度类知识库提问高度收敛，Top 问题（考勤/请假/报销/薪酬）
可离线策划成标准问答；用户问题直接命中 QA 集时直接返回标准答案——跳过改写、检索、
生成全程，**一次大模型调用都没有**，延迟与幻觉风险同时归零。p4.13 已完成素材入库
（`data/qa/kb_qa_set.jsonl` 48 条），本期实现整条链路。

## 实现

1. **`core/qa_direct.py`（新模块）**：
   - `QaEntry` / `load_qa_entries()`：JSONL 加载，单行损坏跳过、缺 question/answer 抛文件级错误；
   - `QaDirectIndex` 两级匹配：① 精确层——复用 `qa_cache.normalize_question` 口径，
     扫 question + alt_questions（零成本零误击）；② 语义层——精确未中才算，
     query 与全部条目问句余弦相似度 ≥ `SEMANTIC_THRESHOLD=0.92` 才命中（golden 校准，
     宁缺毋滥，不做模糊检索排序）；嵌入器可注入（LangChain Embeddings 接口，测试打桩）；
   - `try_qa_direct_hit()` 对外唯一入口，门控顺序：热开关（缺省关 fail-closed）→
     独立问句门控 `is_standalone_question`（「那婚假呢」不直击，须过改写层）→ 精确 → 语义；
   - **fail-open 边界**：文件缺失/损坏、嵌入失败一律返回 None 落回正常链路只留 WARNING
     ——直击是优化路径，不能变成新故障点。索引单例惰性构建，坏文件只报一次。
2. **`core/qa_flow.py`**：新增 `qa_lookup` 节点与 `qa_hit` 终端态（TERMINAL_STATES 五个、
   STATE_LABELS、flow_path 同步），`qa_hit` 路径 = received → cache_check → qa_lookup → qa_hit。
3. **`core/rag_chain.py` query()/stream() 双路接线**：缓存未命中后、`_prepare_parallel` 之前
   调 `try_qa_direct_hit`；命中轮合成 `IntentResult(source="qa_set", route="rag_qa")`，
   answer 直接用标准答案，usage 全零，decision 钉死 `qa_hit`（绕过 resolve_decision 的
   prepared=None 误判），轨迹附加 `qa_id / qa_match_via / qa_match_score`，
   溯源列表用 `_qa_hit_sources()`（qa_id 代替 chunk_id，语义上「来自 QA 集而非检索切片」）。
4. **热开关 `qa_direct_hit`**（FLAG_REGISTRY 第 11 项，卡片「问答增强」，缺省 False）。
5. **前端**：`ChatView.vue` 头部角标新增「QA 直击 · 未调大模型」态；
   admin-console `TracesView.vue` 流程图加 qa_lookup/qa_hit 节点（viewBox 860→962）、
   决策下拉自动随 STATE_LABELS 扩到五项、徽章色 `d-qa` 青色。
6. **测试 `test_module29_qa_direct.py`（30 断言全绿）**：文件契约（48 条）、精确层
   （标准/变体/alt/未收录）、语义层（打桩受控向量空间：高分命中/正交不命中/阈值语义/
   嵌入失败 fail-open）、门控（开关关/指代句/过短句）、端到端（**命中轮 LLM 与检索器
   用「触碰即炸」桩证明零调用**，decision=qa_hit 落库、describe 派生 flow_path、
   流式帧序 meta→chunk→done；未命中回落 rag_qa / zero_recall 无回归）。
