## 3. 决策与代价（否掉的方案）

- **否掉「轻量控制台挂载存储桶」**：那是 FUSE 网盘方案，脚本走 API 上传链路可控、可验收，不需要挂载。
- **否掉「服务器数据归档」（轻量自带 tar 助手）**：黑盒、无 SLA 声明，与自有脚本功能重复。
- **🔴 否掉「默认内网 endpoint」**：实测这台轻量解析不了 `*.internal.tencentcos.com`
  （`no such host`，重试 6 次全败）。改默认**公网**——COS 只收「外网**下行**」流量，
  **上传（写入）永远免费**，每日几十 MB 走公网成本为 0；`--internal` 参数留作后续切换。
- **redis_data 不备**：AOF 非强持久，任务真相在 MySQL `document.status`（P1-5 定调）；
  models 不备：可重新下载，约 2GB 纯占空间。
- **保留策略放 COS 生命周期规则（云端自动删）而不是脚本删**：脚本没跑、密钥换了都不影响旧备份。

## 4. 踩坑实录（这一格的坑密度意外地高，全部实测）

1. **coscli 下载 404**：`releases/latest/download/<名>` 需要精确资产名，
   而资产名**带版本号**（`coscli-v1.0.9-linux-amd64`）→ 只能固定 tag 下载。
   服务器直连 GitHub 不稳 → Mac（挂代理）下载 + scp。
2. **coscli 首次运行强制交互**（`config init` 向导），脚本内首次调用直接卡死
   → 必须先 `sudo coscli config init` 人工走完一遍向导（含 Mode 回车、
   Session Token 回车、桶名/endpoint）。
3. **🔴 `-r` 是 `--recursive` 不是 region**：`cp ... -r ap-shanghai` 把
   `ap-shanghai` 当位置参数 → 报错 → `set -e` 静默终止（`>/dev/null` 吞掉了
   输出），表现是 `[3/3]` 后无声退场。官方文档实锤后改为
   `-e <endpoint> -i <id> -k <key> --init-skip=true`。
4. **flock 防重叠首战立功**：交互卡死的残留进程持锁，第二轮启动被正确拒绝
   （`上一轮备份仍在跑`），验证了机制有效；清理用 `pkill -f backup_to_cos.sh`。
5. **CAM 策略两处写错**：action 必须带 `name/` 前缀（`name/cos:PutObject`）；
   列举对象的 action 是 **`cos:GetBucket`** 不叫 ListBucket——策略分析器
   当场报「无效的 action」才暴露。
6. **控制台迷宫**：轻量「对象存储」tab ≠ COS 控制台；桶详情（文件列表）在
   轻量菜单的「对象存储」里，生命周期规则只能在 COS 控制台配。
7. **诊断手法沉淀**：脚本静默退出时，用**单文件最小复现**（`echo test >
   /tmp/cos-test.txt` 手动 cp）把 `>/dev/null` 吞掉的错误逼出来——先内网
   后公网两次对照，一次定位 DNS 问题。
