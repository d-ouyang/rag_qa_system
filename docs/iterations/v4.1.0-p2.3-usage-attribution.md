- **qa_trace 加 usage 三列镜像**（迁移 0014）：usage_input_tokens / usage_output_tokens /
  usage_cache_read_tokens（NULL=老数据）；
- **qa_trace.id 自成 query_id**：一行轨迹 = 谁（owner_id）+ 哪个会话（session_id）+
  什么流程（decision/intent/route）+ 多少 token（usage 三列）——归因四要素全量；
- **接线**：_record_qa_trace 三个调用点（rag_qa 主链路 / 流式 / 缓存命中轮）把当轮
  exchange_meta["usage"]（_extract_usage 产物）塞进 trace dict，经 _TRACE_KEYS
  透传入表（缓存命中轮 0 token 也落——0 与 NULL 语义不同）；
- **tenant**：RAG 单租户不建模（恒定维度，文档记录）。

## 设计拍板

1. **usage 镜像而非 message_id 关联**：token 真相源在 chat_message（累计列），
   但 add_exchange 返回 None（消息 id 不上抛）——改存储层三处实现侵入面大；
   镜像进分析表让查询不用 join、归因自包含（"第二本账"风险由口径同源缓解：
   两处都来自同一 usage dict）。
2. **迁移 0014**（对齐 0012/0013 的 qa_trace 演进惯例），列注释与 schema.py 逐字
   相同（compare_metadata 守着）。
