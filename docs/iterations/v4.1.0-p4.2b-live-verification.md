## 真链路抓出的三个真缺陷（纯测试盲区，均已修复）

1. **admin.py audit 投影 500**：`dict(r._mapping)` 多余取值——`.mappings().all()` 返回的
   RowMapping 本身就是 dict 型，再取 `._mapping` 抛 AttributeError → 修复为 `dict(r)`；
2. **gateway shouldCheck 路径误写**：照搬了 office 的 `/api/v1/ask`，rag 实际是
   **`/api/v1/qa/ask`**（qa router 前缀）——判定永不触发，**quota 网关短路形同虚设**；
   判定测试断言同步修正；
3. **compose gateway 缺 `MYSQL_HOST=mysql`**：QuotaService（p2.1 新增的 mysql 依赖）
   读 .env 的 localhost → 容器内连自己 → 查库失败**静默 fail-open 放行**（error 日志
   是唯一线索）。backend 早有此覆盖、gateway 是新依赖漏配。

**经验**：单元测试全绿 ≠ 真链路能跑——三处缺陷全部是"生产配置/运行时形态"类，
只有起栈真跑（登录→真问→查库→调端点）才暴露。真链路验证从此是部署前必做步骤。
