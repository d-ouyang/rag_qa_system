## 1. 这一版做了什么（一句话）

管理端引入 **Element Plus（按需导入）**，15 处自研下拉全部替换为 `el-select`，
筛选区改横向排布，**所有列表页统一「列表滚动、分页固定页底」**，
员工列表上真分页、密码看板加「全部人员」视图；
问答端个人信息面板里可以**自助修改密码**（走 11b 全套策略）；
**每轮测试跑完自动恢复固定密码并打印可登录账号表**。

**组件库答复（用户问「选了什么组件库」）：Element Plus 4.x？—— 确切说 `element-plus@2.x`，
按需导入走 `unplugin-vue-components` + `ElementPlusResolver` +
`unplugin-auto-import`（函数式 API），**没有全量引入**——只打包模板里实际用到的组件
（构建产物里 `el-select` / `el-pagination` 各自独立 chunk）。暗色主题用它的
`dark/css-vars.css` + `html.dark`，并把它的 CSS 变量对齐到项目现有色板。

## 3. 关键设计决策

### 3.1 组件库：Element Plus 按需导入 —— 「自绘」与「成熟」的分界线

上一版自绘 AppSelect 解决了箭头与遮挡，但用户指出**筛选区每个下拉独占一行**（宽度失控），
并点名「用成熟的组件库，按需导入」。自绘控件的边界在这里：单控件的行为可以根治，
**布局生态**（宽度体系、表单校验、键盘导航的一致性）靠一个 200 行的自研组件补不完。

选型：**Element Plus**（Vue 3 生态最成熟、暗色支持最好、按需导入方案官方维护）。
按需导入配置（`vite.config.ts`）+ 暗色变量对齐（`main.css` 的 `html.dark` 块）。

### 3.2 「列表滚动、分页固定页底」是一条**规则**而不是三处样式

用户原话：「所有的分页和列表都要遵循这个 UI 规则」—— 所以做成 `.list-page`
一个公共类（flex 列 + `table-wrap flex:1 overflow:auto` + pager 固定），
四个列表页套同一个类；以后新列表页也套它，规则不会散落。

### 3.3 🔴 「全部人员」≠ 五桶并集 —— 并集会把健康的人漏掉

第一版把「全部人员」做成五桶并集去重，实测 9 个在职只显示 6 人 ——
**密码状态健康的人不在任何桶里**。修正：后端 `PasswordBoard` 直接下发
`all_people`（全部在职，不筛桶），前端用它渲染。
「并集」这个看似聪明的方案被实测数字否掉（9 ≠ 6），记入文档。

### 3.4 过期用户放行自助改密 —— 11b 那扇门

`policy.verify` 对过期密码返回 `expired`（登录路径拦下），
而自助改密路径**必须接受它**——用户正是过期才来改密的。
这正是 11b 原文「到期后只放行『改密』与『登出』」的那扇门；
改密成功后 `update_password` 自带 `token_version+1`，旧 token 全失效。

### 3.5 🔴 测试跑完账号不再「悬空」（用户第 4 条）

现状：多个测试会把账号密码换成随机临时值（各自的合法还原方式），
于是「跑完测试 → 想手动看看」之间隔着一个「账号登不进」的坑。
修法：module16 收尾**无条件**（哪怕有 FAIL）执行 `dev_test_accounts.py --apply`
把三个测试账号的密码设回固定值，并**打印账号表**：

```
│ chen.jie │ DevTest2026!Aa  │ 主应用 http://localhost:5173 │
│ zhao.min │ DevTest2026!Bb  │ 主应用 http://localhost:5173 │
│ wu.jing  │ DevAdmin2026!Aa │ 管理端 http://localhost:5174（也可登 5173）│
```

只对测试账号生效；真实员工（离职/停用）不归它管。

## 5. 已知边界

1. 员工页真分页每页 20 条 —— 页大小暂不可调（人多了再说）。
2. 「全部人员」的密码状态列在 el-table 里未做桶标 —— 当前只列人；需要状态列时在行内补 badge。
3. Playwright 浏览器进程存活时 `execFileSync` 调 Python 会静默挂起
   （单独跑 1.4s、浏览器开着 120s 不够，原因未定位）——
   验收脚本的清理改走 HTTP 链路，不再从浏览器进程里 spawn python（记入踩坑 96）。
