## 3. 关键设计决策

### 3.1 底部锚定 popover 而不是居中 Modal

WorkBuddy 的交互（用户给的参考截图）是「点左下角 → 面板从那里向上展开」——
用户心智里这是**菜单**，不是对话框。定位用 `fixed; left:10px; bottom:74px`
（侧边栏内边距 + 用户区高度），宽度跟随 `--sidebar-width`。
遮罩是**透明的**（点击空白关闭）—— 轻量弹出不需要暗遮罩压暗整个页面。

### 3.2 「系统设置 / 文件传输」移进面板 = 收拢侧边栏

这两个入口原本是侧边栏上的两个按钮（16a 之前就有）。移进面板后：
侧边栏更聚焦（会话列表 + 知识库入口高频，设置/传输低频），
且与 WorkBuddy 的信息架构一致 —— 低频功能收进个人菜单。
⚠️ 侧边栏本体没删导航按钮（若需要回退只改 AppSidebar）。

### 3.3 🔴 实时校验是「UX 预检」，不是判据第二份

新密码输入时逐条显示 11b 规则是否满足（✓/○）：
长度 ≥ min_length（参数从 `/qa/me/password-policy` 下发）、
至少两类字符、不含登录名、两次一致。
**判定的唯一出处仍是后端 `password_policy`**（提交时后端完整再验）——
「同一套判据只写一处」指的是**判定生效处**；登录/改密表单的即时反馈
与它不冲突（与本仓库历史教训的区别：教训针对的是「判定生效处写了两份」）。
提交按钮在全部规则满足前 disabled。

### 3.4 示例密码只演示「形状」

规则提示给出示例 `Xk9#mQ2vLp`（10 位 + 四类字符齐全），
并**当场注明「仅演示形状，请勿直接使用」**——
示例密码写在页面上，谁都能看到；真把它当密码用等于把密码贴在门上。

## 5. 已知边界

1. 面板宽跟随 `--sidebar-width`——移动端（侧边栏折叠）未适配（管理后台无移动端场景）。
2. 实时校验的四条是 UX 预检；后端 `validate_strength` 还会校验「不含工号」等
   前端未展示的规则（那些由提交时的后端错误文案兜底）。
3. 示例密码 `Xk9#mQ2vLp` 是页面上的静态文本——若用户真用它，后端历史策略
   会拦（它与示例同形的任意密码不构成规则冲突，但建议用户自造）。
