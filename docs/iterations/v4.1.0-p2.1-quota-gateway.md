# v4.1.0-p2.1 · quota 判定外移 NestJS 网关（Phase ②1）

> 2026-11-16 · 分支 `feature/4.1.0-contract` · gateway 判定测试 11/11 + tsc 0 错 + FastAPI 回归（qa_cache 14 / shared_gateway_trust 7 / 工具契约检查）全过

## 完成判据回填

**「绕过业务 quota 函数的调用不存在；超限 429 在网关短路」→ 达成**：
- 网关新增 `gateway/src/quota/`（QuotaService + QuotaModule）：判定在
  proxy 转发**之前**执行（decidePath 之后——越权的人先 403，不为他查用量）；
  拦 POST /api/v1/ask 与 /ask/stream 两入口；429 错误体形状与原 FastAPI 版
  逐字段一致（前端无感知）；
- **FastAPI 侧删除 `_quota_precheck` 及两个调用点**（/ask 与 /ask/stream）——
  /quota/me 查余额保留（管理端横幅）；业务代码不再有 quota 判定。

## 口径镜像（quota_policy/quota_repo 的 TS 逐字翻译）

can_ask（≤0 不限 / used<quota 放行 / 否则 BLOCK_MESSAGE，**不做单轮预估**——
宽限单语义）、billable（input+output，不含 cache_read）、effective_quota
（覆盖值>0 生效否则全局默认）、usage_by_user 的 CTE 两段聚合 SQL、
period_bounds 左闭右开账期（⚠️ 上游语义照搬：当月 startDay 未到时区间指向
未来 → 0 用量放行——将来改上游两边一起改）。

## 设计拍板

1. **失败语义 fail-open**（与鉴权 fail-closed 刻意不同）：quota 是成本护栏不是
   安全门，DB 抖动放行 + error 日志；写在 service 头注释，改动需过脑。
2. **判定放 handler 内而非 Nest Guard**：与 decidePath 同位置同形态，少一层
   抽象；block 档开关在 shouldCheck 短路。
3. **不可归属身份（uid=null，break-glass/旧 token）放行**：与原 Python 口径
   attributable=False 一致。
4. **SQL 直查网关**（mysql2 pool，4 连接）：判定数据面在网关，避免"网关调
   FastAPI 判定"的回环（那会让 FastAPI 仍是事实收口点）。
