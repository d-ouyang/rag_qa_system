# v2.0.0-p1.6 模型全部走硅基流动 + 知识库列表分页

- **版本**：`2.0.0-p1.6`
- **日期**：2026-09-24
- **对应计划书任务**：P1-6。原计划是「服务器放一份真实 models 目录」。用户改为：**不在本机加载、不部署模型，嵌入 / 重排 / 对话 / 意图都走硅基流动。**
- **上游基线**：`2.0.0-p1.5c`

## 1. 模型怎么改的

| 环节 | 运行路径 | 模型 |
|------|----------|------|
| 对话 | 本来就是硅基流动 | `.env` 里的 `SILICONFLOW_MODEL_NAME` |
| 意图 | `INTENT_LLM_PROVIDER=siliconflow`，失败仍降级成本地规则 | 同上 |
| 嵌入 | `EMBEDDING_BACKEND=siliconflow`，OpenAI 兼容 `/embeddings`，结果再做一次 L2 归一化 | `BAAI/bge-large-zh-v1.5`（1024 维） |
| 重排 | `RERANK_BACKEND=siliconflow`，`POST /rerank`，不加载本地 CrossEncoder | `BAAI/bge-reranker-v2-m3` |

`make test` 强制 `EMBEDDING_BACKEND=local` 和 `RERANK_BACKEND=local`，回归测试继续用本机 `models/`，不打硅基流动、也不改向量维度。

本地加载代码还留着，只是运行路径不走它。`models/` 软链不再是上线前提。

## 2. 必须重灌

嵌入从本地 `bge-small-zh`（512 维）换成 `bge-large-zh-v1.5`（1024 维）。同一个 collection 不能混两种维度。

已删除 chroma 里的 `rag_qa_knowledge`，再 `make reindex-apply`：24 篇成功，106 个切片。问答「员工入职要填什么表」返回 `rag_qa`，引用 5 条。

## 3. 知识库列表分页

列表超出视口却滚不动，是因为外层 `overflow: hidden`，而知识库页作为 flex 子项没有 `min-height: 0`，高度被内容撑破后被裁掉。

- 补上 `min-height: 0`，页面本身可以滚。
- 表格按每页 10 条分页（上一页 / 下一页）。轮询仍一次拉最多 1000 条，完成提示不会因为翻页丢掉。

## 4. 已知边界

- 嵌入和重排每次请求都走公网，解析和问答比本地模型多一次网络往返，也会计入硅基流动用量。
- 全栈镜像里仍然挂着 `./models`，运行路径已经不读它。下次改 compose 时可以摘掉。
- 知识库页分页没有在浏览器里点过（当前环境没有页面自动化）。开发服 `http://127.0.0.1:5173` 打开知识库即可看到底部分页。
