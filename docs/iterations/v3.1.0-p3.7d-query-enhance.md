## 1. 背景（结论先行）

- **D 的核心（多轮指代改写）此前已在 `core/rag_chain.py` 落地**（`_contextualize_q_prompt` + `_rewrite_question`，随 `_PIPELINE_EXECUTOR` 与意图/检索并行，延迟被隐藏）。本轮只补「单轮也过一次改写」+「HyDE」两块。
- 实现：复用主答模型（Qwen/Qwen2.5-7B-Instruct via siliconflow）做单轮改写（`QUERY_REWRITE` 开关）+ 可选 HyDE（`QUERY_HYDE` 开关，用假设答案 embedding 做向量召回，BM25 仍用真实问句关键词）；两者默认 `False`。
- **A/B（受限于本沙箱 siliconflow reranker 挂死，只能跑 reranker-off，见 §3）**：golden 集 7 条口语改写题（q019–q025）用 raw query 已 `hit@5=1.0`（相关切片都找得到），改写后 `recall@5/10` 与基线**逐位一致**（0.8571 / 0.9286）——即改写**没有把任何新的相关切片带进候选池**。
- 结论：**翻默认无 recall 收益**（每问还白多一次 LLM 调用），保持双关。`recall` 结论 reranker 无关、稳健；reranker 依赖的 `mrr@10` 在本环境无法测，留待 reranker 可达时复跑。

## 2. 方案（实现了什么）

```
retriever.retrieve(query, top_k)
   ├─ embed_query = vector_query if vector_query else query   # HyDE 只换向量 embedding 文本
   └─ BM25 仍用真实 query（关键词不污染）

_prepare_parallel（rag_chain）
   should_rewrite = bool(chat_history) or QUERY_REWRITE or QUERY_HYDE
   ├─ 历史 / 开关 关  → 直接用原句（行为逐字节不变）
   └─ 开             → standalone = rewrite_query(q, history)
                      if QUERY_HYDE: vector_query = generate_hypo_answer(standalone)
                      docs = retriever.retrieve(standalone, vector_query=vector_query)
   # 改写与意图/检索在 _PIPELINE_EXECUTOR 并行，延迟被隐藏
```

- `config/settings.py`：`QUERY_REWRITE: bool = False`、`QUERY_HYDE: bool = False`（注释写清「多轮指代改写与此开关无关、始终生效」）。
- `core/rag_chain.py`：`_HYDE_SYSTEM_PROMPT`；纯函数 `rewrite_query(question, chat_history)`（复用 `_contextualize_q_prompt` + `get_llm_client().get_llm()`，sanitize 兜底空输出回退原句）、`generate_hypo_answer(question)`（只输出假设答案文本，空输出回退原句）；`_prepare_parallel` 改写/HyDE 分支；debug 帧新增 `vector_query`（关时 `null`，对齐 `bm25_hits=null` 约定）。
- `core/retriever.py`：`retrieve()` 增 `vector_query: str | None = None`；`embed_query = vector_query if vector_query else query`；hybrid 分支 BM25 仍用真实 `query`。`as_retriever()` 语义不变（`k` 默认 `self.top_k`）。
- `scripts/eval_retrieval.py`：`--enhance` / `--hyde` 受控实验变量；`evaluate_case(enhance, hyde)` 改写后用 `retriever.retrieve(query, top_k=k, vector_query=...)`；结果记 `enhanced_query`。
- `tests/test_module23_query_enhance.py`（新，14 项，无基础设施依赖：FakeLLM/FakeRetriever/FakeVS/FakeClassifier）；`tests/test_module19_eval.py` 更新 2 条源码级不变量断言（56/0 默认、60/0 `--reverse`）；`scripts/test_sandbox.sh` 注册 module23。

## 3. 验证（单测 + A/B 评测）

- `py_compile` 四个改动文件全过。
- **单测**：module23 **14/0**（三分支：无增强/无历史→不改写；QUERY_REWRITE 开→改写并重新检索；QUERY_HYDE 开→vector_query 透传）；module19 **56/0**（默认）/ **60/0**（`--reverse`）。
- **A/B（`RETRIEVAL_HYBRID=false`，reranker 本沙箱挂死故 `USE_RERANKER=false`，仅测召回维度）**，7 条口语题：

| 指标 | baseline（原句） | enhance（改写） | hyde（改写+HyDE） |
|---|---|---|---|
| recall@5 | 0.8571 | 0.8571 | 0.8571 |
| recall@10 | 0.9286 | 0.9286 | 0.9286 |
| hit@5 | 1.0000 | 1.0000 | 1.0000 |
| mrr@10* | 0.7500 | 0.8214 | 0.7786 |

（*mrr@10 在 reranker-off 下只是向量+BM25 相似度排序，**不代表线上 reranker 排序**，弱证据，仅作方向参考。）

- **关键判读**：`hit@5=1.0` 说明 7 题 raw query 都已找回相关切片；改写后 `recall` 逐位不变 = 没带进任何新相关切片。即 Option 1 预设的「改写直接命中这 7 条口语题」**未被证据支持**——这些题本来就能答对。
- **环境限制（重要）**：siliconflow `bge-reranker-v2-m3` 调用在本沙箱**挂死**（单问 k=5 直连也 >55s 无 SIGTERM，embedding 同环境正常），故无法跑 reranker-on 的线上口径 A/B。这是沙箱↔硅基流动网络的偶发问题，非代码缺陷。reranker-off 的 `recall` 结论与 reranker 无关，稳健。

## 4. 否掉的方案与代价

- **默认开启 `QUERY_REWRITE`**：否决。A/B 显示 recall 无增益，且每问多一次 LLM 调用（延迟 + 成本），违背「收益由评测说话、未达标保持关」铁律（同 `RETRIEVAL_HYBRID`）。
- **HyDE 作默认**：否决。`mrr@10`(0.7786) 反而低于纯改写(0.8214)，且假设答案若有漂移（与知识库文风不符）会带偏 embedding；留作可选开关。
- **为改写单起更强模型**：否决。用户要求与主答模型一致；并行管线已把改写延迟藏起来，无必要加依赖/成本。
- **让 BM25 也用改写后的 query**：否决。口语词往往就是关键词，BM25 必须保留真实问句；HyDE 只替换向量 embedding 文本，不污染 BM25。
- **为「修」召回去动切分参数**：不相关，D 是检索前增强、不动 chunk 形态，故不触发整库重建。

## 5. 遗留与触发条件（何时翻默认）

- **翻 `QUERY_REWRITE=True` 的硬条件**：在 reranker 可达的环境（服务器或硅基流动 reranker 不挂）跑
  `RETRIEVAL_HYBRID=false .venv/bin/python scripts/eval_retrieval.py --category paraphrase --k 5,10 --enhance --tag enhance`
  对比 `--tag baseline`，**`recall@5` / `mrr@10` 较基线有可量化提升且拒答不降**才翻。当前证据（recall 不变）不支持翻。
- **复跑前确认 reranker 可达**：本沙箱挂死是网络偶发，上线环境需先验证 reranker 连通，否则 A/B 结论不可信。
- `QUERY_HYDE` 维持默认关：除非未来证明其对特定题（如跨文档综合类）有增益，再单独评估。
