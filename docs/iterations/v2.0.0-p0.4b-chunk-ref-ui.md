## 3. 关键设计决策

### 3.1 行内展开，而不是弹窗或抽屉

知识库页的「片段抽屉」是另一个场景（一次看一份文档的全部切片），
这里的场景是**在对话流里临时看一眼**：引用条本身很窄，弹窗会盖住上下文。

所以做成行内展开区，并且**一次只展开一条**：
同时展开三五条会把对话挤得读不下去，而用户一次也只读一条。

### 3.2 有 `chunk_id` 才是按钮，没有键的渲染成纯文本 + tooltip

后端契约里 `chunk_id` 为 `null` 表示「P0-3 之前的遗留切片，连文档编号都没有，
**本来就无法反查**」。前端对这个值的处理只有一种正确做法：
**不给按钮**，渲染成普通文本，并在 tooltip 里说明「这条引用没有可反查的编号」。

反过来（退化成拿 `source` 路径去查）是最糟的：用户会以为「有键可查」，
点下去必然失败 —— 一个点了就报错的按钮，比没有按钮更让人恼火。

验收里专门验了这件事：可点条数 + 不可点条数 = 引用总条数，**不存在第三种状态**。

### 3.3 前端先校验格式再发请求，且**不用** `encodeURIComponent`

`chunk_id` 的形状由后端契约固定为 `<数字>:<数字>`。前端拼 URL 前先过一遍正则，
两个理由：

1. 非法串拼进路径可能打到别的路由上，发之前拦掉比指望网关拦更可靠；
2. 校验失败就能直接给用户一句人话，不用等一个 400 回来再翻译一遍。

**为什么不用 `encodeURIComponent` 包一层**：它会把冒号变成 `%3A`，
而中间那层代理有可能再编码一次变成 `%253A`，把本来能过的请求搞坏 ——
冒号在 URL 路径段里本来就是合法字符（`p0.4a` 验收里实测过「冒号路径能穿过网关」）。
改成「先校验、合法才拼」，既挡住非法输入，又不需要编码。

### 3.4 缓存要连「失败」一起缓存

按 `chunk_id` 存结果看起来只是省一次请求，但真正要紧的是后半句：
**取失败的也要记住**。否则用户关掉再点开，会看到一次假的「正在取回…」，
然后又弹同一个错 —— 看起来像网络在抽风，其实是前端自己忘了。

这一条在验收里是靠「请求计数不增长」验的（第二次展开不再打接口）。

### 3.5 错误文案原样采用后端给的，前端不重写

后端已经把四种情况分成四类，其中两类失败文案是写给人看的
（「引用内容已随文档删除」/「引用片段已失效，请刷新后重试」）。
前端**照原样展示**：重写一次就多一处与后端对不上的风险，
而且后端改口径时前端永远慢半拍。

验收里断言的是「界面上的文案**等于**后端那句」，而不是「包含某个关键词」——
这样后端改文案时前端会立刻红，而不是悄悄显示旧话。

### 3.6 `qa.ts` 里的内联 `sources` 类型换成 `SourceItem`

原来 `askSync` 的返回类型里把 sources 的字段又抄了一遍。
抄一份就多一处漂移点：后端给 sources 加字段时，只有一处会记得改 ——
这正是 `p0.4a` 踩的那个坑（`response_model` 静默丢字段）在前端的孪生版本。
改成直接复用 `SourceItem`，让「引用长什么样」只有一份定义。

### 3.7 验收里那一处桩：为什么必须用桩，以及为什么要挑一条没展开过的引用

「文档已被删除」这个分支需要真的删掉一份文档，而删掉之后**这条引用就再也检索不到了**
—— 场景无法用真链路复现。所以用 `page.route` 把反查请求改成 404 + 后端真实的错误体，
只验前端渲染分支；后端「确实返回这个 404 与这句文案」由 `p0.4a` 的验收覆盖。

第一版跑的时候这组**假失败**了，根因值得记下来：
**它挑了一条已经被展开过的引用**，而展开过的结果已经进了组件内的缓存，
再点不会发请求 —— 桩永远拦不到，那一组实际上是在验缓存，不是在验错误分支。
改法是显式挑一条没展开过的引用（脚本里用 `usedIdx` 记录，代码注释写明了原因）。

顺带把 `page.route` 的 glob 换成了 predicate 函数：glob 匹配带冒号的 URL 不保险。

### 3.8 `document_exists=false` 时照常展示正文，只加一个标记

切片在、MySQL 记录没了（脏数据）时后端仍返回 200 并把 `document_exists` 置 false。
前端的处理和后端一致：**正文照常展示**（内容确实还在，不该给用户报错），
只在元信息里加一个「文档记录缺失」的红字标记 —— 那是给运维的信号：该跑重建脚本了。

## 6. 已知边界与遗留项

1. **缓存是组件实例级的**：刷新页面（或切换会话再切回来）后同一条引用会重新取一次。
   做成全局缓存需要在 store 里维护一份，并额外处理「文档被删了缓存要不要失效」——
   收益（省一次小请求）不抵复杂度，暂不做。
2. **遗留切片永远点不开**：`chunk_id` 为 `null` 的老切片只能显示摘要。
   跑一次 `make reindex-apply` 重建之后它们就有键了 —— 这是 `p0.4a` 那个脚本存在的理由之一。
3. **一次只展开一条**是刻意设计（§3.1），不是限制。
4. **不做「打开源文档原文」**：前端没有 PDF/Word 渲染能力；知识库页有原文件下载，
   真要核对原件走那条路。
5. **`module9` 的清理仍是全表清空**（`p0.4a` 已列为遗留项）：跑 `make test` 会清空
   `document` 表 —— 跑完想要回演示数据，执行一次 `make reindex-apply`。
