# 迭代总结 · v4.0.0-p4.11 — 信任共享办公网关注入身份（additive 信任 + fail-closed）

> Tag：`v4.0.0-p4.11`。跨服务：对应 office 仓《共享网关迁移设计》（认证放 B：自建共享网关）。
> **只推 develop + tag，不合并 main → 不触发部署 → 线上零影响。**

## 1. 目标
让 RAG 后端信任「共享办公网关」转发来的身份（多服务共用一套 API 网关的场景），作为现有
「只信 RAG 自己网关」的**增量**，且不放松 fail-closed。

## 2. 做了什么
- `config/settings.py`：新增 `OFFICE_GATEWAY_SHARED_SECRET`（共享办公网关的网关证明密钥；
  留空=不信任；可独立轮换；仅 gateway 模式生效）。
- `core/identity.py` `verify_gateway_proof`：可接受的证明从「一把」扩为「**RAG 自己网关密钥
  或办公网关密钥**」两把（均 `hmac.compare_digest`）；**一把都没配 / 不匹配 / 缺头 → 一律 401**。
- `tests/test_shared_gateway_trust.py`（新，纯函数不连库，RAG check 脚本体例）：7 项校验——
  两把各被接受、错误/缺头→401、未配 office 时 office 不被信任、一把都没配全拒。

## 3. 否掉的方案（最值钱）
- **不复用 `INTERNAL_SHARED_SECRET`**：复用一把 = 轮换要同步改三处，正是本文件顶部反复警告的
  故障模式；独立一把可各自轮换/吊销，互不牵连。
- **不动 RAG 自己网关的旧路**：纯 additive——老路（仅 RAG 密钥）行为不变，不回归。
- **dev 模式不受影响**：dev 不验网关证明（否则本机裸跑没法调试）；本改动只在 gateway 模式生效。

- 现有 `test_module14_trust_boundary.py`：**103 通过 / 0 失败**（不回归，DB 在）。

## 5. 风险 / 已知遗留
- 只解决「后端信谁」。要真正跑通还需 **office 侧**：① 按 rag 上游注入 `X-Username`/`X-User-Id` +
  `X-Internal-Auth`(=office secret)，并**剥离客户端身份头**（信任边界）；② **身份对齐**：office
  JWT 的 username 能在 RAG `user` 表解析到（RAG 已支持按 username 回落），否则 RAG 401「账号不存在」。
- 「去双认证」靠**拓扑**实现：共享网关→RAG 后端直连（RAG 自己网关仍服务独立访问），不再叠加验签。
- 上生产：RAG 侧设 `OFFICE_GATEWAY_SHARED_SECRET` + office 网关配同一把 + 注身份；单独验证、可回滚。
