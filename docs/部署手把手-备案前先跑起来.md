## 0. 先回答三个问题

**Q1：备案影不影响部署？**
不影响部署本身，只影响「用域名对外提供 80/443 网页服务」。备案审核期间（管局约 7~20 个工作日），腾讯云会拦截所有走 80/443 的域名访问（访客会看到「未备案」提示页）。但**纯 IP + 高位端口（如 8080）自测是允许的**，官方也是这么建议的。

**Q2：现在能做什么、不能做什么？**

| 动作 | 备案前 | 备案后 |
|------|--------|--------|
| 服务器装环境、跑起全栈 | ✅ 随便做 | ✅ |
| 浏览器访问 `http://42.192.111.82:8080` 自测 | ✅ | ✅ |
| 域名解析指向服务器 | ✅ 可先配好（反正访问被拦） | ✅ 自动生效 |
| 80/443 对外提供网页服务 | ❌ 腾讯云拦截 | ✅（P1-7 + P2-9） |

**Q3：所以现在要做的 = 阶段 A（本文 §2~§8）**，全程约 1~2 小时（大部分是等构建）。备案下来后再做阶段 B（§9）。

## 1. 控制台各模块是什么（你截图问的那些）

| 模块 | 是什么 | 部署中用不用 |
|------|--------|------------|
| **登录**（OrcaTerm 免密登录） | 网页版终端 = 不用装任何工具就能敲服务器命令 | ✅ 主力。点「登录」直接进命令行 |
| **域名解析** | 给域名配 DNS 记录。你的 `@` 和 `www` 已解析正常 | 备案后加一条 `qa` 记录即可 |
| **SSH 密钥** | 一对「公钥+私钥」。公钥放服务器，私钥留在你 Mac（`~/.ssh/id_ed25519` 本来就有）。之后 `ssh root@42.192.111.82` 免密码、比密码更安全 | ✅ 建议配（方便 scp 传文件） |
| **文件管理** | 网页版文件管理器（root 身份），适合看配置文件、传单个文件 | 传整个项目用 git/scp 更快 |
| **对象存储 COS** | 云端「网盘」。部署用不到；它是将来 P2-10 数据备份的目的地，现在不用管（要授权角色，届时再说） | ❌ 暂不用 |
| **Hermes Agent / Lighthouse Agent** | 腾讯云官方的 AI 运维助手（能帮你敲命令、看监控）。可以用它干杂活，但部署核心步骤建议自己敲——这是你自己的生产服务器 | 辅助 |
| **防火墙** | 轻量云自带的入站端口白名单（不是服务器里的 iptables） | ✅ 要开 8080（自测）/ 80、443（备案后） |

## 2. 阶段 A-1：登录服务器

两条路任选：

- **网页终端（最省事）**：控制台右上角「登录」→ 免密登录 → 弹出 OrcaTerm 命令行。本文所有服务器命令都在这里敲。
- **本机终端（推荐顺手配好）**：
  1. Mac 上执行 `cat ~/.ssh/id_ed25519.pub`，复制整行输出；
  2. 控制台「SSH 密钥」→ 创建密钥 → 选「导入已有公钥」→ 粘贴 → 绑定实例 `Hermes Agent-kqQR`（提示重启就重启），**用户名选 `ubuntu`**；
  3. 之后 Mac 终端直接 `ssh ubuntu@42.192.111.82`，免密码。

> ✅ 2026-10-09：这一步已完成（密钥 `ihkp-qe13xtya`，用户名 `ubuntu`）。全文所有 `root@` 均按 `ubuntu@` 理解。

## 3. 阶段 A-2：装 Docker（服务器的心脏）

项目整套架构（MySQL/Redis/Chroma/后端/网关/前端）全靠 Docker 跑。先检查：

```bash
docker -v && docker compose version
```

- 如果两个版本号都出来了 → 跳过本节。
- 实际系统是 **Ubuntu 24.04**，直接 apt 装（**别用 `snap install docker`**，snap 版有网络/挂载的坑）：

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2
sudo systemctl enable --now docker
sudo usermod -aG docker ubuntu   # 免 sudo 用 docker
exit                              # 退出后重新 ssh 进来生效
```

- 装好重新验证一次 `docker -v && docker compose version`（Ubuntu 24.04 源里 docker.io 是 29.x、compose v2，都够用）。

## 4. 阶段 A-3：加 2G swap（4G 内存不够，必须加）

> **这不是升级服务器、不花钱**：用的是 60GB 系统盘的剩余空间，划 2GB 出来当「备用内存」，防止构建前端时内存爆掉。命令直接加，重启不丢。

不加的话构建前端时大概率内存爆掉。逐行执行：

```bash
fallocate -l 2G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
free -h    # 确认 Swap 一行是 2.0Gi
```

## 5. 阶段 A-4：把代码传上去

**在你 Mac 的终端执行**（不是服务器）。私钥配好后 scp 直接通；没配密钥会提示输密码。

```bash
cd ~/Desktop/AIAgent
COPYFILE_DISABLE=1 tar --exclude='rag-qa-system/node_modules' \
    --exclude='rag-qa-system/.venv' \
    --exclude='rag-qa-system/.git' \
    --exclude='rag-qa-system/chroma_data' \
    --exclude='rag-qa-system/upload' \
    --exclude='rag-qa-system/app.log' \
    --exclude='._*' \
    -czf /tmp/rag-qa.tgz rag-qa-system
```

> ⚠️ **`COPYFILE_DISABLE=1` 与 `--exclude='._*'` 必带**（2026-10-09 实测踩坑）：macOS 打 tar 会给每个文件附一个 `._` 影子文件（AppleDouble），它们以 `.py` 结尾时会被 alembic 当迁移加载，直接报 `source code string cannot contain null bytes`。

scp /tmp/rag-qa.tgz ubuntu@42.192.111.82:/tmp/

ssh ubuntu@42.192.111.82 'sudo mkdir -p /opt/qa && sudo chown ubuntu:ubuntu /opt/qa && tar -xzf /tmp/rag-qa.tgz -C /opt/qa --strip-components=1 && rm /tmp/rag-qa.tgz'
```

> 说明：`node_modules`/`.venv`/`.git` 都不用传（体积大且服务器会重新装）；`chroma_data` 是本机历史遗留（真向量库在容器里）；`upload/` 里的知识库原文件**刻意不传**——服务器是干净库，部署完重新上传文档即可，避免本机测试数据混进生产。
> 以后每次更新代码：重复这三个命令，然后在服务器上重新构建（§7）。

## 6. 阶段 A-5：写生产 .env（最重要的一步）

在服务器上：

```bash
cd /opt/qa
cp .env.example .env
vi .env    # 不熟 vi 就用 nano .env
```

**必须改的行**（其余先保持默认，`WORKER_CONCURRENCY=1` 已是 4C4G 合适值）：

```ini
# 对外暴露地址：自测阶段放开，备案后改回 127.0.0.1（由边缘 nginx 接管）
BIND_ADDR=0.0.0.0

# 数据库口令：改成你自己的强口令（两行都用同一个新口令体系）
MYSQL_PASSWORD=<新强口令>
MYSQL_ROOT_PASSWORD=<新强口令root>

# 硅基流动：从本机 .env 原样抄过来
SILICONFLOW_API_KEY=<你本机的 key>

# 网关↔后端内部共享密钥：随便一串长随机字符（openssl rand -hex 32 生成）
INTERNAL_SHARED_SECRET=<openssl rand -hex 32 的输出>

# 浏览器来源白名单：自测阶段写 IP
GATEWAY_ALLOWED_ORIGINS=http://42.192.111.82:8080
ALLOWED_ORIGINS=["http://42.192.111.82:8080"]

# 会话落 MySQL
MEMORY_BACKEND=mysql
```

> ⚠️ `.env` 是唯一不该进 git 的文件——它现在只存在于服务器 `/opt/qa/.env`，本机的 `.env` 与它互不影响。

## 7. 阶段 A-6：构建并启动全栈

```bash
cd /opt/qa
docker compose --profile full up -d --build
```

首次构建约 5~15 分钟（拉镜像 + 前端 vite 构建）。结束后验证：

```bash
docker compose --profile full ps          # 7 个容器都应是 Up / healthy
curl http://127.0.0.1:8080/api/health     # 返回正常 JSON
```

某几个容器没起来时：`docker compose logs -f <名字>`（如 `rag-frontend`、`rag-gateway`）看报错，修完 `docker compose --profile full up -d` 再拉起。

## 8. 阶段 A-7：开防火墙端口 + 浏览器验收

1. 控制台「防火墙」→ 添加规则：协议 TCP、端口 `8080`、策略允许、来源 `0.0.0.0/0`。
2. 你 Mac 的浏览器打开 **`http://42.192.111.82:8080`** → 应看到登录页。
3. 建一个管理员账号登录 → 上传一篇文档 → 等解析完成 → 流式问答。
4. 日常运维命令（都在 `/opt/qa` 下执行）：

```bash
docker compose --profile full ps                  # 看状态
docker compose logs -f rag-backend                # 追某个服务日志
docker compose --profile full restart             # 全部重启
docker compose --profile full down                # 停止（数据在 volume，不丢）
docker compose --profile full up -d --build       # 改代码后重新构建启动
```

> 数据都存在 Docker volume 和 `/opt/qa` 里，重启容器不丢；但**这个阶段还没有备份**，别在这台机器上放唯一副本的重要资料（P2-10 备份上线后再说）。
