# 部署方案：子域名形态（qa.nianan.site）

> 决策日期：2026-09-28
> 适用：备案通过后上线。当前 tag `v2.0.0-p1.6e`。
> 关联计划：`docs/PLAN-v2.0.0.md`（P1-7 / P2-8 / P2-9 / P2-10）

---

## 0. 决策结论

采用**子域名**而非子路径挂载：

- `nianan.site` → 个人网站（静态）
- `qa.nianan.site` → RAG 问答系统（本仓库，前端容器根路径部署）
- 未来项目 → `blog.nianan.site` 等，各自独立

**关键好处**：RAG 应用**零代码改动**按根 `/` 部署（无需改 vite base / favicon / logo / VITE_API_BASE）。
复杂度集中到「一张通配符证书 + 每条 DNS A 记录」，比把路径耦合写进代码更省心。

## 1. 拓扑

```
                         DNS (腾讯云解析)
  nianan.site  ─────A────► 42.192.111.82
  qa.nianan.site ──A────► 42.192.111.82
  blog.nianan.site ─A────► 42.192.111.82   (将来)

                          服务器 42.192.111.82 (Lighthouse 4C4G)
  ┌──────────────────────────────────────────────────────────────┐
  │  边缘 nginx（新，唯一对公 80/443，持通配符证书 *.nianan.site） │
  │   server_name qa.nianan.site  → proxy_pass http://qa-frontend:80 │
  │   server_name nianan.site     → root /var/www/personal          │
  │   server_name blog.nianan.site→ proxy_pass http://blog:80 (将来) │
  └───────────────┬───────────────────────────┬─────────────────────┘
                  │ (同 docker network)         │
                  ▼                             │
        qa-frontend 容器 (nginx, :80)           │
          location /        → SPA 静态                          
          location /api/    → gateway:3000  (proxy_buffering off)
                  │                         │
                  ▼                         ▼
            gateway:3000  →  backend:8000
            worker / mysql / redis / chroma  (既有 compose)
```

注意：浏览器到 `qa.nianan.site` 是同 origin 请求（页面与 `/api` 都在 `qa.nianan.site` 下），
经边缘 nginx → qa-frontend 容器 → 其自带 nginx 反代到网关。**全程同源，不触 CORS。**

## 2. DNS 配置（腾讯云解析控制台）

| 主机记录 | 类型 | 线路 | 记录值 | 说明 |
|---|---|---|---|---|
| `@` | A | 默认 | 42.192.111.82 | 个人站根域 |

| `blog` | A | 默认 | 42.192.111.82 | 将来（先不建也行） |

> 公安联网备案也是针对主体/网站，子域包含在内。

## 3. 服务器初始化（Lighthouse）

1. 系统：TencentOS / Ubuntu（镜像自带 Docker 最佳；没有就装 Docker Engine + compose plugin）。
2. 建用户、配 SSH 密钥、关 root 密码登录。
3. **加 2G swap**（4C4G 内存紧，见 §7 预算）。
4. 防火墙（Lighthouse 控制台「防火墙」规则，不是 iptables）：
   - 22 入站（已有）
   - **80 / 443 入站**（备案通过后再开；备案前公开 80/443 违规）
5. 目录规划：
   - `/opt/qa` 放本仓库（compose + .env）
   - `/opt/edge` 放边缘 nginx 配置与证书挂载
   - `/var/www/personal` 放个人站静态

---

## 4. 证书（详见 §6 对比）

推荐 **certbot 通配符 `*.nianan.site`**（DNS-01 挑战），一次签发覆盖所有子域、自动续期。
若不想配 DNS API，可用腾讯云免费证书按子域分别申请（需手动续期）。

## 5. 部署步骤（备案通过后执行）

### 5.1 拉代码 + 生产 .env
```bash
cd /opt/qa
git clone git@github.com:d-ouyang/rag_qa_system.git .   # 或 scp
cp .env.example .env
# 编辑 .env：
#   PROJECT_VERSION=2.0.0-p1.6e
#   ALLOWED_ORIGINS=["https://qa.nianan.site","https://nianan.site"]
#   MYSQL_HOST=mysql  REDIS_HOST=redis  (全栈模式变量)
#   填入 MySQL 口令 / SECRET_KEY / 硅基流动 key（绝不进 git/镜像）
```

### 5.2 起 QA 全栈
```bash
make stack-up --profile full        # frontend/gateway/backend/worker/mysql/redis/chroma
```
验证：容器内 `curl localhost:8000/api/v1/system/health` 正常。

### 5.3 边缘 nginx（新组件）
- 放在 QA compose 同一 docker network，或独立 compose 连同一 network。
- 配置以 volume 挂载，便于以后加子域只改配置 + reload，不重建。
- 关键指令（qa 块）：
  ```nginx
  server {
      listen 443 ssl;
      server_name qa.nianan.site;
      ssl_certificate     /etc/letsencrypt/live/nianan.site/fullchain.pem;
      ssl_certificate_key /etc/letsencrypt/live/nianan.site/privkey.pem;

      client_max_body_size 120m;          # ⚠️ 否则 >1MB 上传被 413 拦在边缘
      location / {
          proxy_pass http://qa-frontend:80;
          proxy_http_version 1.1;
          proxy_set_header Host $host;
          proxy_set_header X-Real-IP $remote_addr;
          proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
          proxy_set_header X-Forwarded-Proto https;   # ⚠️ 后端/网关拿到的协议要是 https
          proxy_buffering off;              # ⚠️ NDJSON 流式必须关，否则打字机变一次性吐出
          proxy_request_buffering off;
          proxy_read_timeout 300s;         # 长回答别被 60s 掐断
          proxy_send_timeout 300s;
      }
  }
  server {
      listen 80;
      server_name qa.nianan.site nianan.site;
      return 301 https://$host$request_uri;   # 80→443
  }
  server {
      listen 443 ssl;
      server_name nianan.site;
      root /var/www/personal;
      index index.html;
      try_files $uri $uri/ /index.html;
  }
  ```

### 5.4 申请证书（certbot, DNS-01 通配符）
```bash
certbot certonly --dns-tencentcloud \
  -d nianan.site -d '*.nianan.site' \
  --dns-tencentcloud-credentials /etc/letsencrypt/tencent.ini
# tencent.ini: dns_tencentcloud_secret_id = xxx / dns_tencentcloud_secret_key = xxx (权限收紧 600)
# 自动续期：certbot renew 已注册 systemd timer；--deploy-hook 里 reload 边缘 nginx
```
验证续期：`certbot renew --dry-run`。

### 5.8 公安联网备案（ICP 通过后 30 日内，与 ICP 备案是两套独立系统）

> **时限**：依据《计算机信息网络国际联网安全保护管理办法》（公安部令第 33 号）第十二条，
> 网络正式联通之日起 **30 日内**备案。ICP 通过 2026-10-09 → **2026-11-08 前提交**，
> 逾期可被警告或停机整顿（第二十三条）。平台：**全国互联网安全管理服务平台
> `https://beian.mps.gov.cn`**（公安部，注意区别于工信部 ICP 的 `beian.miit.gov.cn`），
> 用「互联网+政务服务」实名登录（手机号 + 人脸）。

**第一步：申请主体（第一个弹窗点「申请主体」，不要点取消）**

- 首次登录「我的主体」显示「无主体」，而绑定数据码、办网站备案都必须先有主体，
  所以提示「您当前暂无有效主体，请先申请主体」时**点「申请主体」**（取消只会关弹窗，绕不开）。
- 主体表单照 ICP 备案填：开办者性质 **个人**、姓名 **欧阳鼎**、证件 **身份证**；
  「关联旧账号」是给曾在本平台办过业务的人用的，用不上。

**第二步：数据码绑定（主体建好后再回到「数据码」入口填）**

| 弹窗字段 | 填什么 |
|---|---|
| 数据码 | `627d1fa0f1127eacef39dbf54da41dee`（工信部备案系统生成的网站备案数据码） |
| 网站或主体负责人手机号/证件号 | ICP 备案时主体负责人的**手机号或身份证号**（任一，用于和腾讯云报送的数据做身份匹配；推荐备案时留的手机号） |

- 绑定成功后平台自动带入腾讯云报送的主体与网站数据，大幅减少手填。
- 弹窗备注「系统检测到您当前登录账号信息与服务商发送的数据码有匹配关系」即本人数据，放心绑。

**第三步：新办网站申请（业务办理 → 网站业务）**

- 域名：`nianan.site`（子域 `qa.nianan.site` 随根域，不单独备案）；
- 服务器 IP：`42.192.111.82`；接入服务商：**腾讯云**（列表里选，别手填）；

## 6. 证书方案对比：腾讯云免费 vs certbot

| 维度 | 腾讯云免费证书 | certbot (Let's Encrypt) |
|---|---|---|
| 类型 | DV，**单域名**（免费版不含通配符） | DV，支持**通配符** + 多域名 SAN |
| 有效期 | 通常 ~1 年 | 90 天 |
| 续期 | **手动**：到期前控制台重新申请、下载、替换 nginx、reload | **自动**：内置 renew（systemd timer/cron），到期前自动续 + deploy-hook reload |
| 通配符 | 不支持（要通配符需付费证书） | 支持 `*.nianan.site`，一次覆盖所有现在和未来的子域 |
| 申请方式 | 控制台 GUI，DNS 或文件验证，下载 pem/key | 命令行；HTTP-01（需 80 可达）或 DNS-01（需 DNS API） |
| 部署 | 手动拷证书到 nginx + reload | `--deploy-hook` 自动拷 + reload |
| 适合 | 子域少（2~3 个）、不想在服务器放证书 Agent | 多子域 / 通配符 / 想要全自动续期 |
| 风险点 | 忘了续期 = 网站 HTTPS 过期告警/不可用 | DNS API 密钥要收好（600 权限） |

**结论**：本场景（qa + blog + 未来更多）选 **certbot 通配符**最省心——一张证管全部 + 自动续。
若不想配腾讯云 DNS API，腾讯云免费证书对每个子域分别申请也能跑，但务必记得到期手动替换。

## 8. 注意事项（坑）

1. **边缘 nginx 必须 `proxy_buffering off` + `proxy_read_timeout 300s`**，否则流式回答会变「转圈十几秒一次性吐出」，且不报错只是慢。
2. **边缘 nginx `client_max_body_size 120m`**：上传先到边缘，默认 1m 会 413 拦在网关之前。
3. **`X-Forwarded-Proto https`**：后端/网关若拼绝对 URL 要用 https，否则出现混合内容或错误跳转。
4. **备案前不要开 80/443 公开服务**；可先用 IP + 高位端口临时自测。
5. **4C4G 内存**：worker 不加载 reranker、Celery `concurrency=1`、`--max-tasks-per-child=20`、MySQL `innodb_buffer_pool_size=128M`、2G swap（沿用 PLAN §11.1）。
6. **边缘 nginx 与 QA 容器同 docker network**，否则 `proxy_pass http://qa-frontend:80` 解析不到。
7. **证书自动续期务必 `certbot renew --dry-run` 验证**，并确认 deploy-hook reload 了边缘 nginx（否则续了但没生效）。
8. **`ALLOWED_ORIGINS` 加 `https://qa.nianan.site`**（同源其实不触发 CORS，加双保险）。
9. **`.env` 不进 git / 不进镜像层**；生产密钥只走 env_file。
10. **子域 307 不会复发**：请求是 `https://qa.nianan.site/api/v1/documents`（无 /qa 前缀），后端双路径注册已消除无斜杠 307，同源不暴露内网地址。
