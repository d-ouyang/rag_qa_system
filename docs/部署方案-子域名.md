# 部署方案：子域名形态（qa.nianan.site）

> 决策日期：2026-09-28  
> 适用：备案通过后上线。当前 tag `v2.0.0-p1.6e`。  
> 关联计划：`docs/PLAN-v2.0.0.md`（P1-7 / P2-8 / P2-9 / P2-10）

---

## 0. 决策结论

采用**子域名**而非子路径挂载：

- `nianan.site` → 个人网站（静态）
- `qa.nianan.site` → RAG 问答系统（本仓库，前端容器根路径部署）
- 未来项目 → `blog.nianan.site` 等，各自独立

**关键好处**：RAG 应用**零代码改动**按根 `/` 部署（无需改 vite base / favicon / logo / VITE_API_BASE）。  
复杂度集中到「一张通配符证书 + 每条 DNS A 记录」，比把路径耦合写进代码更省心。

## 1. 拓扑

```
                         DNS (腾讯云解析)
  nianan.site  ─────A────► 42.192.111.82
  qa.nianan.site ──A────► 42.192.111.82
  blog.nianan.site ─A────► 42.192.111.82   (将来)

                          服务器 42.192.111.82 (Lighthouse 4C4G)
  ┌──────────────────────────────────────────────────────────────┐
  │  边缘 nginx（新，唯一对公 80/443，持通配符证书 *.nianan.site） │
  │   server_name qa.nianan.site  → proxy_pass http://qa-frontend:80 │
  │   server_name nianan.site     → root /var/www/personal          │
  │   server_name blog.nianan.site→ proxy_pass http://blog:80 (将来) │
  └───────────────┬───────────────────────────┬─────────────────────┘
                  │ (同 docker network)         │
                  ▼                             │
        qa-frontend 容器 (nginx, :80)           │
          location /        → SPA 静态                          
          location /api/    → gateway:3000  (proxy_buffering off)
                  │                         │
                  ▼                         ▼
            gateway:3000  →  backend:8000
            worker / mysql / redis / chroma  (既有 compose)
```

注意：浏览器到 `qa.nianan.site` 是同 origin 请求（页面与 `/api` 都在 `qa.nianan.site` 下），  
经边缘 nginx → qa-frontend 容器 → 其自带 nginx 反代到网关。**全程同源，不触 CORS。**

## 2. DNS 配置（腾讯云解析控制台）

| 主机记录   | 类型 | 线路 | 记录值           | 说明        |
| ------ | -- | -- | ------------- | --------- |
| `@`    | A  | 默认 | 42.192.111.82 | 个人站根域     |
| `qa`   | A  | 默认 | 42.192.111.82 | RAG 问答    |
| `admin` | A | 默认 | 42.192.111.82 | 管理端 admin-console |
| `blog` | A  | 默认 | 42.192.111.82 | 将来（先不建也行） |

> 子域备案：同一主体下的子域随主域 `nianan.site` 的 ICP 备案一并覆盖，**不用单独备案**。  
> 公安联网备案也是针对主体/网站，子域包含在内。

> ✅ **2026-10-10 已建**（DNSPod 免费版）：`@` / `www` / `qa` / `admin` 四条 A 记录 → 42.192.111.82，TTL 600。

> **管理端子域决策（2026-10-10）**：管理端用独立子域 `admin.nianan.site`，
> **不用** `qa.nianan.site/admin` 路径形态。
> 否掉的理由：admin-console 是独立 Vite 应用，子域形态下 base 保持 `/` **零改动**；
> 路径形态要改 vite `base: '/admin/'` + 路由 base，SPA 资源路径与 history 回退都容易踩坑，
> 而通配符证书 `*.nianan.site` 一张就覆盖两种形态，独立子域不增加证书成本。

## 3. 服务器初始化（Lighthouse）

1. 系统：TencentOS / Ubuntu（镜像自带 Docker 最佳；没有就装 Docker Engine + compose plugin）。
2. 建用户、配 SSH 密钥、关 root 密码登录。
3. **加 2G swap**（4C4G 内存紧，见 §7 预算）。
4. 防火墙（Lighthouse 控制台「防火墙」规则，不是 iptables）：
   - 22 入站（已有）
   - **80 / 443 入站**（备案通过后再开；备案前公开 80/443 违规）
5. 目录规划：
   - `/opt/qa` 放本仓库（compose + .env）
   - `/opt/edge` 放边缘 nginx 配置与证书挂载
   - `/var/www/personal` 放个人站静态

## 4. 证书（详见 §6 对比）

推荐 **certbot 通配符 `*.nianan.site`**（DNS-01 挑战），一次签发覆盖所有子域、自动续期。  
若不想配 DNS API，可用腾讯云免费证书按子域分别申请（需手动续期）。

### 5.3 边缘 Caddy（宿主机已有，直接接管）

> **方案转折（2026-10-10）**：原计划「独立 nginx 容器 + certbot 通配符」因宿主机 80/443 已被
> **Caddy v2.11.4（systemd `caddy.service`，配置 `/etc/caddy/Caddyfile`）** 占用而作罢；
> 该 Caddy 是裸默认配置（仅 serve "Caddy works!"，未托管任何真实站点），故**直接接管它当边缘 TLS 代理**，废弃 nginx 容器 + certbot。
> 优势：Caddy 自带 ACME 自动 HTTPS（HTTP-01，80 已通），免腾讯云 DNS 密钥、免手动续期；且**默认不缓冲**，
> NDJSON 流式问答直接透传（nginx 才需 `proxy_buffering off`）。

- 反代目标走宿主已发布端口（Caddy 是宿主进程，用本机端口而非 docker 服务名）：
  `rag-frontend` → `127.0.0.1:8080`、`rag-gateway` → `127.0.0.1:3000`。
- 改 `/etc/caddy/Caddyfile` 后 `sudo systemctl reload caddy` 即生效；证书自动申请 + 续期。
- `/api*` 单独反代到网关（前端 SPA 的 API base 是相对路径 `/api`，同源），其余走前端。
- 管理端 `admin.nianan.site` 已在 Caddyfile 内（反代 `127.0.0.1:5174`，P2-9 生产化前需先 `npm run dev` 起 admin-console；未起会 502，可注释掉该块）。

```caddy
{
    email your-email@example.com   # ← 改成真实邮箱（Let's Encrypt 通知用）
}

# RAG 问答：前端 + 同域 API
qa.nianan.site {
    encode gzip
    handle /api* {
        reverse_proxy 127.0.0.1:3000 {
            header_up Host {host}
        }
    }
    handle {
        reverse_proxy 127.0.0.1:8080 {
            header_up Host {host}
        }
    }
}

# 管理端（P2-9 生产化前先在 5174 跑 dev；没跑会 502，可注释）
admin.nianan.site {
    reverse_proxy 127.0.0.1:5174
}

# 个人站主站（构建产物 dist/ → /var/www/personal）
nianan.site, www.nianan.site {
    encode gzip
    root * /var/www/personal
    try_files {path} /index.html   # ⚠️ SPA 回退，缺了非根路径会 404
    file_server
}
```

> ⚠️ 线上验证通过的那一版以服务器 `/etc/caddy/Caddyfile` 为准；上方为 2026-10-10 初版。
> ✅ **2026-10-10 已验证**：`qa.nianan.site` 走通 HTTPS（Caddy → `127.0.0.1:8080` 返回 200），`/api/*` 反代到 `127.0.0.1:3000` 也通（实测到达后端 uvicorn）。
> 健康端点用 **`/api/health`**（不是 `/api/v1/system/health`）。本地验证务必 `curl --noproxy '*'` 绕过 ClashX 代理，否则会误报 502。
> `admin.nianan.site` 502 为预期（5174 未起 dev server），P2-9 生产化时再处理。
> ✅ **个人站已上线（2026-10-10 23:45）**：`nianan.site` / `www.nianan.site` 均 HTTPS 200（Caddy file_server → `/var/www/personal`）；
> 发布流程 = 本地 `pnpm build` → `rsync -avz --delete dist/ ubuntu@42.192.111.82:/var/www/personal/` → `sudo chmod -R a+rX /var/www/personal`（Caddy 以 caddy 用户跑）。
> ⚠️ 静态文件**上传后无需 reload caddy**（file_server 按请求读盘）；只有改了 Caddyfile 才 reload。
> 🔴 `try_files {path} /index.html` 必须**有空格**（两个参数）；写成 `{path}/index.html` 会被当成一个候选路径，SPA 深层路由仍 404（本站无 react-router，单页锚点，暂无影响）。
> 安全收口（P2-9 之后）：把 `rag-frontend` / `rag-gateway` 的 compose 发布从 `0.0.0.0:8080/3000`
> 改为 `127.0.0.1:8080/3000`，并删掉防火墙 8080 规则，让全部流量只走 443。

## 6. 证书方案对比：腾讯云免费 vs certbot

| 维度   | 腾讯云免费证书                              | certbot (Let's Encrypt)                                         |
| ---- | ------------------------------------ | --------------------------------------------------------------- |
| 类型   | DV，**单域名**（免费版不含通配符）                 | DV，支持**通配符** + 多域名 SAN                                          |
| 有效期  | 通常 ~1 年                              | 90 天                                                            |
| 续期   | **手动**：到期前控制台重新申请、下载、替换 nginx、reload | **自动**：内置 renew（systemd timer/cron），到期前自动续 + deploy-hook reload |
| 通配符  | 不支持（要通配符需付费证书）                       | 支持 `*.nianan.site`，一次覆盖所有现在和未来的子域                               |
| 申请方式 | 控制台 GUI，DNS 或文件验证，下载 pem/key         | 命令行；HTTP-01（需 80 可达）或 DNS-01（需 DNS API）                         |
| 部署   | 手动拷证书到 nginx + reload                | `--deploy-hook` 自动拷 + reload                                    |
| 适合   | 子域少（2~3 个）、不想在服务器放证书 Agent           | 多子域 / 通配符 / 想要全自动续期                                             |
| 风险点  | 忘了续期 = 网站 HTTPS 过期告警/不可用             | DNS API 密钥要收好（600 权限）                                           |

**结论（2026-10-10 修订）**：实际落地**不用 certbot 也不用腾讯云证书**——宿主机已有 Caddy，直接由它走 ACME 自动 TLS（HTTP-01），每个子域名独立证书、自动续期，零额外组件、零 DNS 密钥。上表仅供当初选型参考，已被 §5.3/§5.4 的 Caddy 方案取代。

## 8. 注意事项（坑）

1. **边缘 nginx 必须 `proxy_buffering off` + `proxy_read_timeout 300s`**，否则流式回答会变「转圈十几秒一次性吐出」，且不报错只是慢。
2. **边缘 nginx `client_max_body_size 120m`**：上传先到边缘，默认 1m 会 413 拦在网关之前。
3. **`X-Forwarded-Proto https`**：后端/网关若拼绝对 URL 要用 https，否则出现混合内容或错误跳转。
4. **备案前不要开 80/443 公开服务**；可先用 IP + 高位端口临时自测。
5. **4C4G 内存**：worker 不加载 reranker、Celery `concurrency=1`、`--max-tasks-per-child=20`、MySQL `innodb_buffer_pool_size=128M`、2G swap（沿用 PLAN §11.1）。
6. **边缘 nginx 与 QA 容器同 docker network**，否则 `proxy_pass http://qa-frontend:80` 解析不到。
7. **证书自动续期务必 `certbot renew --dry-run` 验证**，并确认 deploy-hook reload 了边缘 nginx（否则续了但没生效）。
