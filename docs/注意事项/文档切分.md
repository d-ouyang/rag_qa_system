## 一、模块 2：文档加载与切分（`core/document_loader.py`）

### 1.1 支持格式与 Loader 选型

| 后缀 | 实现 | 选型理由（面试可讲） |
|---|---|---|
| `.pdf` | `PyMuPDFLoader` | 比 `PyPDFLoader` 快且对中文/版面支持好；**每页一个 Document** |
| `.docx` / `.doc` | `Docx2txtLoader` | 纯文本提取够用、零额外依赖；旧版 `.doc` 会额外告警（解析库支持有限） |
| `.xlsx` / `.xls` | `UnstructuredExcelLoader` | 能带出表格结构 |
| `.txt` | `TextLoader` | **加了编码回退链**（见 1.3 坑 3） |
| `.md` | `UnstructuredMarkdownLoader` → 失败回退纯文本 | 结构化解析失败时不能让整篇内容丢失 |
| `.csv` | `CSVLoader` | 每行一条 Document，`列名: 值` 拼接，天然适合问答 |
| `.json` | **自己写**（约 10 行） | `JSONLoader` 的 `jq_schema` 无法同时兼容顶层对象与数组（见 1.3 坑 5） |
| `.html` / `.htm` | `BSHTMLLoader` | `bs4` 已在依赖树里；`UnstructuredHTMLLoader` 会触发 NLTK 联网下载 |
| `.pptx` | **自己写**（python-pptx） | `UnstructuredPowerPointLoader` 长文本时会因 NLTK 缺失直接失败（见 1.3 坑 2） |

> 共 12 种后缀。**新增格式只需要改一个地方**：`SUPPORTED_EXTENSIONS` 白名单（校验、目录遍历、日志全部读它）。

### 1.2 关键设计决策（面试官爱问的「为什么这么设计」）

| 决策 | 理由 |
|---|---|
| 元数据拆成 `source`(路径) / `file_name`(展示名) / `file_type` | **唯一标识和展示名必须分开**：`source` 唯一（用于删除、去重、溯源），`file_name` 可重复。混用会导致误删（见第三章） |
| 校验失败 / 解析失败**返回空列表**，不抛异常 | 批量导入场景下，**部分成功优于整体失败**；调用方按「非空即成功」处理，异常只用于真正不可恢复的情况 |
| 单文件失败**不中断**整目录加载 | 一个坏文件不该让 999 个好文件陪葬；用 try/except 隔离 + 计数上报 |
| 切分参数（`chunk_size`/`chunk_overlap`）从 `settings` 读，但允许构造时覆盖 | 生产用配置、**测试用小值**（`chunk_size=100` 能快速验证切分逻辑） |
| 内置元数据先写、调用方元数据后 `update`（调用方优先） | 上传时文件会被 uuid 改名，`path.name` 已不是原名，必须允许调用方覆盖 `file_name` |
| `is_supported()` 只看后缀、不碰文件系统 | 上传接口要**先拦截再落盘**，此时文件还不存在 |

### 1.3 踩坑清单

#### 坑 1 · `rglob` 让 `recursive` 参数形同虚设

- **现象**：`load_directory(dir, recursive=False)` 依然把子目录的文件全扫了进来。
- **根因**：参考实现写的是 `pattern = "**/*" if recursive else "*"`，然后传给 **`rglob`**。而 `Path.rglob(p)` 等价于 `self.glob("**/" + p)`——**它本身就是递归的，与 pattern 里有没有 `**` 无关**。所以 `rglob("*")` 照样递归。
- **修法**：按需切换 API，而不是切 pattern：
  ```python
  file_iter = path.rglob("*") if recursive else path.glob("*")
  ```
  （若坚持用 pattern 写法，必须搭 **`glob`** 而不是 `rglob`。）
- **面试说法**：「`Path.rglob` 和 `Path.glob("*")` 的区别容易被名字误导——`rglob` 的 r 就是 recursive，传什么都没用。我先写了单测断言『非递归结果不包含子目录文件』，才把这个静默 bug 暴露出来。」

#### 坑 2 · `UnstructuredPowerPointLoader` 在离线环境直接解析失败

- **现象**：短文本的 PPT 能解析，换成长文本的 PPT 后整份返回空，日志里是 `LookupError: Resource 'punkt_tab' not found`。
- **根因**：文本超过一定长度时，unstructured 会进入「按标题分块」的逻辑，该逻辑**依赖 NLTK 的 `punkt` 分词数据**；数据不存在时会尝试联网下载，网络受限就直接抛异常。
- **修法**：绕开这条路径，用 `python-pptx` 自己抽（每页一条 Document，含文本框、表格、演讲者备注，并打 `page` 元数据）。
- **面试说法**：「同一份代码，短样本能跑、真实样本炸——因为框架内部有一条**按内容长度才触发**的分支。这类问题只有换成真实数据才暴露得出来，所以我坚持样本要贴近生产（见 1.5）。」

#### 坑 3 · 编码回退不生效：`UnicodeDecodeError` 被包装成了 `RuntimeError`

- **现象**：写了 `utf-8 → gbk` 的编码回退链，但 GBK 文件依然加载失败。
- **根因**：`TextLoader` / `CSVLoader` 内部把 `UnicodeDecodeError` 捕获后**重新抛成 `RuntimeError("Error loading ...")`**，只 catch `UnicodeDecodeError` 根本接不住。
- **修法**：候选异常一起接：`except (UnicodeDecodeError, LookupError, RuntimeError)`。
- **面试说法**：「第三方库的异常包装是隐形契约。我的回退链一开始『看起来』正确、日志也不报解码错误，但函数就是返回空——差别只在异常类型，必须实质跑一遍 GBK 文件才能发现。」

#### 坑 4 · `load_directory` 只按文件名判断隐藏文件，漏掉隐藏目录

- **现象**：`.git/`、`.hidden_dir/` 里的文件仍然被扫描入库。
- **根因**：只判断了 `file_path.name.startswith(".")`，**路径中间的目录名没判断**。
- **修法**：按**相对路径逐段**判断：
  ```python
  relative_parts = file_path.relative_to(path).parts
  if any(part.startswith(self.IGNORED_NAME_PREFIXES) for part in relative_parts):
  ```
- **面试说法**：「过滤规则要作用在『路径』上而不是『文件名』上，否则隐藏目录会漏网——`.git` 里有成千上万个文件，一旦入库就是灾难。」

#### 坑 5 · `JSONLoader` 的 `jq_schema` 无法同时兼容顶层对象和数组

- **现象**：`jq_schema="."` 遇到**顶层对象**时，切出来的内容是一堆**字段名**而不是内容；默认 `text_content=True` 遇到 dict 还会直接抛 `ValueError`。
- **根因**：`JSONLoader._parse` 是 `for i, sample in enumerate(data)`——jq 对对象取 `"."` 得到的是 dict，`enumerate(dict)` 迭代的是 **key**。
- **修法**：不用它，自己解析（顶层数组 → 每条记录一条 Document；其余 → 整篇一条）：`record if isinstance(record, str) else json.dumps(record, ensure_ascii=False, indent=2)`。
- **面试说法**：「框架 Loader 的默认行为要读源码确认，不能只看名字。我读完之后发现它要我为每种 JSON 结构分别配 schema，还不如 10 行代码自己写，顺便还少一个 `jq` 依赖。」

#### 坑 6 · 空文件被误报成「文件处理失败」

- **现象**：目录加载时计数 `失败=2`，但其中一个是空文件（合法文件），日志上一条是「加载并切分完成」、下一条却是「文件处理失败已跳过」，自相矛盾。
- **根因**：`load_directory` 用「`docs == []`」判定失败，但**空列表有两种含义**：解析失败 / 解析成功但无有效内容。
- **修法（待做）**：区分「解析异常」与「解析成功但为空」，或让 `load_file` 返回 `(docs, error)`。
- **面试说法**：「统计口径要能区分『失败』和『没内容』——上传进度条给用户看的 `success/failed` 如果算错了，用户就会看到『失败 1 个』却不知道是哪个、为什么。」

#### 坑 7 · 解析失败的 traceback 把日志淹了

- **现象**：批量导入时，每个损坏文件都打一整段堆栈。
- **根因**：`logger.error(..., exc_info=True)` 同时承担了「记录原因」和「记录堆栈」两个职责。
- **修法（待做）**：主日志只留一行原因，完整堆栈降到 `DEBUG`。
- **面试说法**：「可观测性不是『日志越多越好』。ERROR 日志要能一眼看出『哪个文件、什么原因』，堆栈留给需要深入排查的人。」

### 1.4 边界与异常处理清单（已覆盖，有单测）

| 输入 | 期望行为 |
|---|---|
| 路径不存在 / 路径是文件却传给 `load_directory`（反之亦然） | 记录 ERROR，返回 `[]` |
| 不支持的后缀 / 无后缀 | 记录 ERROR，返回 `[]`（错误信息里列出当前支持的类型） |
| 空文件 | 返回 `[]`（不抛异常） |
| 单个文件损坏（假 docx / 非法 JSON） | 跳过该文件，**其余文件继续加载** |
| 隐藏文件 / `~$` 临时文件 / 隐藏目录 | 目录遍历时跳过 |
| GBK 编码的 txt / csv | 编码回退链命中，内容正确 |
| 同一目录树内出现同名文件 | 两份都保留 + 一条汇总 WARNING（见第三章） |

### 1.5 测试与样本工程（这一段本身也是面试加分项）

- **样本只有一个内容源**：`tests/sample_docs/test.txt`（真实的企业考勤制度），其余 8 种格式**全部由它派生**（`generate_samples.py`），保证各格式内容一致、可断言。
- **`.docx` 用标准库 `zipfile` 手工拼最小 OOXML**，不为生成测试样本引入 `python-docx` 依赖。
- **`.pdf` 用 PyMuPDF 内置 CJK 字体 `china-s` 写入**，保证中文是**可提取文本**而不是图片——否则测试会「假通过」（提取到空字符串）。
- **断言对象是函数返回值，不是日志级别**：负向用例里出现 ERROR 日志是**预期**的（证明边界校验生效）。
  > 这正是「终端一堆 ERROR 但汇总 0 失败」的原因——如果这些 ERROR 消失了，才说明校验坏了。
- 每个用例组失败不中断后续（`check()` 汇总 + 退出码），可单独 `python tests/xxx.py` 跑，也可以接 CI。

## 二、切分（Chunking）专题 —— RAG 效果真正的命门

> 项目文档原文：**「RAG 效果差，第一嫌疑人永远是切分参数，不是嵌入模型。」**
> 验收方式：**把 chunk 打出来读，看有没有半句话。**

### 2.1 机制：递归字符切分 + 分隔符优先级

```python
separators = ["\n\n", "\n", "。", "！", "？", ".", "!", "?", " ", ""]
```

规则：**从高优先级往低找第一个命中的分隔符 → 用它切 → 仍然超长的片段再用下一级分隔符递归切**。一旦某个分隔符命中，后面的**不再参与**。

两个必须澄清的事实（容易被人误认为 bug）：

1. **分隔符是安全的**：默认 `is_separator_regex=False`，源码里做了 `re.escape`。所以 `.` 是字面句点，`?` 是 `\?`，**不存在「`.` 变成任意字符」「`?` 抛 nothing to repeat」的问题**。（面试若被问「你用 `.` 当分隔符不怕正则问题吗」，答这个。）
2. **`chunk_size` 按字符数算**（`length_function=len`），而嵌入模型卡的是 **token 上限**，两者不是一个单位。
   已核实本项目模型配置：`bge-small-zh-v1.5` 的 `max_position_embeddings = 512`（**可输入 token 上限**），`hidden_size = 512`（**向量维度**）——**两个 512 含义完全不同，很容易被记混**。
   中文大致 1 字 ≈ 1 token，`CHUNK_SIZE=500` 加上 `[CLS]/[SEP]` 两个特殊 token 已逼近上限（余量不足 2%）。
   → **换嵌入模型、或换成以英文为主的语料（英文 1 词 ≈ 1.3 token，但字符数少）时，必须重新核对 `chunk_size`，否则超出部分会被静默截断，而且不报错。**

### 2.2 「语义断掉」的四类真实场景

| # | 场景 | 根因 | 可修性 |
|---|---|---|---|
| ① | **PDF / 硬换行文本被从句子中间切断** | `\n` 的优先级**高于** `。`。PDF 文本提取普遍是「按版面宽度硬换行」，行尾往往不是句尾 | ✅ 可修（换行归一化） |
| ② | **PDF 一句话跨页被截断** | PyMuPDFLoader **每页一个 Document**；`split_documents` 逐 Document 独立切分，**overlap 跨不过 Document 边界** | ✅ 可修（按整篇切） |
| ③ | 无标点长串被**逐字符硬切** | 从 `\n\n` 到空格全都没命中，只能退到最后的 `""`（逐字符）。典型：超长单词、URL、base64、纯数字表格 | ❌ 无更好切点，只能缓解 |
| ④ | 单个长段落内部无标点 | 与 ③ 同源（如 Excel 长单元格） | ⚠️ 缓解 |

**实测证据（chunk_size=50）**：

```
① 中文每 15 字强制换行：
   #0 ...这是第1句话的内容。这是第2句     ← 以「第2句」结尾
   #1 话的内容。这是第3句话的内容。...     ← 下一段以「话的内容」开头 ❌ 半句话

③ 完全无分隔符 'abc123XYZ'*20  → 50/50/50/50/20  逐字符硬切 ❌

对照：中文有句号（无换行）→ 切点全部落在 '。' 上 ✅
      英文只有空格无标点   → 切点全部落在 ' ' 上 ✅（不会切断单词）
      英文有句点           → 切点全部落在 '.' 上 ✅
```

**结论：硬切不是常态。**它需要「无换行 + 无中文标点 + 无英文标点 + 无空格」四个条件同时成立。

### 2.3 各格式的「切分硬边界」对照表

| 格式 | 原始 Document 粒度 | 实际切分行为 |
|---|---|---|
| txt / md / html / docx | **整个文件 1 个** | 完全由分隔符决定（中文按句、硬换行按行） |
| **pdf** | **每页 1 个** | 页内按分隔符；**跨页断句，且无 overlap 补偿** |
| xlsx | 通常 1 个 | 表格文本常无标点/空格 → 偏向硬切 |
| **csv** | **每行 1 个** | 行内基本不切；**相邻行不会合并** |
| **json** | **每条记录 1 个** | 按记录天然隔离 |
| **pptx** | **每页 1 个** | 页内按分隔符；跨页不连续 |

> 面试说法：「很多人以为切分只受 `chunk_size` 影响，其实**Loader 的 Document 粒度就是一个更硬的边界**——PDF 每页、CSV 每行、PPT 每页各成一个 Document，overlap 在这个边界上是失效的。」

### 2.4 优化方向（按性价比排序）

1. **换行归一化**（收益最大，专治 PDF/OCR 文本）：切分**之前**把「不以句末标点结尾的硬换行」合并成一行，让 `。` 重新成为最高优先级切点。
2. **PDF 按整篇切**：`PyMuPDFLoader(..., mode="single")`，或加载后把同文件的多个 Document 先合并再切，解决跨页断句。
3. **补中文标点**：separators 里 `。！？` 之后加 `；，、：`（中文长句里逗号分隔的并列成分很多）。**注意**：这会让片段更碎，必须配合 `chunk_size` 一起调。
4. **加大 overlap**：`CHUNK_OVERLAP` 提到 `chunk_size` 的 15%~20%，让断句处的语义损失被相邻片段补回来。
5. **可观测性**：留一个把 chunk 打印出来读的调试入口（后续 `/qa` 的 debug 链路）。

## 三、同名文件专题

### 3.1 先澄清：**加载层不会覆盖**

`document_loader` 不落盘，元数据里 `source` 存的是**文件路径**，所以 `/upload/a/说明.txt` 与 `/upload/b/说明.txt` 会各自独立入库，**两份都保留**。

| 字段 | 取值 | 是否唯一 |
|---|---|---|
| `source` | 文件**路径** | ✅ 唯一 |
| `file_name` | 文件**名** | ❌ 可重复 |

### 3.2 真正的三个风险点

| # | 位置 | 现象 | 后果 |
|---|---|---|---|
| ① | **上传落盘**（`api/routes/upload.py`，待开发） | `UPLOAD_DIR / file.filename` 按原名保存 | **物理覆盖**，前一份文件从磁盘消失 |
| ② | **按来源删除** | `delete_by_source(name)` 传的是 `file_name` 而非完整 `source` | 一删删两份（**误删**） |
| ③ | **溯源展示** | 检索结果只显示 `file_name` | 用户看到两个同名来源，**分不清是哪份** |

共同根因：**拿「展示名」当「唯一键」用。**

### 3.3 已实现：加载层同名检测

`DocumentLoader.find_duplicate_names(docs) -> {文件名: [来源路径, ...]}`，`load_directory` 收尾时调用，冲突时打**一条**汇总 WARNING（不是每文件一条）：

```
WARNING - 目录内存在 1 组同名文件（文件名相同、来源不同，内容可能不一样，请确认是否重复）：
说明.txt -> /upload/a/说明.txt, /upload/b/说明.txt
```

**判定依据是 `source` 而不是出现次数**——同一文件被重复传入不会误报。

### 3.4 待实现：上传落盘的完整方案

| 环节 | 做法 |
|---|---|
| 存储名 | `uuid4().hex[:8]_原文件名`（或按 uuid 建子目录），保证 `source` 唯一 |
| 元数据 | `source`=存储路径（唯一）、`file_name`=原名（展示，可重复）、`content_hash`=md5、`upload_time` |
| 去重 | **同名同内容**（hash 相同）→ 跳过并提示「内容相同的文件已存在」；**同名不同内容** → 两份都留，展示名加序号 |
| 展示 | 前端表格展示「文件名 + 上传时间 + 大小 + 存储名后 6 位」，同名时给别名 `说明.txt (2)` |
| 告知 | 接口返回 `{"renamed": true, "stored_name": "..."}`，前端弹**黄色提示**而非绿色成功 |
| 删除 | **只按 `source` 删**，禁止按 `file_name` 删 |
| 幂等 | 向量库入库用 `source + chunk_index` 做确定性 ID，避免重复上传叠加 chunk |

- **面试说法**：「文件同名是个典型的『标识符设计』问题。我一开始也想用文件名做主键，后来发现它会同时导致三个 bug——物理覆盖、批量误删、溯源歧义。正确做法是把**唯一标识（路径/哈希）**和**展示名（文件名）**彻底拆开。」

## 五、面试速查（一页话术）

**最能体现工程思维的 5 个点：**

1. **切分粒度比换嵌入模型更影响效果** —— 所以我把 chunk 打印出来读，而不是只看接口能不能返回答案。
2. **优化由观测驱动，不由教程驱动** —— rerank 是等到「正确片段在 Top-10 但不在 Top-3」时才引入的，不是教程里有就加。
3. **唯一标识与展示名必须拆开** —— `source`(路径) vs `file_name`(文件名)，否则同名文件会导致物理覆盖 + 批量误删 + 溯源歧义。
4. **框架默认实现要读源码** —— `JSONLoader` 的 jq schema 不能同时兼容顶层对象/数组，`UnstructuredPowerPointLoader` 长文本时会因 NLTK 失败；两处我都换成了自己实现，顺便砍掉了两个依赖。
5. **异常边界用「部分成功」优于「整体失败」** —— 单文件损坏不该让整批导入失败；同时 ERROR 日志要能分清「失败」和「没内容」。

**「你踩过什么坑」的标准答法模板：**

> 「现象是 ___（具体到日志/返回值的差异）→ 我先做了 ___ 去定位 → 根因是 ___（框架内部机制）→ 改成 ___ → 为了防回归，我加了断言 ___ 的单测。」
