2.0.0 迭代进度

P0 四项已全部完成（数据落库 · 鉴权 · 异步解析 · 引用可反查可点击），阶段标记为 tag v2.0.0-p0.4。P1-5 已完成（5a 中间件 + 5b 应用 + 5c 体验优化），阶段标记为 tag v2.0.0-p1.5。P1-6 已完成（嵌入 / 重排 / 对话 / 意图走硅基流动），标记为 tag v2.0.0-p1.6。P2-11 与 P2-13 已完成（账号表 · 密码规则 · 种子员工 · p2.11c 网关查库登录；管理端脚手架 · 员工 CRUD · 密码管理 · 审计日志），标记为 tag v2.0.0-p2.13d / v2.0.0-p2.11c。P2-12 进行中：p2.12b 身份与信任边界已完成（此前改一个请求头就能自称管理员，是实测能用的漏洞），p2.12c 会话隔离已完成（「登 A 看 A 的、登 B 看 B 的」真的成立了 —— 拿别人的会话编号去读/改/删一律 403）。2026-10-06 计划书修订到第 3 版、同日再修订到第 4 版、2026-10-08 再修订到第 5 版：第 3 版新增「用户权限与管理端」三项，第 4 版新增「知识库写权限分发」一项（同日再增 Token 额度与预警 p2.15），第 5 版把写权限模型从「按项目授权」改成「按人授权的 kb_role 五档」。现在系统已经能多人登录、不能互相冒充、对话记录也已分人；知识库是全公司共用的一个库（业务决策，不隔离读） —— 知识库写权限六格全部就绪（p2.14a 后端守卫、p2.14b 网关门槛、p2.14e 越权回归与结构断言、p2.14f0 身份注入加固、p2.14df 界面入口收敛 + 管理端下发授权）—— 没有权限的人现在看不到那些会出错的入口，而管理员在管理端一行就能给他开通或收回。Token 额度与预警（p2.15，只提醒不阻断不禁用）已完成第一格p2.15a：按人 × 自然月的用量口径已定死并可对账（三类分开报、缓存命中不计入总额、查不到归属的分两种数），写路径 / 看板与横幅 / 越权回归三格待做。p2.14f0（计划外）修掉了「客户端发来带特定头的请求时网关不注入身份、也不剥离伪造身份」的静默漏洞 —— 它不属于六格中的任何一格，但影响所有人。

本页由 docs/RELEASES.md 的内容渲染而来，两者内容一致。 2.0.0 是进行中的大版本——TLS、配置治理、观测备份，以及第 3 / 4 / 5 版新增的用户体系、会话隔离和知识库写权限都还没有全部做完， 所以「当前版本 2.0.0-p2.14df」不等于「可以上线」。 p2.14a 给知识库装了门（未授权账号改不了全公司共用的那个库），p2.14b 把这道门提前到网关（越权请求连后端都到不了）； 剩下的界面收敛与管理端下发授权（p2.14d / p2.14f）和 token 额度预警（p2.15）完成之前，账号仍只在本机自用。 知识库是否隔离：已决定「全公司共用，不隔离」（2026-10-08 决策）—— 这是业务决策不是疏漏：企业知识库的价值恰恰在于所有人问同一套资料， 按部门切开会导致「问的人找不到答案」，而这比「看到别人的东西」更严重。 ⚠️ 代价是：现在任何人都能上传 / 删除 / 重灌全部文档—— 实测确认：知识库的四条写路由一条守卫都没有，普通员工也能上传（返回 202）和删除。 所以知识库写权限（p2.14）是唯一的知识库防线，也是上线前必须完成的； 写权限分运营 / 测试 / 开发 / 超管四类，本项目当前只启用超管。 另新增 p2.15 Token 额度与预警（只提醒不阻断，管理端看板 + 顶部横幅，不做外部推送）。 在 p2.14 就绪之前，账号仍然只能本机自用： 12b 封的是「冒充」，12c 封的是「看到别人的问答」， 共享知识库里待封的只剩「谁能改这个库」。
