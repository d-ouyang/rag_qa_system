# 知识库切分策略（2026-11）

> 说明当前各格式的解析/切分路径、为什么表格不能按 500 字符硬切、以及 PDF 扫描件与 md 标题切分的处理建议。

## 一、当前配置

| 项 | 值 | 说明 |
|---|---|---|
| `CHUNK_SIZE` | 500 | 单片段字符上限 |
| `CHUNK_OVERLAP` | 50 | 相邻片段重叠 |
| `CHUNK_MODE` | `fixed` | **当前是固定切分**；`title` 模式已在 p4.15 借重建窗口实测复核过，同口径下 recall@5 0.909→0.817、文档级 hit@5 1.000→0.936、2 道题退化成零召回 → **继续否决**（数据见 `iterations/v4.0.0-p4.15-retrieval-and-ui-wave.md` §附） |
| 切分分隔符 | `\n\n` → `\n` → `。` `！` `？` → `.` `!` `?` → 空格 → 字符 | 已覆盖中文段落/换行/句末标点 |

## 二、按文件类型的实际路径

| 类型 | 解析 | 切分 | 现状与问题 |
|---|---|---|---|
| **md** | 原始文本 | `fixed`：RecursiveCharacterTextSplitter（500/50，中文标点分隔） | `title` 模式（h1–h4 标题树 + 短节合并 + 表格行组保护 + header_path enrichment）已实现，**实测更差、当前不启用**（见上一行）；p4.15 顺带修了它的两处缺陷：短节合并沿用首块 header_path（原取公共祖先会退到文档级）、二次切后过短片并给下一片（原来「第九条…：」会单独成 35 字一片） |
| **txt** | TextLoader | `fixed` | 与 md 的 fixed 相同 |
| **docx** | Docx2txtLoader | `fixed` | 纯文本抽取，**标题层级/表格结构会丢**；表格按行变成文本，可能被字符切分 |
| **pdf** | **MinerU**（开关开 + key 在 + ≤20MB）→ markdown；失败/超限 → PyMuPDF | MinerU markdown 走 `_split_markdown_text`（标题 + 表格行组，**不受 CHUNK_MODE 影响**）；PyMuPDF 走 fixed | 扫描件/纯图层：MinerU 负责 OCR/版面；PyMuPDF 只抽文本层，可能为空（已加 WARNING） |
| **xlsx** | 自定义 `_load_xlsx`（openpyxl） | 每工作表 → markdown 管线表；**数据行 >10 的表按「一条记录一片 + 表头随行」**，≤10 行的小表按行组切、表头重复 | 旧版 UnstructuredExcelLoader 是空格分隔纯文本，按字符硬切会**拦腰断行**；已修复并重传验证 |
| **csv** | CSVLoader | 每行一条 Document（`列名: 值`）+ fixed | 每行天然自包含、语义完整；单行 >500 字符时仍可能被二次切分（少见） |
| **pptx** | python-pptx 逐页 | fixed | 每页一条，含表格与备注 |
| **json/html** | 结构化/HTML 纯文本 | fixed | html 用换行分隔，避免正文黏成一行 |

## 三、为什么表格不能按 500 字符硬切

表格的一行是一条完整记录。按字符切分会出现三类问题：

1. **行被截断**：一片以「信息安全 全员 6 讲师15…」开头，课程名在上一片；
2. **表头丢失**：后续片段不知道列名，模型无法判断「35」是权重还是学时；
3. **表结构破坏**：markdown 的 `|` 管线被切断，表格语义消失。

**解决原则**：
- **行原子**：一行绝不切开；
- **行组装片**：按行累加到 `chunk_size`，每片**重复表头**；
- **超长单行**：单独成片（必要时截断并标记），不与其他行混切；
- **行级 vs 组级**：行级（一行一片）检索精度最高但片段多；组级（多行一片 + 表头）片段少、需模型按列筛选。可按表大小/用途配置 `TABLE_ROW_MODE=row|group`。

xlsx 已按此实现；csv 当前是一行一条 Document（已是行级），长行建议加同样的原子保护。

## 四、PDF 扫描件/图层

- 项目已集成 **MinerU**（`MINERU_ENABLED=true`、key 已配、≤20MB）：它做版面分析 + OCR，输出 markdown，再走标题/表格切分。**这就是“office 文档读取工具”的同一类逻辑**；前端预览模块只负责“看”，不负责解析。
- 回退 **PyMuPDF** 只抽文本层：纯扫描件/图层 PDF 可能抽出 0 字。已加 WARNING（文本 <20 字时提示疑似扫描件）。
- 建议：扫描件场景保持 MinerU 常开；MinerU 不可用/超 20MB 时，要么接本地 OCR（RapidOCR/PaddleOCR）做兜底，要么**明确失败并提示**，不要静默产出空切片。

## 五、建议优先级

1. **表格**：xlsx 已行原子 + 表头重复；csv 保持一行一文档，长行加原子保护（低风险）。
2. **md**：`title` 已在 p4.15 复核否决（见上）。真要再试，先做「短节贪心打包到接近 chunk_size」的可选档（title-pack）——现在的规则只合并 <150 字的小节，切出来的片普遍 200～350 字，top_k=5 下证据被切散，这是它输给 fixed 的主因。
3. **docx**：用 python-docx 读 Heading 样式（或 mammoth → markdown），把标题/表格结构保留下来，再走 title/表格切分；当前 Docx2txt 会丢结构。
4. **PDF 扫描**：MinerU 优先；无文本层明确告警/失败；必要时加本地 OCR 兜底。
