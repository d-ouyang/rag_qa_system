# 依赖升级与 LangChain 迁移指南

> 全部结论均在本机实测（2026-09-10）：
> - `~/miniconda3/envs/rag_qa_system`（langchain **0.3.7**）— 视频代码基线
> - `~/miniconda3/envs/langchain`（langchain **1.3.18**）— 最新版对照
>
> 不是查文档猜的，是两个环境里逐个 `import` 跑出来的。

---

## 一、结论：用最新版一定跑不通，但真断的只有 3 处

视频代码一共用到 LangChain 的 9 个入口。实测结果：

| API | 0.3.7（视频基线） | 1.3.18（最新） | 迁移成本 |
|-----|:---:|:---:|------|
| `langchain.chains.retrieval.create_retrieval_chain` | ✅ | ❌ `No module named 'langchain.chains'` | 改前缀 → `langchain_classic.chains.retrieval` |
| `langchain.chains.combine_documents.create_stuff_documents_chain` | ✅ | ❌ 同上 | → `langchain_classic.chains.combine_documents` |
| `langchain.chains.history_aware_retriever` | ✅ | ❌ 同上 | → `langchain_classic.chains.history_aware_retriever` |
| `langchain.memory.ConversationBufferWindowMemory` | ✅ | ❌ `No module named 'langchain.memory'` | → `langchain_classic.memory`（或改自己实现） |
| `langchain.retrievers.ContextualCompressionRetriever` | ✅ | ❌ `No module named 'langchain.retrievers'` | → `langchain_classic.retrievers` |
| `langchain_community.chat_models.ChatOllama` | ✅ | ❌ 已移出 | 装 `langchain-ollama`，改 `from langchain_ollama import ChatOllama` |
| `langchain_core.prompts.ChatPromptTemplate` / `MessagesPlaceholder` | ✅ | ✅ | 无 |
| `langchain_text_splitters.RecursiveCharacterTextSplitter` | ✅ | ✅ | 无 |
| `langchain_community.vectorstores.Chroma` / `FAISS` | ✅ | ✅ | 无 |
| `langchain_openai.ChatOpenAI` | ✅ | ✅ | 无 |
| `langchain_huggingface.HuggingFaceEmbeddings` | ✅ | ⚠️ 需单独装 | 无（该环境没装，PyPI 最新 1.2.2 可用） |

**所以：不是"一处一处改"，是"5 行 import + 1 个新包"。** LangChain 1.x 把旧 API 整体搬进了 `langchain-classic` 兼容层，函数签名没变。

具体到这份代码，迁移到 1.x 要动的地方：

```python
# core/rag_chain.py
- from langchain.chains.history_aware_retriever import create_history_aware_retriever
- from langchain.chains.combine_documents import create_stuff_documents_chain
- from langchain.chains.retrieval import create_retrieval_chain
+ from langchain_classic.chains.history_aware_retriever import create_history_aware_retriever
+ from langchain_classic.chains.combine_documents import create_stuff_documents_chain
+ from langchain_classic.chains.retrieval import create_retrieval_chain

# core/memory_manager.py
- from langchain.memory import ConversationBufferWindowMemory
+ from langchain_classic.memory import ConversationBufferWindowMemory

# core/retriever.py
- from langchain.retrievers import ContextualCompressionRetriever
+ from langchain_classic.retrievers import ContextualCompressionRetriever

# core/llm_client.py（Ollama 分支）
- from langchain_community.chat_models import ChatOllama
+ from langchain_ollama import ChatOllama      # 需 pip install langchain-ollama
```

## 二、那为什么还是不建议现在升

因为**收益为零，噪音极大**：

1. 视频讲的是 LCEL 组合思维（prompt | retriever | llm 怎么串），这个思维在 0.3 和 1.x 里是同一套。用最新版学，你只会多遇到一堆 `DeprecationWarning` 和 `langchain_classic` 的字样，干扰主线。
2. `langchain_classic` 是**兼容层**，官方明确说它是过渡方案。现在学 1.x 的正确姿势是学 LangGraph，那是另一套心智模型——你第二个项目再学不迟。
3. 锁死 ≠ 落后。锁的是**版本**，不是能力。等视频学完，花 30 分钟做一次迁移演练，就是一份很好的技术笔记。

## 三、依赖分层：哪些锁死、哪些随便升

| 层 | 包 | 策略 | 原因 |
|----|-----|------|------|
| **锁死** | `langchain` / `langchain-community` / `langchain-core` | 锁 `<0.4` | 1.x 破坏性重构（上表） |
| **锁死** | `chromadb` | 锁 `<0.6` | `langchain_community.vectorstores.Chroma` 0.3.x 只适配 0.4~0.5 系 |
| **锁死** | `pydantic` | 锁 `<2.12` | chromadb 0.5.x 与 2.13 有兼容风险（见下方修正） |
| **自由** | `fastapi` / `uvicorn` / `python-multipart` | 小版本随便升 | 纯 HTTP 层，与业务代码无耦合 |
| **自由** | `torch` / `numpy` / `scipy` | 小版本随便升 | 新版本对 Apple Silicon 支持更好 |
| **自由** | `streamlit` | 小版本随便升 | 教学期用，Vue 上线后整个删掉 |
| **谨慎** | `unstructured` | 锁 `<0.17` | 0.17+ 改了依赖结构，Excel/Markdown loader 行为有变 |
| **谨慎** | `sentence-transformers` | 锁 `<4` | 4.x+ 重构依赖，CrossEncoder 用法有变 |

> **修正一条我之前的判断**：我原本担心环境里的 pydantic 2.13.4 会让 chromadb 直接 import 失败。
> 实测 `import chromadb`（0.5.17 + pydantic 2.13.4）**是通过的**。所以它没那么致命，
> 但 chromadb 内部有 pydantic 模型，某些运行时路径仍可能炸，继续锁 `<2.12` 是稳妥的，不是必须的。

## 四、长期策略：不是"什么时候升"，而是"降低耦合"

依赖升级这件事，真正的解法不是勤快地追版本，而是**减少对高 churn 依赖的表面积**。

LangChain 在这个项目里只干了 5 件事，每件都有轻量替代：

| LangChain 提供的 | 轻量替代 | 代码量 | 稳定性 |
|------------------|---------|-------|-------|
| `RecursiveCharacterTextSplitter` | 自己写（按分隔符递归切）| ~30 行 | 永久稳定 |
| `HuggingFaceEmbeddings` | `sentence-transformers` 直接用 | 5 行 | 高 |
| `Chroma` 封装 | `chromadb` 官方 client | 20 行 | 高（官方 API） |
| `ChatOpenAI` / `ChatOllama` | `openai` SDK（硅基/Ollama 都兼容 OpenAI 协议） | 10 行 | 极高 |
| `ConversationBufferWindowMemory` | 自己写（list 切片） | 10 行 | 永久稳定 |
| `create_retrieval_chain` 等 | 自己串（检索 → 拼 prompt → 调 LLM） | 40 行 | 永久稳定 |

**合计约 115 行代码，换掉 6 个高频变动的依赖。**

这不意味着现在就要这么干——视频教的就是 LangChain，你现在要学它。
但学到 M4（Agent 化）时会发现：**真正值钱的是"检索 → 重排 → 拼上下文 → 生成"这条链路的设计，不是某个框架的 API 名字。**

建议的节奏：

| 阶段 | 做什么 | 依赖状态 |
|------|--------|---------|
| M0~M3（跟视频 + 前端） | 按视频用 LangChain 0.3.x 实现 | 全锁死 |
| M4（Agent 化） | 引入 LangGraph，理解状态机编排 | 仍锁 0.3.x |
| M5（进阶练习） | **做一次 1.x 迁移**，记录 5 处改动 + 踩坑 | 升到 1.x |
| 之后（可选） | 做一个 `core_lite/` 分支，去掉 LangChain 重写核心链路 | 依赖砍到 4 个 |

M5 那次迁移 + M5 之后的重构，都是**极好的作品素材**："我知道这个框架在解决什么问题，也知道不用它怎么写"——这比"我会用 LangChain"有说服力得多。

## 五、实操规则（照做就不会被版本坑）

1. **一个项目一个环境 + lock 文件**。老项目锁死不动，新项目用新版——**永远不需要为了"追新"去改能跑的旧代码**。
2. **升级只在有理由时进行**：安全漏洞、需要新特性、新项目启动。不要"定期升一下"。
3. **一次只升一个包**，升完跑 `tests/test_module1~5` 回归。
4. **把 DeprecationWarning 当 todo**。langchain 0.3.x 会在旧 API 上打印迁移提示，那就是官方给你的迁移清单。
5. **新项目用 `uv`**：`uv pip compile` 出的 lock 文件能让你在半年后精确复现今天的环境，这是防版本漂移的唯一可靠手段。
